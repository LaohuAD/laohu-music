# 老胡音乐

这是我给自己写歌、改词、做声音和管理作品用的 AI 音乐创作系统。

我不是看了几篇教程就整理出这套规则。我自己一直在做歌，也被 AI 那些“结构完整、句句正确、唱完什么都记不住”的歌词折磨过。副歌像口号，主歌像作文，韵脚像硬凑，人物说着谁都能说的话。老胡音乐就是我为了干掉这些问题，拿自己的作品一轮轮试、一句句改，慢慢磨出来的。

你可以只给一个模糊灵感，也可以直接丢进已有歌词、旋律或试听结果。系统会从选题、人物、关系和副歌核心句开始，把歌词、旋律、声音、歌名、封面和反馈接起来。它真正提升的不是“几秒钟生成一首歌”的速度，而是少写废稿、少在错误方向上精修，让每一轮修改都离作品更近。

## 适合谁

- 只有一个题材、画面或生活片段，想把它发展成一首歌的人。
- 已经有歌词，但副歌、人物声音、韵脚、情绪或可唱性不满意的人。
- 已经有旋律、节拍或伴奏，希望按现有重音和句长填词的人。
- 想让 AI 提出判断和候选，但保留自己对核心方向的决定权的人。
- 愿意用真实试听和作品反馈，逐步养成自己的创作系统的人。

## 它能做什么

### 先把“想写什么”说清楚

输入“写一首关于某件事的歌”通常还不够。系统会继续追问或判断：谁在唱，唱给谁，发生了什么关系变化，哪个事实最值得写，歌曲最后要把听众带到什么情绪和认识。

它不会把模型最先想到的套路直接当成选题，也不会把一堆近义词包装成很多方向。需要用户决定的地方，会给出少量真正不同的选择，并说明每个选择保留什么、牺牲什么；能够由系统判断的结构和硬错误，则直接处理。

### 写词和改词

歌词阶段会同时检查材料、人物、段落和语言：

- 主歌是否提供了具体生活证据，而不是只讲结论。
- 预副歌有没有改变压力和期待，把听众送进副歌。
- 副歌是否有真正需要被重复的核心句，而不是口号或文章标题。
- 动词、名词、人称、韵脚和句子声音是否属于这个人物。
- 语言是否自然、可唱、有画面，也有不能被随意替换的锋芒。
- 局部修改是否真的解决了根因，而不是换几个近义词。

可以从完整灵感开始，也可以只改一段、几句、一个核心句，或按已有旋律做依曲填词。

### 处理旋律、声音和成曲方向

项目支持先词后曲，也支持从已有旋律、伴奏、节拍或 topline 进入。曲式、旋律、和声、节奏、编曲和演唱不是固定模板，会根据人物压力、歌词信息量、听众用途和真实音乐接口决定。

文字锁定以后，试听如果证明某句难唱、重音不对、高潮提前或编曲盖住了核心句，问题会回到最早负责它的阶段，不会只在提示词末尾加几个形容词。

### 处理歌名、封面和归档

歌名要抓住作品真正的记忆中心，封面要服务歌曲的人物和情绪。每个阶段区分讨论、候选、确认和锁定，避免一条还在比较的句子被误当成最终答案。

作品完成后，项目会保留关键决定、待验证问题、试听反馈和发布结果。一次性的意见不会自动变成永久规则，只有能够说明触发条件、底层原因和适用边界的经验，才会进入长期 Skill 或知识资料。

## 一首歌怎样完成

```text
灵感或已有材料
→ 命题、人物和关系
→ 副歌核心句与曲式
→ 歌词初稿
→ 结构和逐句精修
→ 歌词锁定
→ 声音方向与提示词
→ 外部生成和试听反馈
→ 定向修改
→ 歌名、封面、发布和归档
```

并不是每次都要从第一步开始。已有成熟歌词、旋律或声音方向时，可以从对应阶段进入；系统会先检查已有材料的锁定部分和可修改部分，再继续工作。

## 当前 Skill

| Skill | 负责什么 |
|---|---|
| `laohu-song-director` | 一首歌的阶段统筹、交接和回流 |
| `laohu-lyric-topic` | 选题、人物、关系、题眼、受众和创作方向 |
| `laohu-lyric-writing` | 新写、续写、重写、改稿、结构、押韵和可唱性 |
| `laohu-lyric-composing` | 曲式、旋律、和声、节奏、编曲和演唱设计 |
| `laohu-lyric-title` | 工作歌名、正式歌名和候选比较 |
| `laohu-lyric-cover` | 单曲或专辑封面的视觉方向和提示词 |
| `laohu-natural-dialogue` | 把专业判断说得清楚、自然、像人在交流 |
| `laohu-quality-supervisor` | 对阶段产物和最终结果做质量检查 |
| `laohu-project-evolution` | 吸收反馈、修正规则并防止同类问题反复出现 |

`.agents/skills/` 是 Skill 的权威入口；`.agents/references/` 保存按需读取的方法、理论、案例和反例。不会因为资料存在，就让每次任务把所有内容全部读一遍。

## 快速开始

### 获取项目

```bash
git clone https://github.com/LaohuAD/laohu-music.git
cd laohu-music
```

在能读取项目上下文和本地文件的 AI Agent 中打开仓库，然后从真实材料开始。

### 新歌

```text
我想写一首歌，最初的灵感是：……
先帮我判断真正值得写的关系、冲突和情绪落点，再给出推荐方向。
```

### 已有歌词

```text
这是我现在的歌词，最不满意的是副歌没有记忆点。
先判断问题来自选题、人物、结构还是文字声音，再决定改哪里。
```

### 已有旋律

```text
我已经有旋律和段落长度。请按现有重音、音节和情绪运动做依曲填词，不要让我重新从空白选题开始。
```

### 需要先分析对标

```text
这是我想参考的一首歌词。
先分析它解决了什么问题，再给出可迁移的方法和新的创作方向；确定方向后再决定是否写词。
```

## 作品怎么保存

每首正式立项的作品使用一个独立目录：

```text
作品/<作品名或稳定工作名>/
├── 创作日志.md
└── 用户明确要求保存的歌词、谱曲方案、歌名、封面提示词或发布材料
```

未确认的讨论、候选和一次性分析留在聊天中。项目只保留当前有效状态，不创建 `_v1`、`_最终版`、`_再改版` 这类版本副本。个人歌词、创作日志、试听材料和发布数据由 `.gitignore` 排除，公开仓库只保留 [作品使用说明](作品/README.md)。

## 这三个项目，我自己就在一线用

我做这些项目，最开始不是为了发到 GitHub，也不是为了包装一套课程。是因为我自己真的要写歌、做图、做视频、跑模型，工具不好用，第一个浪费时间和调用费的人就是我。它们先是我给自己造的生产工具，跑过真实作品、吃过真实的亏、改过真实的问题，后来才顺手分享出来给大家用。

| 项目 | 它真正替你解决什么 |
|---|---|
| [老胡音乐](https://github.com/LaohuAD/laohu-music) | 从选题、人物和副歌核心句开始，把歌词、旋律、声音、歌名和封面做成一首真正能继续打磨的歌 |
| [老胡 AI 视觉](https://github.com/LaohuAD/laohu-ai-visual) | 把歌曲背后的故事继续做成角色、场景、分镜、MV 画面、封面和完整视觉表达 |

三个项目可以单独用，也可以直接接成一条生产线：音乐项目把歌做出来，视觉项目把歌变成能看见的故事，无限画布负责调用模型、管理素材和保存结果。对我来说，这不是三个展示项目，而是一套真的拿来干活的工作台。
