# 老胡音乐 V3

一个本地优先、目录驱动、可长期养成的 AI 音乐共创系统。

V3 不依赖固定聊天窗口。任何兼容智能体进入项目目录后，读取 `AGENTS.md`、`project.yaml` 和当前作品 `state.yaml`，即可恢复创作状态并继续工作。未来网站可以通过同一数据和操作协议成为界面，不需要重写创作内核。

## 默认工作方式

```text
创作命题选择
→ 副歌不变核心句逐行打磨
→ 曲式结构选择
→ 一份高潜力完整歌词初稿
→ 逐乐段宏观精修
→ 逐句和承重字词精修
→ 歌词锁定
→ 声音方向选择
→ 一次生成 Style Prompt + Controlled Lyrics
→ 外部音频反馈后定向修改
```

用户负责少数高价值审美决策，AI负责提出证据、有限选项、专业推荐和完整执行。默认不使用多个完整候选和多智能体评审流水线。

纯音乐不需要先走歌词流程：从用途、身体/情绪弧、最高主题动机和器乐形式直接进入声音方向，再生成 `Style Prompt + Instrumental Form`。

## 新建作品

可以直接用自然语言：

```text
创建一首新歌。我现在只有一个灵感：……
```

也可以直接创建纯音乐：

```text
创建一首纯音乐，用于深夜独自开车；不要歌词。
```

也可以从音乐片段进入：

```text
这段副歌旋律是 5 3 2 1，音高轮廓不要改，只打磨最后两拍节奏。
```

系统会先确认片段种类、作用、锁定/开放维度和目标。只炼片段时不会强迫生成完整歌曲；需要完整提示词包时才把片段回装到声音方向。

导演 Skill 会建立作品目录，并从 `briefing` 或最接近的成熟入口开始。每首作品只维护：

```text
state.yaml
work.md
events.jsonl
audio/
```

## 恢复作品

```text
继续当前作品。
```

智能体必须从 `project.yaml` 和作品 `state.yaml` 恢复，不要求用户复述旧聊天。

## 快速模式

```text
根据当前要求直接生成一份完整歌词初稿，使用快速完整稿模式。
```

系统在一次歌词调用中完成有限内部搜索和冷读，只交一份结果；偏好证据不足的部分会使用通用默认并明确说明。

## 精修

```text
从第一段主歌开始逐段精修。
```

系统先诊断乐段整体，再处理句子和承重字词。每一行都会被检查，但没有真实缺陷的行不制造候选。

## 声音提示词

```text
歌词已经锁定，进入声音方向选择。
```

用户选择一个宏观声音方向后，系统生成一套 Style Prompt 和 Controlled Lyrics。外部平台生成音频后，再根据真实结果定向修改。

纯音乐分支生成 Style Prompt 和 Instrumental Form，不生成空的 Controlled Lyrics，也不虚构歌手。

同一提示词可以登记多个外部音频结果。用户可以反复执行“生成音频、用文字反馈、修改提示词、再次生成”，没有总轮数上限。系统自动管理 `audio_run_id` 和 `prompt_revision_id`，用户只需提供音频或听感。每轮记录哪些效果要保留、修改什么以及下轮应该出现什么可听变化。用户文字反馈始终有效；工具音频分析只在当前环境确实支持时作为补充。只有用户明确接受当前提示词包才结束循环；暂停不等于接受。

## 学习

V3 区分：

- 当前作品修改。
- 一次性要求。
- 客观专业缺陷。
- 个人审美偏好。
- 待验证根因。
- 通用知识。

反馈不会自动变成永久规则。长期经验必须同时说明表面表现、底层根因、因果链、执行改变、正反证据、边界、反例和验证状态。

```bash
ruby scripts/validate_project.rb

```

## 当前边界

- 第一阶段是本地项目模板，不建设网站和数据库。
- 项目生成歌词、纯音乐形式和声音提示词，不在内部生成音频。
- 提示词包只获得进入外部生成的资格，不代表发行成品。
- 未来老胡音乐网站可以作为适配界面，但不是当前运行依赖。
