# 老胡音乐 V4

一个给 AI Agent 使用的本地音乐创作项目。它把一首歌从灵感、选题、歌词、谱曲和 AI 音乐生成，继续推进到歌名、封面、发布与归档，同时把真实创作中验证过的判断沉淀回项目。

V4 不是旧版目录的简单扩容，而是一次重新组织：`.agents/skills/` 只保留各领域的权威入口，`.agents/references/` 保存按条件读取的方法资料，作品状态则回到每首歌自己的创作日志。这样做是为了让 AI 每次只读取当前真正需要的能力，不让旧规则、重复 Skill 和历史流程互相打架。

> 想把歌曲继续做成画面和视频？[来老胡的主页看作品与教程](https://lao-hu.com)，也欢迎到[造梦公会](https://lao-hu.com/#community)一起交流创作。

## 适合谁

- 想用 AI 辅助写歌，但不想只得到一版随机歌词的人。
- 想把人物、关系、题眼、歌词、旋律、编曲和演唱分阶段想清楚的人。
- 已经有歌词或旋律，希望让 AI 做专业比较、改稿和阶段衔接的人。
- 想让 AI 记住自己的稳定偏好，同时避免把一次意见误写成永久规则的人。
- 愿意通过真实作品、试听和发布反馈训练个人创作系统的人。

## 这个项目能做什么

### 1. 从灵感找到真正值得写的歌

项目不会把模型最先想到的高频题材直接当成答案。它会继续判断：

- 谁在唱，唱给谁，为什么此刻必须说。
- 哪个生活事实、关系变化或价值冲突值得保护。
- 这首歌相对于同题作品新增了什么认识。
- 当前需要的是一个明确主推荐，还是由关键事实触发的条件分支。
- 哪些方法可以向代表作学习，哪些具体表达必须避让。

选题方法按人物、题材、材料、中心句、展开机制、受众、类型、用途、旋律入口、新意、验证交接、立意和情绪动力拆进 Reference，需要哪一项才读取哪一项。

### 2. 写完整歌词，也能处理局部改稿

写词按“灵魂 → 筋骨 → 血肉 → 表皮”四层组织，不把某种曲式或文风当成所有歌词的固定模板：

- **灵魂**：作品为什么必须被唱出来，人物真正要承认、质问、请求、拒绝、告别或决定什么。
- **筋骨**：演唱视角、人物对象、乐段职务、情绪运动、重复变体、核心句、桥段和结尾后果。
- **血肉**：具体关系、动作、声音、身体感受、物件、职业材料和必要事实；画面是抒情触点，不是连续分镜。
- **表皮**：自然搭配、字词、句法、雅韵、修辞、韵脚、长短句、重音、气口和可唱性。

四层按优先级执行：上层不成立时不能靠下层的辞藻、押韵或排版放行。详细方法按需读取对应 Reference，避免一次加载互相重复的规则。

用户只要求改一句时，不会强行重做整首歌；但局部问题来自人物、命题或结构时，也不会用换几个近义词假装已经修好。

### 3. 连接歌词、谱曲、编曲和演唱

V4 默认支持先词后曲，也允许从已有旋律、伴奏、节拍、topline 或成曲进入。谱曲阶段会继续判断曲式、旋律、和声、节奏、编曲、演唱距离与声音叙事，不要求所有作品套同一种流行结构。

文字锁定后仍然允许声音结果回流：真实试听证明某句难唱、重音错误、高潮过早或编曲遮住核心句时，问题会退回最早负责的阶段，而不是只在 style prompt 末尾补几个形容词。

### 4. 完成歌名、封面、发布和归档

- 歌名要能代表作品的真正记忆中心，不只是从歌词里截一句。
- 封面要服务歌曲人物、情绪和发布场景，不套固定审美模板。
- 每个阶段区分候选、暂定、确认和锁定，避免讨论稿被误当成最终稿。
- 作品完成后保留当前有效状态、关键决定、待验证项和发布反馈。

### 5. 在真实反馈中继续进化

项目会区分一次性修改、当前作品要求、稳定偏好、领域规则和项目级边界。只有确实会复发、能够写成判断条件并通过回归检查的问题，才进入长期 Skill；否则保留在当前作品，不把规则库越写越乱。

## 当前 Skill

| Skill | 负责什么 |
|---|---|
| `laohu-song-director` | 一首歌从灵感到归档的阶段统筹、交接与回流 |
| `laohu-lyric-topic` | 选题、人物、关系、题眼、受众、用途与创作方向 |
| `laohu-lyric-writing` | 新写、续写、重写、改稿、结构、押韵与可唱性 |
| `laohu-lyric-composing` | 曲式、旋律、和声、节奏、编曲与演唱设计 |
| `laohu-lyric-title` | 歌名初稿、正式歌名、候选比较与复核 |
| `laohu-lyric-cover` | 单曲或专辑封面的视觉方向与生成提示词 |
| `laohu-natural-dialogue` | 把专业判断组织成自然、清楚、有人味的沟通 |
| `laohu-quality-supervisor` | 对中间产物和最终交付做独立的全维度质量检查 |
| `laohu-project-evolution` | 吸收反馈、修正规则、补齐能力并防止同类问题复发 |

`.agents/skills/` 是 Skill 正文的唯一权威来源；`.agents/references/` 保存详细方法、理论和案例。项目不会同时维护另一套同名 Skill，也不会默认一次读取全部 Reference。

## 快速开始

### 1. 获取项目

```bash
git clone https://github.com/LaohuAD/laohu-music.git
cd laohu-music
```

### 2. 在 AI Agent 中打开仓库

使用能够读取项目上下文和本地文件的 AI Agent 打开仓库。项目级 Skill 位于 `.agents/skills/`；支持该目录约定的 Agent 会在当前项目中发现它们，不需要把内容复制到 Home 目录。

### 3. 直接从真实任务开始

新歌：

```text
我想写一首歌，最初的灵感是：……
先帮我判断真正值得保护的关系和冲突，再给出当前主推荐。
```

已有歌词：

```text
这是我现在的歌词。我最不满意的是副歌没有记忆点。
先判断问题来自选题、人物、段落还是文字声音，再决定改哪里。
```

已有旋律：

```text
我已经有旋律和段落长度。请按现有重音、音节和情绪运动做依曲填词，不要让我重新从空白选题开始。
```

## 作品怎么保存

每首正式立项的作品使用一个独立目录：

```text
作品/<正式歌名、歌名初稿或明确标记的路线标签>/
├── 创作日志.md
├── 歌词创作台.md（需要写词时才建立）
├── 创作档案.md（需要保留长篇审议时才建立）
└── 用户明确要求保存的歌词、谱曲方案、歌名、封面提示词或发布材料
```

`创作日志.md`保存结构化状态，`歌词创作台.md`保存写词所需的四层输入，`创作档案.md`保存需要追溯的长篇审议；它们不互相替代。未确认的普通讨论、候选和一次性分析留在聊天中，不提前落盘。作品目录不创建 `_v1`、`_最终版`、`_再改版` 等版本副本。

公开仓库只保留 [作品使用说明](作品/README.md)。个人歌词、创作日志、试听材料和发布数据由 `.gitignore` 排除，不会随 GitHub 更新公开。

## 这些项目怎样配合

我做自媒体时，要找选题、写文章、做图片、剪视频，有时还要写歌、做 MV。下面这些项目分别帮我处理其中的一部分，也都在跟着我的实际创作继续修改。

| 项目 | 可以用它做什么 | 在我的创作里负责什么 |
| --- | --- | --- |
| [老胡的审美起源](https://github.com/LaohuAD/laohu-taste-genesis) | 把自己判断作品好坏的方法、修改意见和经验整理成 Agent 能调用的规则与 Skill | 给其他创作项目建立和改进专业能力，让反馈不只停在一次聊天里 |
| [老胡 AI 视觉](https://github.com/LaohuAD/laohu-ai-visual) | 推敲故事、写剧本、设计角色与场景，再拆分镜、写视频提示词 | 处理影视短片、MV 和其他视觉内容的创作方案；当前主要交付文本，不直接替你生成整部影片 |
| [老胡音乐 V4](https://github.com/LaohuAD/laohu-music) | 从歌曲想法开始，讨论歌词、曲式、演唱与声音方案，再做歌名、封面和发布准备 | 处理歌曲创作，也给 MV 提供歌词、音乐方向和创作背景 |
| [老胡无限画布](https://github.com/LaohuAD/laohu-Infinite-Canvas) | 在本地画布中连接素材、模型调用和生成结果，保存参数与工作流 | 承接图片、视频、音乐等生成任务；基于 Infinite-Canvas 继续开发 |
| [CapMotion](https://github.com/LaohuAD/laohu-CapMotion) | 在 Cap 产品基础上继续开发录屏、口播剪辑、字幕和讲解动画工作流 | 把教学录屏和讲解素材整理成视频；涉及桌面编译和环境配置，先看本项目的开发说明 |

比如做一支歌曲 MV，可以先在音乐项目里打磨歌词和声音方向，再用 AI 视觉整理故事与镜头，最后在无限画布里调用模型、保存素材。做软件教程时，CapMotion 则更相关。它们之间可以传递方案和素材，但还不是安装一次就能全自动跑完的产品。

你只需要挑眼下能帮上忙的项目，不必一次把它们全部装好。

## 我是老胡，喜欢玩 AI，也喜欢讲故事

我是**老胡用AI画梦**。看到有意思的 AI 工具，我总想上手玩一下：写文章、做图、写歌、做视频，都想试试。玩得挺杂，但现在花时间最多的，还是 AI 影视创作、讲故事，以及一个人怎么把自媒体做起来。

我自己就要经历找选题、写稿、做素材、剪辑和发布这些事。哪些环节可以让 AI 帮忙，哪些地方还得自己想、自己改，我会边做边琢磨。这些开源项目和教程，就是在这个过程中一点点做出来的。如果你也在独立做内容，希望里面有些东西能帮你省下重复劳动，多留点时间给真正想做的作品。

### 经常跑模型，想把试错成本降下来？

做图、做视频时，往往要试好几轮才有满意的结果。我自己也在用和维护[老胡的模型小屋](https://api.lao-hu.com)，希望把模型调用的成本降下来，让同一份创作预算能多试几种想法。

如果你正在找价格更合适的模型接口，可以先看看站内的模型和当前价格，再用一个小任务比较效果、速度和费用，合适再继续用。模型调用按站内说明收费，开源项目本身和接口消费是两回事。
