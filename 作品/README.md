# 作品

每部正式立项的作品使用一个独立目录。目录名优先采用正式歌名或当前歌名初稿；尚无合格歌名初稿时，可以暂用能够辨认核心冲突的路线标签，但日志必须明确它不是歌名。

```text
作品/<正式歌名、歌名初稿或路线标签>/
├── 创作日志.md
├── 歌词创作台.md（需要写词时才建立）
├── 创作档案.md（需要保留长篇审议时才建立）
└── 用户明确要求保存的歌词、谱曲方案、歌名、封面提示词或发布材料
```

`创作日志.md`是状态控制台，`歌词创作台.md`是写词输入台，`创作档案.md`是追溯材料，三者不混用。未确认的普通讨论、候选、试写和一次性分析留在聊天中，不提前落盘。作品目录不创建版本副本和临时文件夹。


## 当前状态与衍生产物

同一歌曲更名、制作封面或发展 MV 时，先检查已有作品目录。源歌词与声音保持一个权威入口；衍生视觉可以保留自己的用途和决定，但日志必须互链并说明哪些标题、画面或解释仅适用于该产物。封面完成不代表声音锁定，视觉标题不自动更改正式歌名。

当前日志只写有效状态、来源、保护项与下一步；历史选择和完整制作过程进入既有创作档案。比较用的音频和图片可保留，明确当前采用、候选、被替代及保留理由，不依靠文件名中的“最终版”推断状态。用户新决定只更新其实际影响范围。

发布前由总监核对主音频、歌词、名称、署名、封面和用途的对应关系；平台规格按实际目标核实。目录仍只保存在本地，通用方法有复用价值时才提炼到项目资料，具体作品计划不放入公开的工程文档。

历史作品不构成新作品的默认素材库。新任务只加载目标作品的当前有效输入；其他作品、失败候选和复盘记录仅在用户指定对标、续作或专项诊断时读取，不因存放在本目录就成为质量范本。
