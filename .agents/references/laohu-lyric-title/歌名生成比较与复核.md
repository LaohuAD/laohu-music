# 歌名生成、比较与复核

## 什么时候读取

需要为一首歌生成候选、比较两个或多个歌名、判断工作名能否升级为正式名，或在歌词、成曲、封面和发布前复核时读取。

## 一、先做命名取证

不要先想名字。先在作品中标出：

```text
出现至少两次并发生意义变化的词
→ 逼人物行动的物件、地点、原话或仪式
→ 副歌中听众最容易带走的声音单位
→ 桥段以后被重新理解的旧材料
→ 结尾仍留在听众眼前的对象或动作
```

每项回答四个问题：它属于谁；在哪段出现；拿掉后作品损失什么；听前与听后是否不同。无法回答的材料只算气氛，不进入首轮核心候选。

## 二、生成不同母义的候选

内部先生成八至十五个候选，再做母义去重。数量只是防止第一反应垄断，不是交付指标。

每轮至少尝试四种机制：

1. 用一个核心物件或道具命名。
2. 用人物持续动作、关键选择或未完成仪式命名。
3. 用一句原话、称呼、问句或关系判断命名。
4. 用地点、时间、身份、声音符号、悬念或反差命名。

把每个候选解压成普通话。例如：

```text
《未拜堂》＝婚礼没有完成。
《不下台》＝人物持续留在舞台，可能也指拒绝结束等待。
《嫁衣》＝一件衣服，同时可能连接戏服、婚服与未兑现婚约。
```

普通话意思相同的候选归为一组。每组只留证据最多、自然度最高、听后增义最强的一个。

## 三、用顺序淘汰，不用平均分救弱项

### 1. 归属淘汰

- 正文能否指出至少两处证据。
- 候选是否连接人物动作或关系变化。
- 换到同题歌是否仍然毫无损失。

归属不成立，直接淘汰。

### 2. 泄底与泥实淘汰

- 是否提前交代死亡、分手、婚礼失败、背叛或反转。
- 是否像故事梗概、选题标签、影视分集名或管理员总结。
- 是否把多层关系压成单一结论。

若泄露的是作品真正的公共态度，且副歌需要听众直接唱出，可以保留；若泄露使桥段和结尾失去发现，淘汰。

### 3. 双时态测试

分别写一句：

```text
听前，听众以为它在说什么？
听后，哪项人物事实让它多了一层意思？
```

第二句只是重复第一句，标题只有说明功能。不是自动淘汰，但必须与能增义的候选比较。

### 4. 三次变义测试

叙事型与核心意象型歌曲，检查候选能否在三个位置改变职务：

- 首次出现：字面对象或日常意义。
- 桥段前后：关系证据或误解被改写。
- 最后副歌或结尾：人物选择、命运或公共意义。

三次不是硬凑次数。两次准确变义胜过三次机械重复。

### 5. 声音测试

连续完成：

- 主持人报幕：`下面请听……`
- 朋友推荐：`你去听一下……`
- 副歌或结尾试唱标题词。
- 只听声音，不看文字，写下听到的字。

检查词组边界、同音歧义、音节长度、自然重音、开口度、尾字可延展性和曲风匹配。没有旋律时只做口头测试，不假装完成可唱性验证。

### 6. 传播测试

- 封面缩略图能否一眼读清。
- 搜索时是否与大量著名作品、艺人或通用词完全重叠。
- 目标听众是否愿意自然复述，而不是必须解释典故。
- 标题承诺是否被歌词与成曲兑现。

同名不是绝对禁用；已有强势作品会提高识别和检索成本，应纳入取舍。不得为避同名硬造生词。

## 四、比较时先找决定性差异

不要把所有维度平均打分。先问哪个差异会改变作品身份。

比较《嫁衣》与《未拜堂》：

| 判断 | 《嫁衣》 | 《未拜堂》 |
| --- | --- | --- |
| 作品证据 | 可连接戏服、婚服、约定、舞台、等待 | 连接婚礼未完成这一事件 |
| 听前 | 具体物件，保留人物与结局悬念 | 直接知道婚礼没有完成 |
| 听后 | 可由衣服变成未兑现婚约与人物命运 | 主要仍是没有拜堂 |
| 段落职务 | 可进入主歌、桥段、末次副歌多次变义 | 更适合剧情节点或质问 |
| 主要风险 | 若正文不写衣服行动，会只剩古风意象 | 泄底、泥实、像剧情标签 |

当前设定让嫁衣真实参与剧情时，`《嫁衣》`胜出。若作品最后把重点改成两人反复在台上扮夫妻、现实却始终没有完成仪式，而嫁衣只出现一次，结果需要重新比较。

## 五、公开候选必须机制不同

公开三至五个候选时，不能是：

- 《嫁衣》
- 《那件嫁衣》
- 《红嫁衣》
- 《等你的嫁衣》

这只是一个母义的四次改字。应保留机制差异，例如：物件型、动作型、原话型、地点或仪式型各一项，再明确哪项胜出。候选较弱时宁可只公开两个，不制造陪跑。

## 六、工作名升级程序

### 选题确认后

检查它是否集中人物、关系和主矛盾。此时允许解释性较强，标为工作名。

### 歌词定稿后

检查它在正文中是否有证据、是否进入记忆句、是否被桥段和结尾改写。正文出现了更强中心词时，替换工作名。

### 成曲完成后

检查旋律最高点、重复次数、演唱重音、听觉歧义和歌手口吻。纸面中心与声音中心不一致时，优先重新审视歌名，不强迫音乐服从旧标题。

### 发布前

检查同名碰撞、封面可读、平台展示、影视或品牌关系和目标听众。只调整传播层，不推翻作品核心；若必须推翻，说明此前命名或作品定位尚未完成。

## 七、失败处理

- 没有候选通过归属门：回到选题或歌词，作品中心尚未形成。
- 候选都像剧情摘要：回到反复物件、原话、动作和听后增义寻找。
- 候选都抽象漂亮：逐个要求正文证据，删到只剩有来源的词。
- 候选都难读：先改自然中文，不用“艺术性”开脱。
- 一个名字传播强、作品弱：保留为平台文案候选，不当歌名。
- 用户偏爱与专业推荐不同：说明两者分别保护什么、牺牲什么，由用户决定正式名称；不得假装专业差异不存在。

## 八、最终复核

1. 这个名字属于谁、哪段、哪个动作。
2. 它有没有误导或提前说破。
3. 听完整首后是否增加含义。
4. 是否能被自然说出、听清、记住。
5. 是否进入歌词或声音记忆，而非悬在正文外。
6. 与强候选相比，决定性优势是什么。
7. 什么歌词或成曲变化会推翻当前选择。

七项答不全，保留为工作名，不宣布正式定名。
