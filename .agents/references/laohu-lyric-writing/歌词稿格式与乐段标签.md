# 歌词稿格式与乐段标签

## 什么时候读取

需要把已经确定的歌词信息结构交付为正式歌词、AI 音乐平台输入、作曲沟通稿或试唱稿时读取。它只规定乐段标签、正文分行、标点和说明文字的边界；段落是否需要、各段承担什么，仍由[段落结构与情绪推进](段落结构与情绪推进.md)决定。

## 一、标签必须来自结构决定

先确定听众接收信息的顺序、主 hook、重复和转折，再选择标签。标签不能证明曲式成立，也不能把故事大纲自动变成歌词。

正式歌词默认使用英文小写方括号标签。核心标签：

| 标签 | 中文职务 | 使用条件 |
| --- | --- | --- |
| `[intro]` | 前奏 | 建立声音、动机或入口；不塞背景说明 |
| `[verse]` | 主歌 | 提供现场、动作和关系证据 |
| `[pre-chorus]` | 预副歌 | 收窄问题并制造进入副歌的必要门槛 |
| `[chorus]` | 副歌 | 完成主要语言动作和主 hook 回归 |
| `[post-chorus]` | 副歌后 | 保留短声音记忆；不继续讲剧情 |
| `[bridge]` | 桥段 | 带来新证据、新认识、新对象或不可逆决定 |
| `[outro]` | 尾声 | 留下动作后果、最后画面或声音余波 |

按需标签：

| 标签 | 中文职务 | 使用条件 |
| --- | --- | --- |
| `[rap]` | 说唱 | 确有节奏密度、韵脚和角色功能，不用来塞故事梗概 |
| `[interlude]` | 间奏 | 非演唱过渡；不填写作者说明 |
| `[refrain]` | 反复句 | 依附各节回归的短句，不等同完整副歌 |
| `[guitar solo]`、`[piano solo]` | 乐器独奏 | 用英文写明乐器，不只写含糊的 `[solo]` |

`[instrumental]`、`[spoken]`、`[breakdown]`、`[drop]`、`[hook]`、`[ad-lib]`等扩展标签，只在目标平台或制作流程明确支持、并且作品确实需要时使用。不同平台对标签解释并不一致；不得为了显得专业发明标签。

同类段落需要区分时，可以使用 `[verse 1]`、`[verse 2]`。副歌若歌词和职务相同，继续使用 `[chorus]`；若平台不明确支持 `[final chorus]`，不要自行创造该标签，用重复的 `[chorus]`和实际歌词变化表达最后一次回归。

## 二、正式歌词正文默认无标点

用于 AI 音乐平台和本项目默认交付的纯歌词稿，正文不使用中文逗号、句号、问号、感叹号、冒号、分号、引号、书名号和括号。停顿、换气和段落边界由以下方式完成：

- 一个可唱意群写一行。
- 同一乐段连续排列，不用逗号粘接两句。
- 乐段之间空一行。
- 同一行需要展示内部意义气口时，用一个普通半角空格隔开词组；禁止使用`|`、`｜`、斜线和标点作为气口符号。
- 气口由词组、分行、休止和旋律共同确定；无旋律时的空格只是文字侧候选，不冒充歌手实际换气。
- 需要强调时依靠重复、语序、重音和旋律，不用引号与感叹号加戏。

去掉标点以后听众不知道谁说话、问谁、先做什么，说明句法或视角本身没写清，必须重写，不能把标点加回来遮丑。

《歌词写作十八讲》在“纸面投稿”场景建议尽量使用标点，不使用时用空格或斜线断句。这条服务编辑阅读，不是所有歌词载体的唯一格式。本项目把用途分开：AI 平台纯歌词稿默认无标点；印刷投稿、曲谱出版和委约审稿按对方格式另行生成，不混成一份稿。

## 三、对白、书信和人物说明

正式歌词不使用引号模拟面对面对话，也不在正文里写`男：`、`女：`、`旁白：`。听众听不见引号，平台也不会替作者建立人物关系。

人物原话要么由当前歌者直接说给明确对象，要么用自然转述交代来源，要么在已经设计好的对唱或戏中戏乐段中换人。删掉排版提示后仍分不清说话者，退回[演唱视角与多角色分配](演唱视角与多角色分配.md)。

制作说明、演唱者分配、情绪提示、音域、气口、韵脚和故事解释统一放在歌词正文之后的“制作备注”，不插入可唱文本。目标平台支持特定元标签时，另按平台规则输出。

## 四、标准输出模板

```text
[intro]

[verse 1]
歌词正文
歌词正文

[pre-chorus]
歌词正文

[chorus]
歌词正文
歌词正文

[verse 2]
歌词正文
歌词正文

[bridge]
歌词正文

[chorus]
歌词正文
歌词正文

[outro]
歌词正文
```

模板只示范格式，不代表每首歌必须拥有这些段落。没有预副歌、桥段或尾声时直接删除；需要分节歌、回旋、冷开或通篇连续结构时，按实际段落使用相应标签。

## 五、交付前机械检查

```text
曲式与段落职务是否已经确认
→ 标签是否全部来自允许列表并按实际顺序排列
→ 正文是否仍有 Markdown 中文段名
→ 正文是否仍有标点、引号、角色冒号和括号说明
→ 每行是否只有一个可唱意群
→ 同一行的气口是否只用普通半角空格，是否仍残留竖线、斜线和标点气口
→ 去掉视觉提示后是否仍听得出人物、对象和句法
→ 制作备注是否已经移到正文之外
```

任一项失败，不交正式歌词。
