# 单一技能四层深化与保真迁移

本 Reference 只在创建、深度优化、重构或迁移一个 Skill 时读取。它解决的不是怎样把文件整理得更像系统，而是怎样让一个 Skill 的独门本事从方向一直传到真实结果，同时保护成熟项目已经有效的能力。

## 方法箴言

```text
长处定其名，边界守其形。
先保真，再增益；先修断点，不补全能。
四层不分目录，只问能力是否贯通。
解释可以迁移，判断不能失传。
新规则要改变选择，旧强项要经得起回看。
```

箴言负责确定取舍，下面的方法负责执行。不得把五句话复制进目标 Skill 后便宣称完成优化。

## 一、先找到独门能力，不从缺点开始

成熟 Skill 的价值不是“它什么都会”，而是它能稳定完成某一次相邻能力无法替代的专业转译。修改前先回答：

```text
它接到什么上游事实、材料或决定
→ 它独自完成哪一次专业转译
→ 这次转译改变了什么候选或结果
→ 它使用哪些领域关系、材料和工具
→ 它把什么可执行产物交给谁
→ 哪类失败应由它负责，哪类不应由它负责
```

例如：选题把题材和人物事实转成作品命题，不负责写完整歌词；写词把关系命题转成可唱语言，不负责决定完整编曲；谱曲把作品关系转成听觉运动，不负责替歌名完成命名；歌名把作品记忆转成听前成立、听后增义的名字，不负责制造新主题；封面把作品中最值得先看见、又不能说尽的关系转成一帧，不负责完整角色开发。

找不到独门转译时，先判断这个文件是否只是 Reference、入口、路由或重复副本；不要为了保留一个目录名硬造 Skill 身份。

## 二、用真实长处建立保护清单

不能只从当前失败反推规则。至少寻找一项旧任务、现有规则或用户反馈，证明这个 Skill 已经擅长什么：

```text
旧任务是什么
→ 哪个判断比普通做法更好
→ 这项优势来自哪条原则、哪段运行链、哪种材料或哪项法度
→ 修改后必须保留什么可观察结果
```

保护项可以是：判断快而不草率、候选差异真实、材料有来处、语言有锋芒、格式稳定、边界清楚、交接准确或用户无需重复解释。不能只写“保持原能力”，必须写出原能力在什么场景产生什么结果。

如果原项目没有可追溯版本，只能从当前原文直接建立语义清单，不依赖模型记忆。存在 Git 历史时优先读取原文件版本；不能用已经被摘要过的中间稿代替原文。

## 三、把四层翻译成目标领域

四层是能力剖面，不是统一章节。对目标 Skill 分别完成下面四项判断。

### 方向与取舍

写清它面对哪两个都说得过去的方向，优先保留什么、舍弃什么、为什么、在什么条件下反转。先用准确普通话写清判断；只有符合公共语感、能反向解压并统领多种选择时，才压成现代汉语诗学箴言。

伪箴言的表现：只有气势，没有真实冲突；只能解释一个案例；用生造搭配压缩尚未想清的内容；换到任何 Skill 都成立。伪箴言保留为普通说明，不进入最高原则。

### 运行关系

写清能力从哪里进入，各步骤为什么按这个次序，各部分怎样分工，前一步留下什么，下游接住什么，什么时候锁定，什么时候回流。列表齐全不等于关系成立；删除或调换一部分没有损失，说明仍是平行材料。

跨 Skill 时同时区分：共同不变量由项目或总导演保护，领域交付由当前负责人定义。不能用一张通用表取代多次专业翻译。

### 材料与技法

材料必须经过相称、关系、承重、典型性、组合和声音或媒介潜力的比较。技法必须说明：

```text
作用对象
→ 目标效果
→ 使用条件
→ 过量风险
→ 失败后退回哪里
```

只列“对比、留白、反转、运镜、配色、重音、排比”不算能力；只给案例而无法解释为什么有效，也不算能力。

### 交付法度

分开硬规格和审美分寸：

```text
硬规格：长度、字段、路径、尺寸、字符、标签、接口、事实与合规边界
审美分寸：语言、节奏、密度、气质、分量、留白和体裁得当
```

硬规格能机械检查就准确检查，失败即打回；审美分寸依靠语境、候选对照、朗读、试听或观看判断。机械通过不能证明艺术质量。

## 四、先判缺口属于谁

当前问题只允许先确定一个主要责任位置。

### 目标 Skill 自己的缺口

它宣称负责的转译没有原则、运行链、材料技法或交付法度。修改目标 Skill 的唯一权威位置。

### 跨 Skill 交接缺口

上游已经拥有判断，下游没有收到，或收到的是不适合自己执行的语言。修交接字段、状态和激活证据，不复制整套上游规则。

### 相邻 Skill 的缺口

问题真实存在，但属于另一项独立专业能力。调用、创建或修复相邻负责人；不把目标 Skill 扩成全能工具。

### 项目顶层缺口

多个领域共同需要的身份、路由、优先级、阶段和硬边界缺失。只把共同部分写进顶层，领域执行仍回各自 Skill。

无法确定责任位置时先保留现状，做只读审计和局部试验；不得以“先补上再说”制造重复权威。

## 五、成熟能力的保真迁移

拆分、合并、精简或重写前，从原文件逐项建立语义单元：

```text
目的
触发
动作
禁止表现
例外与边界
消歧义的例子
验收
原位置与新位置
```

每个单元只允许四种处理：

- 保留：原位置仍是最佳权威。
- 加厚：保留原判断并补足缺失的因果、条件、动作或验收。
- 迁移：新位置更符合按需读取和职责边界，且能恢复原判断能力。
- 删除：完全重复、已被更高权威完整替代、明确错误或无法改变任何选择。

删除必须指出替代位置或失效依据。不能因为文件长、模型应该懂、当前对话已经明白、文字不够整齐而删除。行数下降不代表质量提升，行数增加也不代表能力增强。

重构成熟 Skill 时还要检查规则架构债。逐条把现有内容标成：正向生成能力、条件分支、失败验收、详细案例、当前作品事实。若主流程里聚集了多个由单次事故长出来的词表、错句和局部禁令，不能只给它们换上更大的类别名；先找它们共同缺少的输入、比较或裁决动作，把这项正向能力放回最早生成节点，再把条件差异保留为分支，把失败原句移到测试或既有复盘；生成 reference 不保留未经验证的项目成品示范。新的根规则若没有让旧补丁减少，只是又多了一层说明，视为重构未完成。

案例不是必须删除。它的正确职务是证明一条规则怎样区分近似情况、作为回归输入，或保存某种低频边界；它不能在没有正向能力的情况下替所有新任务决定词、句、材料和结尾。审计时至少回答：没有这个案例，新模型是否仍知道如何选择；换一个完全不同的外观，根规则是否仍能工作；案例与规则冲突时谁拥有裁决权。

## 六、Reference 必须改变取舍

为每份需要调用的 Reference 写明：

```text
什么缺口触发读取
→ 从中取得什么判断或方法
→ 它改变或确认哪个具体决定
→ 变化落在什么候选、中间结果或交付字段
→ 哪些内容本轮没有采用
```

Reference 只是被读取、被引用或被写进路由，最多证明结构可达。读取前后没有任何决定变化，也没有一个旧决定得到可审计确认，视为未激活。

不要为了“知识完整”默认读取全部 Reference。知识过量会让相邻标准同时满功率运行，最终把作品拉向平均。

## 七、四类回归缺一不可

### 当前失败场景

确认用户指出的问题在新规则下会被最早责任节点拦住。

### 同根变体

不仅更换题材、人物、媒介或材料，还要让错误换一种外观，确认规则识别的是同一生成原因，不是记住案例表面。若规则只能抓住近义词、同类物件或相同句架，仍是扩大的补丁。

### 边界反例

准备一个表面相似但正确的做法，确认规则不会误伤。例如“私人小物不自动深刻”不能变成禁止钥匙；钥匙确实改变人物关系时仍应允许胜出。

### 旧强项场景

使用修改前已经做得好的代表任务，确认新规则没有降低原本的判断速度、候选质量、专业深度、审美锋芒、职责边界或交付稳定性。

当前失败减少而旧强项退化，结论不得为 `KEEP`。

## 八、验证结论与回退

分别记录：

```text
STRUCTURE：文件、路径、命名和确定性接口
ROUTE：入口能否到达负责人和必要 Reference
BEHAVIOR：规则是否改变判断、候选、否决或中间结果
QUALITY：独立领域任务或真实结果是否证明质量提升
```

每级使用 `PASS / OBSERVE / FAIL / UNKNOWN`。同一执行者既修改又自检时，行为最高为 `OBSERVE`；没有真实成品或独立裁决时，质量保持 `UNKNOWN`。

最后给出：

- `KEEP`：目标改善，旧强项保留，边界反例未受损。
- `OBSERVE`：结构或行为有改善迹象，但仍缺独立任务或真实结果。
- `REVERT`：目标未改善、职责扩张、信息密度下降或旧强项退化。

发生 `REVERT` 时回到原文件与语义清单，撤销不能证明有益的改动；不保留“以后可能有用”的补丁。

## 九、直接阻断

- 给每个 Skill 复制同一套四层章节和同一张表。
- 只补缺点，不说明目标 Skill 的独门长处。
- 因相邻能力不足，把目标 Skill 改成全能工具。
- 用摘要、行数和文件整齐替代语义迁移。
- Reference 已存在却没有触发、激活和决定变化。
- 新规则只写“更深、更专业、更自然、更有感染力”。
- 只测当前失败，不测边界反例和旧强项。
- 同一执行者根据自我感觉宣称质量达到顶尖。
