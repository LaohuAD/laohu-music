# 演唱控制与生成歌词

本 reference 负责把全曲声音方向落实成逐段、逐句的演唱动作，再按当前生成接口编译成可以直接复制的最终歌词。它保护两件事：演唱设计必须细到能够指导停顿、重音、音区、发声和字尾；用户已经明确的接口格式必须原样执行，不能被内部控制表或通用平台默认值替换。

## 演唱箴言

```text
先决定这句话为何这样唱，再决定控制写在哪里。
宏观进提示词，细节编进最终歌词，格式服从当前接口。
高音属于关系重心，不属于最宏大的名词。
停顿改变句义，换气服从词组，技巧不能抢走人物。
没有旋律时只定相对责任；有了旋律，才定音符与时值。
控制带来负增益，先删控制，不怪模型不懂暗号。
```

## 一、接口各负其责，最终歌词必须可直接复制

一个完整人声生成方案把以下内容放在同一生成块内：

```text
Style Prompt：全曲人声身份、速度与律动、分段声音运动、编配和制作距离。
最终生成歌词：歌词正文、段落标签和当前接口要求的演唱控制；用户复制后不需要再次拼装。
演唱设计底稿：只在需要审稿、导唱或标准标签接口时保留；它必须被编译进最终歌词或明确说明无法嵌入，不能替代最终歌词。
```

当前项目的嵌入式格式固定为两种：段落级写成`[Verse 1 ｜ 指令1 ｜ 指令2]`；句级写成`[(指令1｜指令2)]`，并单独放在目标歌词的上一行。全角`｜`只允许出现在中括号内部，用来分隔指令；不得写成`歌词｜控制说明`，也不得把控制改成歌词外的逐行表格后让用户自行回填。

## 二、进入条件与证据等级

进入逐句控制前必须拿到：

```text
锁定歌词与段落标签
→ 每段职务、中心句、承重词和文字侧候选气口
→ 与作词排版分开的演唱乐句草图
→ 主唱身份与全曲声音方向
→ 目标平台、模型版本，以及用户或当前项目已经确认的歌词控制语法
→ 无控制基线音频，或明确记录尚未生成
```

控制证据分为：

- `user-specified-interface`：用户明确给出当前工具的输入格式，必须按该格式交付；它证明怎样写，不证明写入的每项唱法都会产生正向声音结果。
- `documented`：平台正式文档明确支持，允许作为通用接口依据。
- `project-tested`：同一平台和模型版本中，固定其他输入后重复试听，能够稳定改善目标，允许谨慎复用。
- `creative-hypothesis`：作品需要但尚未验证的具体唱法，只能少量写入本轮试验，并由真实音频决定保留或撤销。

用户已提供“加控制以后节奏变差”的真实试听时，相关控制直接降级或撤销。不能以“标签理论上合理”推翻实际负增益。

## 三、先建立全曲人物表演与人声运动

先写一条人物表演线：歌者在向谁开口，每段正在强忍、承认、反驳、追问、改口还是作出决定，哪一段第一次失去原有防御，最后留下怎样的关系后果。再写一条人声总线：歌者从什么距离开口，哪一段第一次改变发声责任，哪里是关系最高点，最后怎样离开。随后为每个主要乐段只选一个主情绪动作和一个主声音变化，必要时增加一个辅助变化：

```text
Verse：距离、句法流动或咬字方式中的一项建立人物入口。
Pre-Chorus：通过气息压力、和声等待、句长或起音变化取得进入副歌的资格。
Chorus：根据扩张、转换或抽空策略决定主唱是否升高、变响、变实或变近；不自动全开。
Post-Chorus：回答副歌留下的问题；收窄不等于停止脉冲，除非停止本身承担意义。
Bridge：改变听法，不以稀疏、耳语或念白本身冒充新证据。
Final：保留 hook 的可辨认部分，只改变一项与桥段新证据有关的声音责任。
```

高音、长音、气声、破音、转音、戏腔、和声与大混响都需要具体职务。最宏大的剧情词不自动领取最高音；先判断听众最终应记住世界事件、私人关系、否定、承认还是决定。

## 四、先做演唱判断，再编译控制

无旋律阶段，内部仍按下面字段完成判断；没有必要的字段写`保持前句`，不能为填满表格制造变化：

```text
歌词单位｜对象与人物动作｜情绪矛盾｜句法与起音｜停顿和候选气口｜相对音区与轮廓｜力度与发声｜重音与字尾｜编配配合｜证据等级
```

逐句裁决顺序固定为：

1. **对象与人物动作**：这句唱给谁，歌者正在强忍、承认、对照、追问、改口、拒绝还是收束；先确定她为何非在这里这样开口，以及它与前后句的关系。
2. **演唱乐句、节奏与停顿**：先判断哪些词属于同一次语义和情绪推动，再决定哪些作词行应合并、哪里需要休止改变听法；停顿不能切断主谓、动宾、共同主语或宾语、连续谓语、固定搭配和仍在递进的追问，也不能把每次分行都唱成句号。
3. **相对音区**：本句比前句升、降、保持还是突然收窄；最高点给哪个承重词，为什么不是相邻的大词。
4. **发声与力度**：贴近或打开、连奏或短收、真声比例、混声、气声和颤音怎样变化；技巧只能强化已经成立的语言动作。
5. **字头与字尾**：否定词和关系词是否听清；长音先检查韵腹能否稳定延展，再决定辅音何时收束。
6. **编配配合**：伴奏在重词前让位、在句尾接答还是维持脉冲；不能让人声和编配同时把所有变量推满。

情绪控制必须写成一条能够被听见的因果：

```text
人物面对谁、刚知道或承受了什么
→ 此刻想完成什么关系动作
→ 声音应出现什么可听变化
→ 用哪项咬字、气息、音区、力度、连断或字尾实现
→ 哪条全曲时间与能量边界不能被它破坏
```

`sad / emotional / heartbroken / deeply`一类词只说明气氛，不能决定表演；`mixed voice / firmer onset / pause / sustain`一类词只说明技巧，也不能替人物开口。承重乐段和发生转折的关键句必须同时具有人物动作与可听结果。例如`拒绝把爱情说成过去｜短促截断“不”｜停顿后立即回拍`，比`emotional pause`更清楚；`承认选择但在“再无”暴露失去｜稳定中声区｜只在承重词短暂变脆弱`，比`powerful high note`更贴近人物。情绪不能自动翻译成降速、升高、变响、气声或哭腔；这些唱法仍要经过全曲脉冲、音区准备和真实试听。

没有旋律或导唱时，只能给相对音区、候选拍位和停顿范围。绝对音高、精确到拍的时值、换声点和真实换气必须在旋律、歌手音域或导唱出现后补齐。把未知写成精确数字，会让控制谱看起来细致却无法证实。

## 五、停顿、气口、高音和技巧的判断

### 演唱乐句不是作词换行

作词稿的换行可以同时承担视觉对称、句式展示、留白、韵脚提示和创作时的候选气口；进入谱曲后，必须根据实际听法重新编译。依次检查：

```text
这几个词是否共享主语、宾语或未完成的句法
→ 是否属于同一次看见、承认、追问、反驳或情绪冲出
→ 中间若真正停住，人物关系和听法会不会改变
→ 是否需要新的旋律起点或真实换气
→ 最后才决定合行、分行或加入句级控制
```

生成输入里的换行不是中性的版式符号。平台把每一行作为歌词输入单位时，换行可能成为乐句结束、句尾延长、换气或重新起唱的候选；插入句级标签又会增强这个边界。共同主语下的连续动作、共享宾语的并列谓语、仍未结束的一次追问或同一轮高潮递进，中间默认不插标签。需要的只是局部重音、音色或字尾变化时，不必为了描述它另造一次起唱。

连续高潮要做“时间方向”检查：每条指令分别标为前推、中性或减速。`re-entry / pause / isolated silence / hold / sustain / falling phrase / close / release / broaden`并非禁词，但连续落在相邻歌词前，可能叠加成反复收尾与重启。若乐段目标是一气增能，优先把共同情绪和声音运动提升到乐段标签，句级标签只保留真正改变句义或关系动作的断点。

### 停顿

停顿必须完成至少一项：让前句后果落下；把下一句从补充改成反驳；暴露一个人称或否定；让桥段新证据改变最后回归。删除停顿后句义与听法都不变，就不应强加。模型把停顿唱成拖拍时，先回到连续乐句或交给编配让位，不继续添加标签。

### 气口

先按自然词组朗读，再根据速度、字密度和歌手能力调整。无旋律时气口只是候选；不得用竖线切歌词正文，不得为了每行整齐固定一个或两个气口。

### 高音

先列出全曲三个候选峰值：公共事件、私人失去、人物最终承认。由作品总线选择一个主峰，其他位置通过节奏、和声、音色或配器取得分量。第一次副歌不必用完最高音；桥段可以是情绪最高点而不是音高最高点。

### 技巧

混声、真假声转换、气声、颤音、转音、短收和长音分别回答：它改变了距离、意志、脆弱、余波还是句义中的哪一项。一个技巧同时解释不了作用对象和删除损失时，先不用。桥段接近说话可以成立，但不能把其他乐段都唱成平直叙述，只为了让桥段显得特殊。

## 六、编译为嵌入式 Controlled Lyrics

当前项目已经由用户确认嵌入式歌词控制格式。段落级控制写在乐段标签内部：

```text
[Verse 1 ｜ hold grief behind clear words ｜ intimate vocal ｜ connected phrasing]
歌词正文
```

句级控制单独占一行，并紧贴在目标歌词上方：

```text
[(reject the past tense｜clip “不”｜brief silence, then return to pulse)]
不
```

禁止三种错位：把`｜`写在歌词正文后面；把句级控制塞进上一句歌词；把整份控制另做成表格而最终歌词仍是裸标签。段落指令只写本段共同成立的唱法；一处歌词独有的停顿、重音、长音或改口才使用句级控制。控制密度以试听效果为准，不能为了显得细致给每一行贴标签，也不能把标签插在同一个演唱乐句内部。判断次序固定为`先划乐句 → 再定换行 → 再决定是否需要标签`，禁止从作词换行直接推导逐行控制。

编译前先建立父子约束，而不是先删标签：

```text
Style Prompt：锁定人物处境、全曲情绪运动、BPM、细分脉冲、groove、整体能量走向、主唱基准音区与高潮准备
→ 乐段标签：继承上述不变量，只写本段相对上一段的人物动作、进入状态、退出状态与可听增量
→ 句级标签：继承本段人物动作、拍点与能量，只处理一句独有的情绪转折、音色、距离、咬字、重音、字尾或被全局允许的停顿
→ 真实成歌：若听感与设计冲突，回到最早冲突层重编；不能让一句局部标签偷偷接管整首伴奏
```

每个乐段在内部至少记录`入口能量 / 出口能量 / 句子密度 / 主要音区 / 力度 / 伴奏脉冲是否继续`。相邻两段逐项交接：后段可以在上一段出口上加力、变色、扩宽或抽空，但不能没有准备地同时改变速度、音区、响度和句子密度。副歌的高点若要成立，前一段至少要在气息压力、和声期待、句长或音区中的一项给出准备；后半段的高潮优先通过支撑、共鸣、句子密度和编配宽度增长，不能默认用一整段高音解决。

`soft / close / speech-like`默认只改变力度、音色、距离或吐字，不等于降速；`sustain / hold / pause / suspended / unresolved / rubato`可能改变时间感，同一标签或相邻标签叠加时必须检查是否会拖慢人声并连带打断伴奏。`re-entry`只用于确实需要重新起唱的位置，不能拿来描述同一乐句后半的轻声变化。全曲要求脉冲继续时，优先把共同唱法写到乐段标签并保持歌词连续；真正需要自由速度或停拍时，Style Prompt 与编配必须同时给出位置和恢复方式。

父子关系成立以后再做跨层去重：全曲始终成立的声线、咬字、速度和制作距离只留在 Style Prompt；乐段标签只记录相对全曲或上一段的新变化；句级标签只记录相对本段的新变化。每条控制检查三件事：是否产生独立可听结果；是否与全局时间线和能量线相容；删掉后上一级是否已经足以得到同一结果。前两项成立、第三项不成立就保留，不能因为追求更少标签而删掉具体、有效的轻声、口语化或字尾动作。

所有控制在生成前先建立双层控制表：人物表演层逐段记录对象、情绪动作、内在矛盾和本段变化；声音执行层逐段记录节奏、音区、力度、发声、连断、重音、字尾与段落交接。编译完成后做双向核对：去掉人物表演短语，仍能看见完整、可执行的唱法；去掉声音执行短语，仍能看见人物在对谁完成什么感情动作。任一方向丢失信息，都说明另一层正在代替它，必须退回重编。重新编译时，已经成立且能产生独立可听结果的决定继续保留；只有跨层重复、上下级冲突或真实试听负增益才单项撤销。

### 全曲控制分辨率与局部返编

控制详略不要求各段字数相等，而要求各段的因果闭环达到同一完成标准。每个主要乐段都必须能够独立回答：人物此刻对谁完成什么动作；相对上一段新增什么声音变化；本段怎样接住入口并把能量、音区、脉冲或关系交给下一段。职务简单、已经能够由 Style Prompt 自然推出的乐段可以写得短；承担双重情绪、音色转义、复杂转场或结尾改判的乐段可以写得长。短只能来自功能简单和上级已经覆盖，不能来自沿用旧占位词、未重新判断或为了省事写成`悲伤地唱 / 更有力量 / 渐进高潮`。

只要局部修改新增了旧生成包没有的控制维度，例如把一个乐段从气氛标签推进到`人物矛盾 + 声音动作 + 入口出口`，就暂停局部交付，对整首歌执行一次“分辨率返编”：逐段重开双层控制表，确认旧段是有依据地保持简洁，还是仍停在较低标准；再重查相邻交接和全曲连续线。`保留锁定内容`只保护歌词、人物决定和已经验证的声音动作，不保护低完成度占位控制；`单变量 A/B`限制的是两次试听之间改变的声音假设，不允许一份基线内部一段精写、其余段落欠设计。若补齐旧段会同时引入多个新声音变量，先建立一份完整、同标准的新基线，再从它复制单变量试验版。

数量只作过载预警，不作创作目标：通常每个乐段二至四项、每个句级标签一至三项已经足够；超过时逐项说明它为何无法由上一级推出、为何必须协同存在。真实试听证明更多或更少更有效时，以试听为准，并记录当前平台与模型版本。禁止把默认数量反过来当作删减指标，造成格式更短、有效信息也更少。

官方通用资料与用户指定格式不一致时，分别记录事实身份：官方资料说明通用接口公开了什么；用户指定格式决定当前项目怎样交付。不得用前者擅自删除后者，也不得把后者宣称成所有 MiniMax 接口都支持的官方语法。具体唱法仍需单变量试听：

```text
基线：相同段落控制 + 锁定歌词
试验：只增加或修改一个句级控制
固定：Style Prompt、歌词、平台、模型、时长和可固定的 seed
判断：模型是否识别；目标句是否改善；全段节奏是否受损
```

识别不稳定、标签被唱出、目标句无改善或全段节奏变差，立即撤销该句级控制；保留用户指定的格式骨架，不退回错误的表格格式。

## 七、歌词锁与校验

Controlled Lyrics 默认在去掉段落标签与句级控制后，与锁定歌词逐字符一致。若实际接口会把换行当作乐句边界，可以启动“演唱乐句编译”：锁定非空白字符、标点、段落标签及其顺序，只允许合并或重分相邻歌词行；不得借重排增加、删除、替换或倒置任何歌词内容。作词稿继续保存作者确认的视觉排版，生成包单独保存演唱排版，并在 Platform Assumptions 中声明。用下面的命令检查允许演唱重排的完整生成包：

```bash
python3 tools/check_controlled_lyrics.py \
  --lyrics locked-lyrics.txt \
  --ai-lyrics package.md \
  --section "方案 A Controlled Lyrics" \
  --require-package-fields \
  --require-controls \
  --control-syntax bracket-pipe \
  --allow-performance-reflow \
  --lint
```

校验器必须同时检查三件事：段落控制是否在乐段标签内部；句级控制是否使用`[(...)]`并位于目标歌词上方；全角`｜`是否只在中括号内部。未启用重排时验证全部字符与换行；启用重排时验证段落和全部非空白字符，空格与换行只承担演唱编译。它证明格式和歌词内容没有被改，不证明乐句划分或控制一定有效；声音效果只能由同条件试听确认。

## 八、试听回填

先保留无控制基线，再记录可观察差异：实际速度是否拖；哪些分行被唱成不必要句号；哪个重词没听清；哪个停顿破坏推进；哪个长音拖坏字义；哪个高点给错对象；哪个标签带来负增益。修正顺序是：

```text
撤销造成负增益的具体句级控制
→ 保留正确的嵌入格式并调整 Style Prompt 中的速度、事件密度和段落运动
→ 修旋律、groove、和声或编配
→ 有导唱后细化绝对音高、时值与气口
→ 最后才申请歌词回填
```

不得把节奏拖沓全部归咎于 BPM；同时检查细分脉冲、和声更换速度、句尾延长、段间空白、低频进入、鼓点密度和反复抽空。相同 BPM 可以产生完全不同的身体速度。若伴奏正在持续增密或进入高潮，而人声标签仍要求慢唱、反复停顿或长拖字，优先撤销或改写局部时间指令；除非全局蓝图明确采用“伴奏前行、人声跨拍悬置”的反向关系，并且真实成歌没有破坏 groove。

## 九、直接淘汰

- 为了证明“做了演唱控制”而强制每段或每句出现标签。
- 没有旋律便宣称某字已经是绝对高音、固定长音或真实换气点。
- 把同一标签同时作用于语义不同的两句，例如把等待与后果一起机械短收。
- 把作词稿的每次视觉换行直接当作演唱边界，或在共享主语、宾语、连续谓语和同一次情绪推动的中间插入句级标签。
- 连续高潮本应一气增能，却在相邻每行前反复写重新起唱、停顿、延长、收尾和释放，使多条局部指令累积成减速。
- 用户已明确嵌入格式，仍把`｜`写到中括号外或把控制改成逐行表格。
- 把项目确认格式冒充官方通用语法，或拿官方缺省示例推翻当前项目格式。
- 宏观提示词写低速、稀疏、连奏和反复抽空，成歌拖沓后只修一句局部控制。
- 用桥段的耳语、念白或抽空方式复制所有乐段，使全曲失去速度和对比。
- 控制带来负增益后继续补更多控制，或用作者解释替代基线试听。
- 用 Style Prompt、乐段标签和句级标签反复描述同一唱法，使控制短语增加而独立可听决定没有增加。
- Style Prompt 要求持续脉冲与逐步增能，乐段或句级标签却反复要求降速、自由拍、长停顿或大段高音，造成局部控制反过来改写整首歌。
- 为了通过控制数量预警，删除原本能准确区分轻声、近口语、重新进入和字尾收束的有效动作。
- 用`悲伤、深情、心碎、情绪饱满`等气氛词代替人物在该句对谁做什么，或只列混声、重音、停顿、长音等技巧，使表演技术正确却没有关系与感情。
- 把人物表演层写成声音执行层的注释，或用其中一层改写、概括、删除另一层，使控制只能回答“为什么唱”或“怎样唱”中的一个问题。


## 十、从完整设计到本轮输入

完整表演与声音设计供制作判断，平台歌词供本轮生成；两者的差异必须能解释，不能用人物描述替换声音执行，也不能把每个设计细节都复制成标签。具体对照记录与证据口径按 [音乐风格路由与提示词生成](音乐风格路由与提示词生成.md) 第十节执行。单次标签失效先收窄到平台、版本、位置和输入组合；有益的局部动作仍保留，不推导“标签越少越好”。

歌词工具只核对文字、标点和结构。未知方括号行保留参与比较，不能自动当作可删除控制；新增结构标签先核对接口支持，再同步工具。工具识别结构不代表平台支持，未知标签原样一致也不代表可以投喂。
