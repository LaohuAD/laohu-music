# 音乐风格路由与提示词生成

本 reference 把 MiniMax Music 3 的 `Music Brief → Genre Router → Family Index → Reference Roles → Structured Caption` 迁入老胡音乐 V4。它保留外部项目的信息密度和渐进式读取，改用 V4 的作品总线、前台声音身份、词曲回填和平台诚实边界。

## 谱曲箴言

```text
风格是身体，不是标签堆。
先定听法，再定音法。
一主一辅，声音才有归处。
参考取职，不取皮相。
全局定骨，分段见血，提示词只留可执行的字。
提示词要能对应声音，不能只会解释。
```

这些话是统领选择的公理，不是禁词表。细则必须回答“这项音乐动作替作品完成什么职务”，不能把公理退化成“禁止某个乐器”或“必须使用某种曲风”。

## 一、建立 Music Brief

在读取风格库前，先把输入压成一张内部声音简报。只记录有根据的内容，并给每项标注来源：`explicit`（用户明说）、`tagged`（歌词标签）、`inferred`（由总线推断）、`unspecified`（未知）。

```text
作品类型：vocal_song / instrumental
现实用途：影视节点、片尾、独立发行、现场或其他场景
目标听众与起始状态：谁在什么身体、情绪或注意状态下开始听
聆听职务：希望音乐帮助他自我理解、调节唤醒/情绪、连接他人，或陪伴一项活动；只能选本作真正负责的主项
目标动作与指标：听完、复听、收藏、跟唱、律动、分享、引用、搜索或作为内容素材；用完成率、复听率、收藏率、分享率、使用量等相应指标验证
艺术赌注：本作故意拒绝哪项类型惯例或顺滑处理 / 为什么必要 / 谁可能拒绝 / 必须留下什么听觉后果
听众入口：第一耳先听见谁的身体、哪一个动作或哪一个记忆
音乐身份：流派、文化语境、必要的融合方向
速度与身体：BPM或范围、拍号、groove、前倾/后靠/悬置
人声：主唱身份、性别、音区、音色、距离、咬字和唱法
前台声音身份：一条短乐句或声音事件中最先被认出的词、动机、节奏、唱法或音色组合；项目通常以约3–8秒作为工作范围，不把它写成科学阈值
身份回归：它在哪些乐段重复，保持什么，最后一次只改变什么
段落：Intro、Verse、Pre-Chorus、Chorus、Bridge、Outro的实际职务
声音材料：核心乐器、声部关系、声场、制作质感
明确排除：用户明确不要的声音、语言、角色或制作手段
```

未知就保留未知。没有证据时，不凭题材补精确 BPM、调性、声部关系、歌手性别或具体制作技术；宽泛但可执行的假设优于虚构的精确。

## 二、约束有先后

```text
用户明确要求与排除
→ 歌词中的乐段标签和局部控制
→ 作品总线与锁定歌词
→ Music Brief 中的强推断
→ 参考卡提供的风格特征
→ 平台默认值
```

局部标签只能改变本段音乐行为，不能推翻全曲的音乐身份。冲突时采用最小、可解释的调整；不能悄悄反转人声性别、纯音乐要求、速度限制、核心乐器、歌词控制或用户排除项。

## 三、把“好听、特色、记忆点”变成试听任务

`好听`不是一种曲风，也不是生成前能够由提示词自证的客观属性。项目只在已知用途、目标听众和作品总线下判断：听众能否进入、能否辨认、能否继续听、复听时是否仍有发现，以及声音质量是否妨碍这些结果。不同文化经验、流派习惯和听歌场景会改变偏好，不能把一张固定分数表当成普遍审美。

### 先分清三层成功

```text
作品反应：目标听众是否喜欢、听懂、记住，并愿意继续听。
情境复用：歌曲是否稳定完成某项聆听职务，使人愿意在同类状态或活动中再次调用。
传播放大：曝光、平台分发、社交证明、艺人关系、营销和时代事件怎样扩大结果。
```

声音设计可以提高作品反应和情境复用的概率，不能单独决定传播放大。`容易火`必须改写成一个可观测动作和一个具体人群/平台；若用户真正要的是短视频使用量，不能拿完整播放率替代；若要长期收藏和复听，也不能拿十五秒停留替代。项目交付时分开报告已经设计的、真实试听支持的、发布数据支持的和仍由外部分发决定的部分。

### 制作控制不能缩小艺术胆量

风格提示词需要少量优先项，是因为生成模型会受到条件竞争和字符预算影响；这不说明作品本身只能有一处轻微创新。先在声音蓝图中完成完整的艺术判断，再把它压成模型最需要保住的因果：哪项惯例被拒绝，哪个声音事件完成拒绝，其他部门怎样共同承担后果。若不规则旋律、粗粝发声、突然抽空和未解决和声都在完成同一项人物选择，它们可以作为一套协同设计保留；若只是分别炫技，才删减。

第一遍可进入只要求目标听众能够找到作品的说话者、身体或声音秩序，不要求立刻舒服、同意或得到解决。故意造成的不安、空缺、延迟、刺耳、重复压力和语义悬念，只要来源清楚、后续兑现，就属于作品内容；不能在“清晰、顺滑、商业、适合歌单”的名义下自动抹平。反过来，难听、含混和失控也不会因为大胆便自动成立：删掉它以后作品没有损失，或它只能靠作者解释，仍然淘汰。

### 把个人感受变成可反驳的声音假设

`磁性、浓厚、悠然、哲理感、治愈、带感`是听众对整体效果的命名，不是模型能稳定执行的单一参数。先问这个词具体指向哪一种听觉事实，再写声音动作：

```text
磁性/浓厚：低或中低音区、偏暗音色、较完整共鸣、较强声带闭合感、轻微粗糙或气声、贴近收音、稳慢句法可能分别造成这种感受；不能默认全部叠加。
悠然/哲理感：较低事件密度、稳定脉冲、较长乐句、停顿、清楚语义、克制装饰和稀疏织体可能让听众有思考空间；歌词若只有抽象金句，声音再松弛也不能证明内容有哲理。
带感/想动：节拍显著度、鼓与贝斯咬合、切分程度、微时值、重复、低频和段落能量共同决定；BPM 只能描述速度，不能单独证明 groove。
```

每个感受标签形成两张互斥假设卡。例如同一首反思性歌词可比较“中低音区、贴耳、连奏、少装饰”与“中音区、明亮、口语断句、稳定脉冲”；两版只改变一个主要声音家族，检查语义一致性、喜欢、记忆、身体反应和目标用途。胜出只对当前人群、作品、平台和模型版本成立，不自动写成跨题材默认值。

功能场景也不能按歌单名套公式。情绪不佳时既可能需要同情绪陪伴和自我理解，也可能需要提高唤醒、转移注意和改善心境；驾车既需要稳定陪伴，也可能被过强音量、过度刺激或抢注意的编排干扰；运动、工作和睡眠面对的唤醒水平与注意负担不同。先写“听众开始怎样 → 希望音乐让他怎样 → 不能妨碍什么”，再决定速度、律动、动态、歌词密度、音色和段落变化。

重要生成先建立六项听觉任务：

```text
入口：最初一个主要乐段是否给出稳定的速度、律动、调式重心、声线或核心织体，让目标听众知道怎样听；实验性作品可以延迟入口，但要说明延迟换来什么。
期待：让目标听众获得足够线索，能够辨认作品正在建立或拒绝什么规律；偏离可以很小，也可以由多个部门共同完成，幅度由艺术赌注决定，不由“有限偏离”预先封顶。
前台身份：听众在不看提示词和歌名时，能否复述、哼唱或描述一个短乐句或声音事件；它可以是旋律、节奏、歌词、人声动作、音色或二者的稳定组合。
回归发展：同一身份再次出现时保留可辨认部分，只改变一至两项与人物或段落有关的内容；完全照抄容易停滞，全部换掉又失去作品身份。
清晰与空间：主唱、主旋律、承重词和核心律动是否有可听位置；新增声部不能靠后期形容词掩盖遮蔽。
用途相称：音乐可以与歌词同向，也可以有意反衬；必须说明反差让听众多听见什么。无意冲突、错误人物距离或错误使用场景直接淘汰。
```

`有特色`不由冷门乐器、稀有音色或流派数量证明，也不被限制成“熟悉基础 + 一个受控偏离”。它要求一个不能随意替换的作品决定，以及这个决定在全曲留下的连锁后果。熟悉语法可以胜出，激进组合也可以胜出；判断标准是异常音色、复杂节奏、陌生和声、极端唱法和曲风切换是否共同完成同一项听觉选择。各自炫技就删，彼此加强就保留，不能按异常项数量裁决。

“一个前台声音身份”是项目为了减少提示词竞争而设的优先级，不是关于好音乐只能有一个 hook 的科学定律。作品可以有副动机、前奏 riff、节奏 hook 和人声 hook；进入 Style Prompt 前仍要选一个最应被模型保住的前台身份，其他材料只做协作。真实试听若证明两个身份彼此加强且都能被听众复述，可以保留；若互相抢位置，退回一个主项。

没有用户锁定的声音参考时，先比较两个完整艺术方向，再在胜出方向里选择提示词最应优先保护的前台身份。完整方向必须改变听众怎样理解人物、怎样经历段落或怎样记住声音，允许多个相互依赖的字段一起变化；只换形容词、乐器皮肤或制作光泽仍是同一方向。前台身份随后写清它重复在哪里、保持什么、怎样变化、最可能怎样失败。

## 四、渐进式路由

每次谱曲都按以下顺序打开资料，禁止扫描全部模板：

```text
读取外部 references/genre-router.md
→ 选择一个主风格家族
→ 只有明确融合或必要对照时，增加一个副风格家族
→ 最多读取两个 family index
→ 在索引卡中选最多三个不同职责的参考
→ 只打开被选中的完整模板
→ 把参考的职务迁移到当前作品，不复制句子、参数组合或整套结构
```

路由优先看流派、groove、核心配器和文化语境；`伤感、史诗、现代、电影感、黑暗、燃`只是修饰，不能单独决定风格家族。无明确流派时，先看身体节奏，再看主唱和核心乐器，最后才以情绪或意象作为保守兜底。

### 参考卡的三个职务

```text
Foundation：承接全曲身份、groove和基本写歌语言。
Modifier：只提供一个已被请求的副维度，如文化色彩、主唱质感或制作纹理。
Arrangement：只提供段落能量、声部生命周期、转场和进入/退出逻辑。
```

一个参考同时承担多个职务时，必须写清它实际被借用的维度。副参考不能覆盖主风格、速度、人声、核心乐器、排除项或前台声音身份。只选到一个可信参考时，不为了凑满三个而加弱匹配。

## 五、声音蓝图先于 Style Prompt

内部蓝图必须先回答：

```text
这首歌让听众先用身体感到什么
→ 哪个动机、词语或声音事件成为前台声音身份
→ 每个段落让谁进入、退出、靠近或让位
→ 旋律、groove、和声、配器和演唱怎样共同服务这条变化
→ 最后一次回归改变的是责任、判断还是距离
```

蓝图的开头还要写明本轮主听觉命题：听众起初怎样听这段关系，最后必须重新听见什么，哪一种声音关系承担改听。后面的旋律、groove、和声、配器和演唱不能各自追求完整；只有对这项改听有职责的内容才进入蓝图。

不能拿“古风、伤感、电影感、空灵、炸裂”代替蓝图。它们只能作为检索线索，最终必须落成速度、重拍、句法落点、音区、声部行为、音色职责或结尾动作。

在编译提示词以前，为胜出的前台身份写一张内部卡：

```text
载体：哪一个词、旋律、节奏、人声动作、乐器音色或稳定组合
首次出现：在哪个乐段、由谁完整交出
辨认不变量：每次回归必须保留的音程轮廓、节奏、歌词、音色或发声动作
唯一变体：最后一次回归只改变什么，以及它对应哪项人物或段落变化
让位关系：伴奏、人声层和效果怎样给它留下时间、频率或声场位置
删除测试：拿掉这项设计以后，歌曲是否仍能被同一句普通风格描述替代
```

删除以后作品仍然同样可辨认，这项设计只是装饰；删除以后歌词更难懂、段落更松散或作品反而更清楚，则先修设计，不用“特色”替它免责。

### 可执行语言怎样判断

“可执行”指一个短语能够落到可听对象、声音状态、段落位置或相对变化，不等于把所有句子改成命令。内部声音蓝图允许解释人物事实为什么要求某项声音选择；最终 Style Prompt 删除作者理由，只保留模型需要生成的结果。试听回填再记录实际听见的差异，不能把前面的创作意图当成结果已经发生。

先辨认平台怎样使用文字：

```text
从零生成 / text-to-music：默认使用描述式语言，写成这段音乐听起来怎样、谁在何时进入、前后怎样变化。
已有音频或分轨的指令编辑：只有平台明确经过 instruction tuning 或文档确认支持时，才使用 add、remove、extract、only 等操作命令。
独立技术字段：sample rate、bitrate、format、duration 等写入平台字段；没有对应字段时，不把它们伪装成风格词并承诺生效。
```

最终短语优先采用下面四种形状：

```text
对象 + 状态：solo female alto, dry close-miked, clear consonants
段落 + 动作：muted piano anchors the verse; full bass enters at the chorus
声部 + 关系：guitar fills answer in the spaces between vocal lines; lead vocal remains centered
前后 + 差值：pre-chorus narrows the phrase length; chorus opens the low end and stereo field
```

情绪、场景和审美词可以作为辅助描述，但附近必须有声音实现。`melancholic`可以保留，随后要说明是低音区贴耳主唱、稀疏钢琴、延迟解决的和声，还是其他可听选择。三类句子直接退回重编：`为了表达她终于放下`属于作者解释；`make the chorus more powerful`只有要求，没有声音动作；`high-end, cinematic, emotional`只有评价，没有对象和段落变化。可执行版本应写成：`chorus opens with full drums and bass; the lead vocal shifts from close restrained phrasing to open stable resonance; one low harmony enters on the final hook`。

负向要求先改成正向目标和边界：`no reverb`优先写`dry upfront vocal with minimal room ambience`；`no background noise`优先写`clean studio capture with a low noise floor`；`no backing vocals`优先写`single exposed lead vocal throughout`。只有目标平台明确支持负向提示或编辑命令时，才同时保留简短否定。用户要求的是整首歌时，`isolated vocal`会与完整伴奏冲突，必须先裁决交付物是成曲还是干声，不能靠同一条 Style Prompt 同时索取两种结果。

### 副歌到达与段落对比账

生成主副歌歌曲的 Style Prompt 前，先比较 Verse、Pre-Chorus、Chorus 与 Final Chorus 的相对状态；副歌的分量来自相邻段落的可听差值，不来自“乐器越多越好”。内部逐项记录：声部密度、节奏密度、音区跨度、和声稳定度与更换速度、力度、音色亮度、声场宽度与纵深、主唱距离与人声层数。随后只选择一种主要到达策略，并指定两至三项主要变化：

```text
扩张：副歌增加必要声部、低频根基、音区跨度或声场宽度；主歌和预副歌保留对应空间。
转换：声部数量接近，但副歌改变 groove、和声归宿、音色职责、重音或主唱姿态。
抽空：预副歌先建立密度或期待，副歌撤掉部分伴奏，以停顿、近距离主唱或单一动机暴露核心句。
```

“主歌一件乐器、副歌加入全乐队”只在核心乐器能够独立建立歌曲身份、又没有提前占满节奏与频率时使用。不得按乐器件数判断能量：一件钢琴可以用满和弦和宽音区占满声场，多件声部也可以通过错开音区、缩短时值和轮流进入保持清楚。预副歌若已增加节奏密度，就把副歌的主要差值留给低频归位、和声释放、音区展开、声场变宽或人声层次中的其他项目；不能在预副歌和副歌连续复制“越来越多”。

编译 Arrangement 时把相对动作写进同一句，不用孤立标签：`verse stays narrow around muted piano and lead vocal; pre-chorus adds a restrained pulse while withholding full bass and backing vocals; chorus opens the low end and stereo field as drums and a single low harmony enter`。采用抽空时则写清撤掉谁、留下谁以及核心句为何因此被听见。第一次副歌不自动用完全部和声、叠唱和宽声部；第二次或最后一次回归必须根据新证据决定增加、替换还是撤掉。新增声部遮住中心词、制造频率拥挤，或删去该声部后副歌职务不受损时，删除该声部，不用混音形容词替无效编配善后。

### 参考音频的接口分流

上传音频以前先建立一行输入账：

```text
目标操作 → 平台与模型版本 → 文档说明会保留什么 → 音频覆盖的乐段与时长 → 音频实际含有什么 → 本轮允许模型改变什么
```

同一段音频放进不同接口，会承担完全不同的工作：

| 目标操作 | 音频主要提供什么 | 合格输入 | 不得承诺 |
| --- | --- | --- | --- |
| 从零生成 / text-to-music | 通常不依赖参考音频，由歌词和声音描述建立整歌 | 完整歌词、段落标签、Style Prompt 与平台字段 | 不把文字要求说成模型必然逐项执行 |
| Cover / Remix | 按平台能力保留或重组源音频的旋律、节奏、结构与演唱关系 | 准备继续保留的成品或完整导唱；整歌任务默认使用完整曲式 | 局部片段不能自动补出准确的主歌、桥段和整歌回归 |
| Style Reference | 音色、配器、速度、声线、制作质感或宽泛结构特征 | 权利清楚、声音身份准确的代表性片段 | 不等于精确旋律控制，也不等于整歌曲式已经设计 |
| Extend | 片段末端的调式、节奏、声部与局部上下文 | 能承担续写起点的片段 | 不证明模型知道片段之前缺失的内容 |
| Voice Conversion / 声音转换 | 原演唱的音高、节奏、咬字、气口和表演 | 有实际歌词与表演动作的导唱或干声 | MIDI、蜂鸣器或无词合成元音不能替代演唱 |

技术上能够上传，只说明文件满足格式与时长，不说明它适合当前任务。若平台会保留旋律或节奏，先独立试听源音频：旋律不好听、字句没有落位、段落不完整或唱法错误时，直接否决源音频，不让 Cover/Remix 把错误扩写成完成度更高的成曲。局部副歌只有在本轮明确验证 hook 时才可先做；一旦目标改为整歌生成，必须先完成整首音乐结构，或改走不依赖该片段的 text-to-music 路线。

截至 2026-08 的官方接口证据只用于确定边界，调用时仍需重新核对当前版本：[MiniMax Music Generation](https://platform.minimaxi.com/docs/api-reference/music-generation)把 `music-3.0` 的从零生成与 `music-cover` 分开，Cover 预处理会返回歌词和带时间戳的段落结构；[Suno Cover](https://help.suno.com/en/articles/2872257)把 Cover 定义为改变风格同时保留旋律，并把 [Audio Upload](https://help.suno.com/en/articles/6141569) 作为另一种工作流；[Udio Audio Upload](https://help.udio.com/en/articles/10754328-create-music-with-your-own-audio)把 Extend、Remix 与 Style 分开，[Udio Styles](https://help.udio.com/en/articles/11003046-styles)说明 Style 使用上传音频的局部上下文抽取整体声音特征。由此只能推出“先按接口分流”，不能推出三家平台会以相同强度保留同一项音乐信息。

## 六、Style Prompt 的三段式输出

给 MiniMax Music 3 或其他目标平台的最终风格提示词保留三段信息，但必须压进已核实的平台/模型硬上限；项目默认以 1000 个 Unicode 字符作为减少条件竞争的工作预算，不把这个预算冒充所有接口的硬上限：

```text
Global Metadata：流派/融合、速度/拍号/groove、情绪运动、声场与制作轮廓。
Vocal Details：人声歌曲的主唱身份、音区、音色、距离、咬字、和声和少量效果；纯音乐写主题动机的主导乐器或音色。
Arrangement：核心声部职责、各乐段进入/退出/让位、段落变化、转场和结尾。
```

推荐顺序是“身份 → 身体 → 前台声音身份 → 声部职责 → 段落变化 → 结尾”。每个短语尽量同时带有对象和动作，例如“fingerpicked guqin anchors the verse, opens into sustained ensemble tones in the chorus”，而不是只写“优美古风、情绪递进”。

编译前建立一张字段来源账，不放进最终提示词：

```text
Global Metadata ← 现实用途、主听觉命题、速度与身体、整体声场
Vocal Details / Motif ← 人物身份、主语言动作、中心句、前台声音身份
Arrangement ← 段落职务、动机回归、和声与配器的进入、退出、让位和结尾后果
```

每个字段再标内部证据等级：`documented`（平台正式支持）、`project-tested`（当前平台与模型版本已有试听记录）、`creative-hypothesis`（根据作品提出、尚待试听）。等级不写进最终提示词，但要进入 Platform Assumptions。只有 `documented` 可以承诺接口存在；`project-tested` 只能说明在已测版本中较稳定；`creative-hypothesis` 不得写成模型一定执行。

每个字段必须能回到一项已确认事实、声音蓝图决定或标明来源的假设；回溯不到的短语删除。未知项保持未知，不为了写满三段、接近工作预算或用尽平台上限而补风格库存。三段如果给出互相不同的情绪曲线、高潮位置或人物距离，回到蓝图重编，不能在表皮层用连接词缝合。

提示词长度不是质量目标。先保留前台身份、groove、主唱身份、核心声部关系和段落差值；同义形容词、没有位置的制作赞美和重复情绪词先删。每个短语至少承担“建立基础、突出身份、制造段落差值、保护清晰”中的一项，承担不了就不占条件预算。

Style Prompt 不是分析报告，不放：

- 选题解释、歌词复述、营销口号和给用户看的创作自述；
- 只表达情绪、不说明音乐动作的宽泛形容词；
- 互相冲突的流派、声部、人声或制作要求；
- 禁止清单、平台无法执行的导演语言和未被证据支持的精确参数；
- 参考模板中的原句、歌名、模板 ID、逐句结构或可识别的独特组合。

生成包必须同时记录“平台硬上限”和“项目工作预算”。超过任一当前交付门都退回重编，不能因为平台允许更长就绕过项目预算；只有用户明确要求保留超预算信息并接受条件竞争风险时，才可例外记录。需要压缩时依次删除跨字段重复、同义形容词、装饰性制作词和从属声部；保留前台声音身份、主唱身份、groove、核心乐器职责、段落变化和结尾动作。仍超限时回到血肉层合并不影响总线的副职务；不得删掉作品的声音中心来换取通过。

字符数必须用项目工具计算，而不是凭肉眼估计：

```bash
python3 tools/check_style_prompt.py --file style-prompt.txt --limit 1000 --lint
```

工具按 Python Unicode code point 计数，空格、换行和标点均计入；`--limit` 必须填本轮要检查的硬上限或工作预算，未传时使用项目默认工作预算 1000，不能把默认值解释成平台事实。超过传入值返回非零退出码。`--lint` 还会提示混入采样率、码率、文件格式、弱负向命令和提取/移除命令等接口风险；这些警告需要回到 Platform Assumptions 裁决，不能机械删除用户明确要求。若输出是完整包，使用 `--section "方案 A Style Prompt"` 对指定段落计数，不能把 Controlled Lyrics 或 AI Lyrics 的字符混入风格提示词上限。

## 七、vocal_song 与 instrumental 分流

`vocal_song` 先冻结歌词正文，建立文字、标点、段落与次序基准，再写 Style Prompt，并把逐段逐乐句的演唱判断编译成当前接口可直接复制的最终歌词。用户或项目指定嵌入式控制时，必须使用`[乐段｜指令]`和目标行上方的`[(句级指令)]`；不得退回控制表加裸歌词。作词稿的视觉换行不能直接冒充生成气口；接口会把换行当作乐句边界时，可另做只改变空白与换行的演唱乐句编译，并使用对应校验模式。声音可以解释歌词，不能趁谱曲改事实、人物关系、字句、标点或段落责任；词曲冲突回到写词阶段或申请解锁。

`instrumental` 不把人声歌简单删掉主唱。它必须拥有用途、身体动作、一个前台主题动机家族、实际形式、groove/和声、配器生命周期、高潮或非高潮策略和结尾。它不使用人物称呼、中文咬字、歌词主韵、演唱控制谱和 AI Lyrics 规则。

## 八、生成前后的检查

生成前检查：

```text
是否已经选出一个前台声音身份作为提示词优先项
主参考与副参考各司其职吗
目标接口是描述式生成还是指令式编辑；语言形状是否匹配
每个 Style Prompt 短语能否指出对象、声音状态、段落位置或相对变化
是否仍混入作者理由、模糊命令或只有评价的形容词
负向词是否有平台支持；能否先改成正向目标和明确边界
采样率、码率、格式和时长是否放进对应技术字段
Style Prompt 是否低于已核实的平台硬上限；超过项目工作预算的每项内容是否有独立职务
三段式信息是否齐全且没有互相冲突
副歌采用扩张、转换还是抽空；两至三项主要差值是否明确
主歌与预副歌是否提前耗尽副歌选定的差值
每个乐段是否写了至少一个进入、退出、让位或变化
新增声部是否仍让中心词和主旋律保持清楚
最终歌词是否已经按当前接口嵌入演唱控制；是否还要求用户自行拼装
```

真实音频回来后，不用“更好听”作为自证。按“听见什么 → 预期什么 → 差异在哪个字段 → 最早改哪个字段”的顺序回填；同一根因只改一组字段，并记录下一次可被听见、可被反驳的预期。没有音频时，只能声称提示词内部一致和待验证假设。

方向探索与工程诊断不得混用。方向探索比较两套完整且可独立成立的声音方案，允许相互依赖的曲风、旋律、groove、人声和编配共同变化，用来判断哪一套艺术选择值得继续；不能为了可归因，把大胆方案拆成几个失去协作的温和改动。方向锁定后才做可归因 A/B：歌词、平台、模型版本、时长和其他设置保持一致，平台支持时保持同一 seed，每轮只改变前台身份、主唱动作、副歌到达策略或制作距离中的一个，用来定位具体效果。

试听采用硬门加比较，不把审美伪装成总分：

```text
硬门：人物/主唱没有唱错；承重词能听清；没有妨碍使用的伪影、破音、削波或声部遮蔽；交付物确实是成曲、清唱、分轨或编辑结果中的目标类型。
第一次听：不看提示词，听众先描述听见的作品身份、主唱距离和段落差值；描述与意图相反时先判失败，不用解释纠正听众。
短时回想：经过一次短暂停顿或无关动作后，听众能否哼唱或准确描述前台身份；只能说“伤感、电影感、好听”而说不出声音事件，说明身份仍然泛化。
回归检查：第二次或最后一次出现时，身份仍可辨认，并且变体确实对应新信息或新责任。
情境复听：在目标设备、常用音量和真实活动中试听；分别记录是否想再次调用、是否完成目标动作、是否干扰主要任务。专注耳机试听胜出不等于驾车、运动、工作或放松时也胜出。
分歧检查：分别记录听众具体喜欢什么、拒绝什么、隔一段时间记得什么。少数人强烈记住、且拒绝原因正是作品有意保留的选择，不能被平均喜好覆盖；所有人只说顺耳却无法复述任何声音事件，也不能靠平均分胜出。
安全化对照：把艺术赌注改成同类型最常见的旋律、唱法、和声或段落处理；常规版若更顺却使作品判断、声音身份或回归后果消失，退回原方向修实现，不删除赌注。
成对裁决：A、B 都过硬门后，说明哪一版在入口、身份、发展、清晰和用途上胜出；没有单一赢家时保留具体分歧，不用平均分强行判优。
```

若听众喜欢 B 但无法复述 B 的身份，不立刻判 B 失败：它可能靠整体 groove、制作质感或熟悉度取胜。记录这项事实，再决定本作保护即时愉悦还是可识别记忆。若作品目标同时要求独立发行和传播，必须继续寻找既不过硬门、又能留下身份的版本。

## 九、来源与适配边界

外部参考资产位于 `external/MiniMax-Music3/skills/music-caption-rewriter/`：

- `references/genre-router.md`：风格家族路由与别名；
- `references/index-*.md`：紧凑风格卡；
- `templates/*.txt`：完整三段式模板。

V4 只按需读取它们，不把外部仓库的默认输出长度、精确参数或英文叙述风格视为不可变规则。V4 的最终裁决仍由作品总线、歌词锁定、演唱控制、字符校验和真实试听负责。

段落对比规则还参考两类公开专业资料：Berklee 对歌曲对比的教学把和声更换速度、音高、音程、音符时值、重拍位置和力度都列为能量变化手段，说明副歌差异不能缩减为乐器数量；iZotope 关于副歌与编配的制作文章同时展示新增声部、分阶段加入、窄主歌与宽副歌等方法，也提醒垂直叠加会造成频率遮蔽，而且持续高能量的类型可能依靠音色、滤波或抽空制造段落变化。V4 采用其中“相邻段落必须有可听差值”的共同原理，不把任何一种加层方案写成必做公式。

模型语言边界采用四项证据：[MiniMax Music 3.0 API 文档](https://platform.minimax.io/docs/api-reference/music-generation)把 `prompt` 用于风格、情绪和场景，把采样率、码率、格式放在独立 `audio_setting`；同一份现行文档给普通 Music 3.0 与 cover 接口规定了不同的提示词范围，说明字符上限必须随平台、模型和接口记录，不能由项目经验硬编码成平台事实。[MiniMax Music 3.0 技术说明](https://www.minimax.io/blog/minimax-music-3-0-next-generation-open-weights-production-ready-versatile-music-model)强调细粒度时间描述用于刻画情绪、乐器和演唱随时间的变化。[Google MusicCaps](https://huggingface.co/datasets/google/MusicCaps/blob/main/README.md) 的训练式文本以音乐人写的声音描述和 aspect list 为主，并明确排除艺人名等元数据。[Instruct-MusicGen](https://arxiv.org/abs/2405.18386) 的消融实验则显示，原本为音乐描述设计的文本编码器不擅长理解 `extract / remove / no / only` 等编辑命令，经过指令训练后才明显改善。V4 因此默认使用“声音描述 + 段落动作 + 相对关系”，只在目标平台明确支持时切换为编辑命令；这项依据说明语言接口应当匹配训练任务，不能证明任何单条提示词必然被生成模型严格执行。

平台控制不能跨产品照搬。[Udio 的官方 guidance tags 说明](https://help.udio.com/en/articles/11166249-level-up-your-creations-with-guidance-tags)明确称这些标签是建议而非硬编码命令，并承认遵循度仍在改进；[Suno 的 Exclude Styles 说明](https://blog.suno.com/release-notes/exclude-styles)则把排除乐器、风格和人声类型放进独立界面。它们支持项目把 `Style Prompt / Lyrics Tags / Exclude / Technical Settings / Reference Audio` 分开记账，也说明所谓“隐藏控制”只有在指定平台与版本中被文档或试听支持时才成立。

“好听、特色、记忆点”的项目定义只借用研究能支持的部分，不把相关性写成配方：[不确定性与惊奇的交互研究](https://doi.org/10.1016/j.cub.2019.09.067)说明音乐愉悦不是越熟悉或越意外越好，二者组合会改变愉悦评价；[切分、身体运动与 groove 的实验](https://doi.org/10.1371/journal.pone.0094446)发现中等程度的节奏复杂性在其材料中获得更高的愉悦和运动评价；[人声音色与陌生旋律记忆实验](https://doi.org/10.1177/0956797612442552)和[音色一致性的旋律识别研究](https://doi.org/10.1080/20445911.2012.674029)支持把声音身份视为记忆材料；[流行音乐混音中的注意研究](https://doi.org/10.3389/fpsyg.2021.769663)显示主唱在复杂混音中具有较高显著性。它们支持建立可辨认规律、安排惊奇、保持声音身份、让回归发生变化并保护前台清晰；不能证明创新只能是一处有限偏离，也不能证明陌生元素越多越好。

“有用途更容易被反复调用”有调查和心理学依据，但不能直接推成爆款因果：[音乐聆听功能研究](https://doi.org/10.3389/fpsyg.2013.00511)把大量聆听理由归纳为自我觉察、社会连接、唤醒与心境调节；[IFPI《Engaging with Music 2023》](https://www.ifpi.org/wp-content/uploads/2023/12/IFPI-Engaging-With-Music-2023_full-report.pdf)显示受访者广泛在驾车、通勤、放松、运动和工作等活动中听音乐。它们支持把聆听职务写入 Music Brief，不证明写上“适合开车”就会增加播放。

对“什么声音最火”的边界来自三类证据：[人声偏好研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC11026466/)发现听众的知觉评价比所测底层声学指标更能预测喜好，同时报告明显个体差异与旋律交互；[中、美、日流行市场的比较](https://pmc.ncbi.nlm.nih.gov/articles/PMC8356657/)显示音频特征偏好存在文化差异；[人工音乐市场实验](https://doi.org/10.1126/science.1121066)则显示社会影响会增加成功结果的不平等和不可预测性。V4 因此只把深沉、浓厚、松弛、强律动等当作待验证路线，并把作品内在反应、情境复用和外部传播分开验收。
