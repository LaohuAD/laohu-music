# 老胡歌词谱曲与声音实现

本 Skill 负责把选题阶段确认的作品总线变成听觉运动。音乐不是给歌词铺一层“伤感、燃、古风”的气氛；它必须安排听众何时稳定、何时怀疑、何时被迫等待、何时听见人物作出选择。

## 谱曲箴言

```text
音乐不替情绪贴色，音乐让关系有声。
先定听法，再定音法。
动机记住人，节奏承受事，和声保留未决。
高潮由本作体验决定，可是意义改听，也可是律动、音色与能量的到达。
曲风是人物的身体，不是乐器的名单。
好听须归总线，可唱才算落地。
```

解码顺序仍是：灵魂确定听众最终要重新听见的关系判断；筋骨安排稳定、破坏、等待、回归和选择；血肉让音乐材料来自人物、时代、语言和现场；表皮落实到音高、节拍、和声、音色、咬字、气口和制作参数。任何“更伤感、更电影、更古风”的形容词都只能作为待验证假设，不能代替音乐动作。

开始前必须读取[作品总线与跨阶段交接](../../references/laohu-lyric-topic/16-作品总线与跨阶段交接.md)，并按入口取得用途、现有声音或歌词与保护项。有词人声再核对中心句和歌手条件；纯器乐不要求歌词或虚构歌手。缺少旧卡片可从实际材料建立暂定简报，不阻止结构试验。

默认先词后曲流程中，正式谱曲准入还需要一份用户确认的`歌词已锁定`稿。写词阶段可以调用本 Skill 验证曲式、重音、气口和声音假设，但那是局部预验证，不等于作品已经进入谱曲阶段。先曲后词、伴奏或 topline 先行时，按实际入口先建立音乐约束，再交给选题和写词，不要求虚构一份先行歌词。

谱曲不是单向接收定稿。有词作品第一次取得可试听结果后进入`词曲回填中`，把真实重音、长音、气口、倒字、音域、时长和记忆反馈给写词；词曲共同通过并由用户确认后锁定声音。纯器乐无论由 AI、MIDI 还是人工录制完成，都省略歌词回填，按动机、结构、演奏与制作质量和用途试听，由用户确认声音后进入命名与封面，不虚构歌词流程。

涉及 AI 人声生成时，读取[音乐风格路由与提示词生成](../../references/laohu-lyric-composing/音乐风格路由与提示词生成.md)和[演唱控制与生成歌词](../../references/laohu-lyric-composing/vocal-control.md)。前者负责从外部风格库渐进检索并形成可执行的 `Style Prompt`，后者负责把逐段、逐句的主唱动作编译进目标接口要求的歌词格式。目标接口由用户本轮明确格式、当前项目已确认格式、平台文档和真实试听共同确定；不得因为通用官方资料没有列出某种项目格式，就擅自把用户已经明确要求的控制移出最终歌词。

纯器乐生成只读取风格路由与提示词方法，按接口设置无歌词或器乐模式；无关的人声控制、歌手和词曲回填字段省略。

## 1. 谱曲准入

先确定听者、用途、声音身份、持续或展开方式与验证条件。人物选择路线再把总线翻译成以下声音问题；其他路线不填写人物事实或不可逆行动：

```text
人物起点需要什么听觉秩序
→ 触发事实在哪个位置破坏秩序
→ 人物主动目标怎样形成重复动机
→ 现实阻力怎样进入节奏、和声、音域或配器
→ 副歌要完成承认、质问、请求、决定还是命名
→ 桥段的新证据怎样改变最后一次副歌
→ 结尾要让听众得到结束、悬念、牺牲还是余震
```

不能只给“伤感女声、电影感编曲、情绪逐渐推进”。必须说明音乐选择怎样服务本作体验，以及不用它会损失什么；人物路线再检查对应事实。

随后只确定一个主听觉命题：听众从什么声音进入，怎样持续、累积、释放、改听或回接，哪种音乐关系负责完成。它不是曲风、情绪或制作形容词，而是全曲音乐选择的胜负依据。内部按路径写清：

```text
听众怎样进入
→ 哪项声音秩序建立体验
→ 本作为何保持、累积、释放或改变；人物路径再检查触发事实
→ 哪些声音部门实现相应职务
→ 回归怎样延续、回接或改变听法；人物路径再检查承担
→ 结尾或循环边界留下什么可听后果
```

每次只允许一个主听觉命题统领全曲；其他正确标准作为辅助、硬门或待验证项。两项都重要时要说明主次和协作，不能把两个中心平均混成“层次丰富”。

`好听`不等于多数人都不反感，`有特色`也不等于在常规模板上换一个稀有音色。技术下限是意图可听、主次可辨、该听清的内容能听清、声音缺陷没有妨碍作品；艺术上限则要求全曲作出一项不可替代的听觉选择：它来自人物、关系、立场或世界规则，改变旋律、节奏、和声、曲式、音色、演唱或静默中的至少一处，并迫使其他部门承担后果。把这项选择改成更熟悉、更完整或更顺滑以后，若作品只剩同类歌曲都能使用的声音，修改失败。

正式生成前登记值得保护的艺术选择；若主动违背惯常期待，再说明为什么需要、谁可能拒绝及必须保留的声音后果，不为登记赌注强造偏离。它可以是拒绝和声解决、让副歌抽空、保留刺耳或脆弱的发声、使用不对称句法、延迟 hook、让核心问题不被和解，也可以是在喧闹类型中坚持近乎残酷的简单。项目不设“越怪越好”的偏离配额；安静、悦耳和传统同样可以成立，但必须有一个不能被同类模板替换的决定。

用户要求“容易火、容易传播、适合某个场景”时，先拆开三种结果：作品本身是否让目标听众喜欢、听懂和记住；是否适合在驾车、通勤、运动、放松、独处、短视频或其他情境中反复使用；曝光、社交证明、艺人基础、发行和平台机制是否把它放大。谱曲与提示词可以设计并验证前两层，不能把第三层承诺为声音配方。必须先写清目标人群、目标情境和目标动作——听完、复听、收藏、跟唱、律动、分享、引用或作为内容素材——再决定声音；“爆”若没有对应指标，不得当作可执行目标。

`磁性、浓厚、悠然、哲理感、治愈、带感`等词只登记为感受标签或创作先验，不能直接升级为普遍偏好。进入生成前必须把它们翻译成可听变量，并至少保留一个相反但同样服务作品的假设：音区与音域、明暗与共鸣、声带闭合感/气声/粗糙度、咬字、起音、连断、句长与停顿、节拍显著度、切分、低频关系、声部密度和制作距离。个人经验只有在适用人群、作品和场景明确，并经过同条件试听或发布数据复现后，才可升级为项目经验。

提示词的主次、字符预算、一个前台优先项和单变量诊断只负责减少模型条件竞争、定位生成原因；它们属于制作控制，不是艺术风险上限。同一项艺术赌注若必须由旋律、音色、唱法和段落共同完成，可以让多个部门协同偏离常规，只要它们都在完成同一个作品决定。不得为了便于写提示词、做 A/B 或让更多人接受，把一套相互依赖的艺术选择拆散后逐项删平。

## 2. 六个声音部门的职务

六个部门不是必须填满的配置表。先由主听觉命题决定本轮需要激活哪些部门、哪个部门承担主要变化、哪些部门只保护可唱和制作边界、哪些主动不动。每项被激活的设计都要留下同一条因果：

```text
作品来源：来自哪项事实、歌词、人物动作或关系压力
→ 声音动作：具体改变音高、节奏、和声、曲式、音色或唱法中的什么
→ 听觉作用：听众先听见什么，后来怎样改听
→ 相邻协作：需要哪个声音部门接住或反衬
→ 否决证据：什么试听结果说明这项设计失败
```

只说“更伤感、更有张力、更高级”没有声音动作；只写参数没有作品来源，也不算完成设计。

### 旋律动机

动机负责声音身份、记忆和回归。它可以联系中心句、人物动作，也可以先以节奏、音高、音色或演唱本身成为作品中心。再次出现时按用途保持、累积或变化；好听且有效建立律动、安定或辨识度就是有效职务，不强迫解释成戏剧关系。改变已锁定作品身份时提出回流，不能悄悄换题。

### 节奏与速度

节奏决定人物怎样行动和说话。等待、追问、仪式、奔走、对抗和决绝不能只靠 BPM 标签区分；要检查拍点密度、切分、延宕、停顿、推进和身体可感的步态。歌词最重要的词不能被无意义的弱拍、连读或装饰音吞掉。

### 和声与调式

和声负责稳定、悬而未决、抵抗、误导和释放。不得把“悲伤”等同于小调，把“高潮”等同于升调或更多和弦。选择必须说明：何处让听众以为会解决，何处拒绝解决，何处因桥段证据改变了同一旋律的意义。

### 曲式与段落

曲式负责信息、记忆、悬念和能量的分配。设计或评审曲式时必须读取[曲式结构与音乐叙事](../../references/laohu-lyric-composing/曲式结构与音乐叙事.md)。先比较结构候选，再决定是否需要主歌、预副歌、副歌、桥段、尾声、分节歌、回旋、冷开或通篇连续。对多材料叙事抒情、强反转副歌、主歌直达会产生心理或声音跳跃的作品，必须先试写预副歌；只有删除测试通过，才可裁决不使用。段落名称不能替代职务；删除一段后总线不受损，这段就不该存在。

没有旋律、和声循环、节奏、目标时长、歌手或明确曲风时，只能给暂定曲式方向和验证条件。不得因为题材“有故事、有场景”便机械套用标准 Verse–Pre–Chorus–Chorus，也不得在用户追问预副歌后把它当成补装零件；高压力叙事作品必须先完成预副歌文字候选，再说明直达副歌会失去什么、加入预副歌会延迟什么、哪项音乐变化使这段获得独立职务。

### 曲式问答的最低交付

凡是回答“曲式怎么排、能不能按这套写、要不要预副歌”，必须在对外回复中完成四步，不能只在内部比较：

1. 写清已经存在的歌词与音乐条件，以及仍然未知的条件。
2. 给出至少两个会改变 hook 到达、证据位置、重复方式或高潮顺序的完整候选；对上述高压力叙事作品，一个候选可以是“预副歌缺席”的直达方案，但必须作为被反证对象，不能预先享受“更简洁”的默认优势。
3. 分别说明每个候选保护什么、牺牲什么、怎样失败；然后给主推荐。
4. 明确指出什么旋律、和声、时长、歌手或用途条件会使推荐改变。

### 曲式分析的执行闸门

回答前先在内部完成一张“结构账”，再组织语言：

```text
当前作品已有的事实与必须保留的句子
→ 听众在每一段结束时已经知道什么
→ 哪个信息必须延后，哪句必须回归
→ 每次回归保持什么、累积什么或改变什么；关系路线再检查新证据与判断
→ 高潮由信息揭示、人物行动、旋律峰值、音色变化还是影像入口承担
```

结构账没有填完，不得使用“这首歌适合加预副歌”“故事需要一段过门”“情绪要再推一下”作为结论。尤其是叙事歌，不能把“人物经历很多”当成增加段落的理由；必须指出增加的段落究竟承载哪一项不能放进主歌、不能直接交给副歌、也不能靠音乐独立完成的新信息。

对外比较候选时，每个候选至少要写到具体现场或具体句子的位置，而不是只写“更有层次”“更抓人”“更电影感”。候选回答：从哪里进入，hook 或声音中心何时出现，重复保持或改变什么，对比段完成什么，结尾怎样收束或回接。仅在人物选择路线中追加桥段揭示与不可逆动作；纯器乐、律动和安定作品以可听结构判断。没有这些内容，所谓“候选结构”只是模板名称。

如果没有旋律、和声和时长，只能裁决歌词信息结构，不能把句长、音域、和声悬置和“情绪上行”说成已经确定的音乐事实。应把它们写成待验证条件，并明确哪种试听结果会删掉预副歌、移动 hook 或改用冷开。

表达曲式作用时，直接写可观察的音乐与歌词变化：变化发生在哪一段、持续多久、哪项和声稳定度、节奏密度、句长、音区、停顿、配器或信息位置被改变，以及核心句因此提前、延后还是换了听法。身体感和方向性比喻只能在这些事实已经清楚后辅助解释，不能替代设计参数与歌词位置。

### 配器与音色

配器负责人物世界、时代、距离和冲突的物理质感。传统乐器、战争打击、弦乐、电子氛围和戏曲声腔都不是题材贴纸；它们必须来自人物身份、世界规则或叙事视角。只因“古风”加入锣鼓、二胡和戏腔，是声音换皮。

副歌是否醒目，先看它与相邻乐段产生了什么可听差值，不看乐器数量是否绝对更多。确定编配前建立段落对比账，至少比较声部密度、节奏密度、音区跨度、和声稳定度与更换速度、力度、音色亮度、声场宽度与纵深、主唱距离与人声层数。为本次副歌选择一种主要到达策略：增加声部、音区或声场的`扩张`；保留相近声部但改变律动、和声、音色或演唱责任的`转换`；在预副歌已经积满能量后撤掉伴奏、让核心句暴露的`抽空`。每次只押两至三项主要差值，其他部门留出余地；不得把所有参数同时加满后用响度冒充高潮。

主歌由一件核心乐器贯穿、到副歌再加入节奏组和宽声部，是有效候选，不是通用公式。只有这件核心乐器确实留下频率、节奏和声场空间，而且歌词需要亲近或克制的入口时才使用；一件钢琴也可能因满和弦、宽音区和密集节奏而过满，多件乐器也可以因分工稀疏而保持低能量。预副歌可以增加推动，但不得提前耗尽副歌选定的主要差值；副歌新增声部若遮住中心词、让低频浑浊或使第一次副歌已经没有后续发展空间，退回段落对比账删减或改选到达策略。

### 演唱与声音表演

演唱负责人物此刻怎样把话说出来：克制、隐瞒、求答、命令、失控、认账或诀别。设计咬字、气息、真假声、音域、力度和装饰音时，先保护人物的语言动作。高音不是自动高潮，破音不是自动真情，戏腔不是自动文化重量。

形成方案时至少比较两个真正不同的声音方向，再决定是否公开。候选必须改变 hook 的到达、能量分配、重复意义、演唱姿态或结尾听觉后果中的至少一项；只换乐器、相近 BPM、风格标签和制作形容词，仍是同一方案的表皮变体。

### 2.7 编曲工艺委派：本 Skill 是协调者，具体工艺交给 `mc-*` 库

本 Skill 保留全部灵魂与筋骨判断权：主听觉命题、六个部门激活与否、副歌到达策略、艺术赌注登记、词曲接口裁决、总线一致性，都由本 Skill 定，不外包。但六个部门内部的**血肉与表皮工艺**——具体怎么写这条旋律线、这组和声怎么上色、这套鼓怎么打得像人——委派给挂在本 Skill 目录下 `skills/` 里的 `mc-*` 工艺库执行。它们是本 Skill 手里的执行件，**用户不从它们进入整首歌**；本 Skill 判定某个声音部门出现工艺缺口时才点名调用对应件。

| 本 Skill 已决定方向、需要落地的工艺缺口 | 委派给 |
|---|---|
| 旋律线怎么写、音高走向、最高音落点、由歌手换声点定调 | `mc-melody` |
| 和声功能骨架（先 T-S-D 再上色）、调外和弦 | `mc-harmony` |
| 具体和弦进行、避开模型最爱的套路进行、和声节奏 | `mc-progressions` |
| 离调与转调、接缝该多明显 | `mc-modulation` |
| 第二条线的对位（互补轴、横向声部进行规则） | `mc-counterpoint` |
| 节奏性格判定（这条节奏是什么、beat 感 vs 速度） | `mc-rhythm-groove` |
| 鼓组与贝司怎么打得像真人、量化到什么程度 | `mc-rhythm-section` |
| 块级曲式乐理（这段该叫什么、是一段还是两段） | `mc-form` |
| 全曲能量弧、乐器进退场、减法事件 | `mc-arrangement-arch` |
| 谁来奏这条线、几件叠起来变成什么新音色 | `mc-orchestration` |
| 单件音色从零点设计、音区、心理声学约束 | `mc-sound-design` |
| 空间预算、前景/背景感知线索、冲突改写而非改混 | `mc-texture-layering` |
| 主题材料在某段做了什么发展（封闭十操作） | `mc-development` |
| 这些字具体怎么唱（气声、力度、pitch 偏移、咬字时机） | `mc-vocal-direction` |
| 混音意图（mood 否决权、深度一致、诊断糊先查持续音） | `mc-mix-intent` |
| 风格落地与风格融合（citypop/edm/hiphop/jazz/影视/国风/摇滚…） | `mc-style-*` ＋ `mc-workflow` §2.4 |
| 规格单编译成各后端输入、符号乐谱 | `mc-render-compile`、`mc-symbolic-score` |
| 成品有没有 AI 味（照做率 vs 旗标数分开看） | `mc-ai-tell-audit`（只作为 `laohu-quality-supervisor` 的工具，不单独判交稿） |
| 不确定某个编曲决策归库内哪个件、要不要跑测试 | `mc-workflow`（库内导航＋边界表＋ARR-SPEC 契约，**非入口**） |

⚠ 三条边界，防止把判断权也一起外包出去：

1. **`mc-workflow` 不是入口、不是第二本状态账**。它原是编曲库的入口＋总协调者，在本项目被降级为库内导航工具；整首歌统筹仍归 `laohu-song-director`，编曲域统筹仍归本 Skill。ARR-SPEC 只作可选的规格参照，作品当前状态以创作日志为唯一权威。
2. **人声分两层**：本 Skill 的 §4 词曲接口、`mc-vocal-direction` 管「这些字怎么唱」（演唱表现）；「字落在哪个音、会不会倒字」是作词库 `lw-tone-check` 的语言正确性判断，不在这里裁决。
3. **生成交付以 `mc-render-compile` 为唯一编译器**；作词库的 `lw-suno-interface` 只管词侧文本对接，重叠处以编曲库编译器为准。

## 3. 段落声音总线

每个主要段落按表达路径填写：

```text
本段已有的听觉材料与体验；人物路线追加所知事实
→ 听众听到什么
→ 本段保持、累积、释放或改变什么
→ 核心歌词或器乐动机是什么
→ 音乐怎样让核心材料被听见
→ 本段怎样连接、回接或结束
```

最后一次副歌或核心材料可通过和声、旋律、节奏、配器、演唱或停顿形成到达，也可原样回归完成安定、仪式或循环；以实际作用裁决。关系改判路线不能只靠音量代替后果，稳定路线也不能为制造变化破坏有效秩序。

叙事型歌曲需要把反转分成三层：前文可回听的音乐伏笔、桥段出现的新证据、最后副歌的听觉后果。突然停顿、升调、转调和全乐队进入只是手段；没有前文铺垫和后文变义，都是效果，不是反转。

## 4. 词曲接口

逐句检查：

- 语义重音是否落在音乐重音或有意形成可解释的反差。
- 长音是否给了值得延长、韵腹能够稳定延展、意义不被拖坏的字；音高升高后是否需要合理的元音调整。
- 气口是否服从词组和句义，不把主谓、动宾和固定搭配切断。
- 转音和装饰是否遮住关键人物、动作、否定词和关系词。
- 韵脚是否获得稳定听觉位置；需要破韵时是否真的对应人物或信息变化。
- 音域峰值是否给了总线最重要的语言动作，而不是最方便唱高的字。

韵辙、字数和纸面气口都只能提供文字侧线索，不能替代发音与旋律的联合检查。对长音、音高峰值、快速密集句和连唱位置，按`前一音节 → 当前声母 → 韵腹延展 → 韵尾收束 → 下一音节`逐项试唱，观察双唇、舌位、下颌、气流和辅音时值怎样变化。辅音闭合或阻塞并非天然不连贯；真正需要修正的是它在当前速度、音高和时值中造成吞字、挤压、断气或无意的情绪重音。没有可试听旋律时，把结论写成待验证风险，不宣称某组字已经顺滑或一定难唱。

词曲无法同时保留时，比较损失：改词会不会改变事实和人物，改曲会不会破坏动机和段落，改演唱会不会损害听清与可信。不得默认让词或曲单方面让步。

## 5. 曲风不是乐器清单

讨论流行抒情、民谣、摇滚、说唱、R&B、K-pop、蓝调、艺术歌曲、戏曲融合、影视或合唱时，必须选二至三首可核对的声音参考，比较：速度与律动、旋律跨度、和声密度、段落长度、歌词密度、重复方式、声部关系、音色和演唱姿态。

只换乐器、鼓组、唱法或提示词标签，人物的行动、语言密度和段落职务没有变化，不算曲风适配。参考作品只能提供可迁移的方法，不能复制可识别旋律、节奏组合、配器标志和演唱设计。

### 5.1 风格参考与提示词适配

使用外部 MiniMax Music 3 参考库时，保持“路由 → 家族索引 → 参考卡 → 完整模板”的渐进式读取，不扫描或复制全部模板。每次最多一个 `Foundation`、一个 `Modifier`、一个 `Arrangement`；每个参考只能提供与其职务对应的维度。外部仓库位于 `external/MiniMax-Music3/`，它是只读参考资产，不是 V4 的第二套规则入口。

接口职责分开，作品交付不分家。每个公开的完整人声方案必须在同一个生成块中包含`演唱风格 → Style Prompt → 最终生成歌词 → Platform Assumptions`。最终生成歌词必须已经按当前接口编译完成：若用户或当前项目明确要求嵌入式控制，段落指令写进段落标签，句级指令单独写在目标歌词上方；若目标接口只能接收标准标签，则另附逐句演唱控制谱并输出标准 AI Lyrics。不得把需要用户自行搬运、拼接或改写的控制表当成最终歌词。

```text
Style Prompt：Global Metadata + Vocal Details/主题动机 + Arrangement；公开交付默认必须同时低于已核实的平台/模型硬上限和项目工作预算。平台允许更长不构成放宽项目预算的理由；只有用户明确要求保留超预算信息并接受条件竞争风险时，才可例外。
嵌入式 Controlled Lyrics：当前接口采用用户已明确的格式时，段落级写成`[Verse 1 ｜ 指令1 ｜ 指令2]`，句级写成目标歌词上一行的`[(指令1｜指令2)]`；全角`｜`只分隔中括号内部的指令，禁止写成`歌词｜控制说明`。
标准 AI Lyrics：目标接口没有嵌入式控制约定时，只使用正式支持的结构标签；细节另留演唱控制谱。两种模式都必须锁定歌词的文字、标点与段落次序；默认连换行一起逐字符一致。若生成接口会把换行当作乐句、气口或重新起唱边界，允许另做“演唱乐句编译”：只合并或重分相邻歌词行，不改任何非空白字符，并在 Platform Assumptions 中声明、用允许演唱重排的校验模式验收。
```

曲式、Style Prompt 和最终生成歌词是同一声音蓝图的三个接口：曲式负责信息、记忆、能量和回归次序；Style Prompt 负责全局声音运动；最终生成歌词负责当前接口所需的段落与局部演唱控制。需要独立演唱控制谱时，它是生成歌词的设计底稿，不是让用户再加工的半成品。各接口冲突时回到主听觉命题重新编译，不能让内部设计、平台输入和真实成歌各说一套。

编译演唱控制以前，先锁定三条全曲连续线。人物表演线写清歌者每段在对谁强忍、承认、反驳、追问、改口或作出决定，以及这项关系动作怎样逐段改变；时间线写清速度、细分脉冲与 groove 在哪里保持、哪里允许真正抽空或变速；能量与音区线写清每段进入和离开时的力度、句子密度、音区、共鸣与下一段怎样接续。Style Prompt 是三条线的全局契约；乐段标签继承全局并写本段的人物动作与可听增量；句级标签只处理一句独有的情绪转折、音色、距离、咬字、重音、字尾或已被全局允许的停顿。局部指令不得静默改写全曲速度、让伴奏迁就拖拍，或把尚未准备的高音区突然塞进后半段。

锁定三条连续线以后，不得按作词稿的视觉换行机械贴控制。先把每段重新划成“演唱乐句单元”：共同主语或宾语、连续谓语、同一次追问、递进复沓和同一口情绪，优先保留在同一单元；真正改变对象、句义、关系动作、旋律轮廓或需要可听气口时才建立边界。生成歌词中的换行和句级标签都按潜在边界处理：控制不得插进尚未结束的演唱乐句；连续高潮优先用乐段级控制维持推进，不能逐行重新起唱、收尾和解释。作词排版可以保留原有句式展示，生成排版则服务实际演唱；两者的差异必须只涉及空白与换行。

随后按双层结构生成全部演唱控制。人物表演层写歌者对谁开口、正在强忍、承认、反驳、追问、改口还是作出决定；声音执行层写节奏、音区、力度、发声、连断、重音、字尾和段落交接怎样使这项感情被听见。两层同时属于完整控制，不能互相代替：只有`悲伤、心碎、深情`等情绪形容词，或只有混声、重音、停顿、长音等技巧，都判为未完成。情绪不能自动等于更慢、更响、更高、更虚或带哭腔，声音执行仍服从全曲时间线和能量线。随后再做差量控制：删去指令后，目标结果能由上一级自然推出，或该指令只换词重复已有要求，立即删除；但任何能够产生独立可听结果的决定，不得因另一层已经写得充分、减字、减标签或默认数量而被删除。`softer re-entry`、近似口语、字尾轻收等局部动作，只有在该处确实需要重新起唱且不切断演唱乐句时才保留；若只是同一口情绪内的轻重、重音或字尾变化，优先交给同一乐句或上一级控制。信息密度以“人物为何这样唱、具体怎样唱、控制放置是否符合乐句边界、上下级是否协同”判断，不以标签数量和文字长度判断。每次编译完成后必须顺序朗读全部生成歌词，而不只是标签，检查人物动作是否递进、乐句是否被意外切断、连续局部指令是否累积出反复停顿或收尾、上一段出口能否成为下一段入口；任一项断裂，先回到对应层重编，不靠另一层补救。

Style Prompt 超过项目工作预算或平台硬上限时回到表皮层压缩，不得用提高校验上限或硬截断绕过；不得把歌词、创作解释、参考模板原句、禁止清单和营销语言塞进提示词。生成后必须先按项目默认预算调用 `tools/check_style_prompt.py`，已核实的外部硬上限另做第二次检查；人声歌曲还必须调用 `tools/check_controlled_lyrics.py`。

提示词和局部控制进入生成包前，还要区分证据等级：用户明确指定当前输入格式的是`user-specified-interface`，它决定交付形状但不证明声音效果；平台文档明确支持的是 `documented`；当前平台与模型版本已有重复试听记录的是 `project-tested`；根据作品提出但尚未试听的是 `creative-hypothesis`。不得把创作假设写成模型一定服从，也不得用某类歌词直接推导唯一性别、音色或唱法。

### 5.2 音频产物先定用途，再进入平台

只要准备制作、上传或复用音频，先写明它的唯一职务：`内部旋律草图`、`完整导唱`、`风格参考`、`Cover/Remix 源音频`、`续写起点`或`声音转换源`。随后核对目标平台和当前接口究竟会从音频中保留什么；接口能力没有正式文档或当前版本试听支持时，保留为未知，不用“参考音频”四个字把不同任务混在一起。

用途之间不得自动替换：

- 内部旋律草图只用于检查音高、节奏、和声或段落假设；合成元音、MIDI 渲染和局部乐段可以承担这项职务，但必须明确标为草图。
- 风格参考可以让模型借用音色、配器、速度、声线或整体质感，具体范围服从平台文档；不得承诺它会准确保留或补全整首旋律与曲式。
- Cover/Remix 若会保留源音频的旋律、节奏或结构，源音频本身必须已经拥有准备保留的音乐内容。目标是整首歌时，默认要求完整曲式和足以辨认的演唱或主旋律；局部副歌不能冒充整歌源音频。
- 续写只证明模型能够从片段前后发展，不证明它知道此前缺失的主歌、桥段和全曲回归关系。
- 声音转换需要实际人声表演来提供音高、节奏、咬字和气口；无歌词的合成旋律不能替代导唱。

局部副歌可以先行验证 hook，但它只能得到两种裁决：`通过，继续完成全曲`或`否决，停止扩散`。旋律尚未被用户或真实试听确认时，不得把局部草图交给 Cover/Remix 生成整歌，也不得用编曲、音色和模型完成度掩盖旋律本身没有通过。具体的平台接口判断与输入要求按[音乐风格路由与提示词生成](../../references/laohu-lyric-composing/音乐风格路由与提示词生成.md)执行。

## 6. AI 音乐生成与试听

生成阶段把声音蓝图翻译成当前接口能接收的动作。`Style Prompt`承接全局和分段声音变化；最终生成歌词按用户或项目已确认的语法嵌入段落与关键句控制。没有旋律或导唱时，可以指定相对高低、承重词、连断和候选停顿，不能虚构绝对音高、精确时值或已成立的换气。纯音乐只输出 `Style Prompt` 与 `Instrumental Form`。

这里的“可执行”不等于一律使用祈使句。先辨认目标接口：从零生成音乐、接口接收 `prompt` 或 caption 时，优先描述成品听起来怎样、各段怎样变化；只有平台明确支持指令编辑，并且已有音频或分轨作为操作对象时，才把 `add / remove / extract / only` 作为编辑命令。平台没有说明负向命令能力时，先写正向声音目标，例如用`dry close-miked lead vocal with minimal room ambience`代替只写`no reverb`；用户明确排除仍留在输入账中，但不能承诺一个未确认支持的否定词必然生效。采样率、码率和文件格式若有独立 API 字段，写入字段，不塞进风格描述。

生成前把总线翻译成可执行约束，不把情绪形容词堆成提示词：

```text
段落结构与时长
→ 每段新增的信息和能量
→ 中心句的音域、重拍、长音与气口
→ 主要动机怎样回归和变形
→ 核心配器进入、退出和转义的位置
→ 演唱对象、声线、语言动作和禁止的表演腔
→ 目标听众在什么情境使用、希望发生什么动作、用什么指标判断
→ 结尾必须留下的听觉后果
```

方向探索先比较至少两个完整且真正不同的声音方案；一个方案可以同时改变相互依赖的旋律、节奏、和声、音色和演唱，使听众先听见它完整的艺术判断。方向锁定以后再进入单变量诊断。试听至少分六轮：

1. **总线轮**：不看提示词，只听音乐实际把作品带向了什么结论。
2. **词曲轮**：检查重音、气口、长音、咬字和关键句可懂度。
3. **结构轮**：检查主歌、副歌、桥段和结尾是否真的发生变化。
4. **传播轮**：检查第一段承诺、主 hook、十五至三十秒切片、复听发现和现场跟唱空间；传播切片不得泄底或脱离全曲变成另一首歌。
5. **情境轮**：在目标设备、音量和使用情境中复听，检查歌曲是否妨碍驾驶、工作、运动、放松或内容使用的主要任务；实验室式专注试听不能替代真实用途。
6. **艺术保真轮**：把最危险、最不顺或最可能引起分歧的设计改成常规版本再比较；若常规版更容易接受，却让人物立场、声音身份、段落后果或短时回想明显变弱，保留原设计并继续修实现，不用平均喜好把它判死。

生成结果“好听”但总线错误，判为失败样本，不用制作质量替方向开脱。若音乐发现了更强的新命题，记录变化、收益、代价和需重做内容，回到选题确认。

重要作品分两种比较。艺术方向对照允许比较两套完整声音判断，不能要求它们只差一个参数；它负责决定哪一版更像这首歌。方向选定后的可归因 A/B 才锁定歌词、平台、模型版本、时长和其他设置，每轮只改变前台身份、主唱动作、副歌到达策略或制作距离中的一个，用来判断具体实现是否有效。两种比较都先过唱错、伪影、削波、遮蔽和交付类型等硬门；裁决时同时记录喜欢与拒绝、能否具体复述、艺术赌注是否被听见、身份怎样回归、用途是否成立，不把平均分最高自动当成胜出。没有真实音频时，只能确认结构与约束自洽，外部质量一律标为未知。

试听结束必须形成一份词曲回填清单：哪些词保持，哪些字需要换重音或时值，哪些行需要改词、改旋律、改气口或改段落。责任必须分清，不能把所有问题都推给歌词或歌手。清单处理完并由用户确认主版本后，才进入声音锁定。

### 6.1 生成包最低结构

若公开两个声音方向，每个方向都必须重复下面的完整结构，不能只给一份共同歌词、把演唱控制散放到另一文件。用户必须能够直接复制 Style Prompt 与最终生成歌词，不再自行把控制表改写进歌词。

## 8. 直接淘汰

- 用伤感、治愈、燃、电影感、古风等气质词代替声音设计。
- 旋律好听但中心句的对象、否定词或动作听不清。
- 主歌、副歌和桥段只靠音量区分，没有信息和人物变化。
- 未比较其他结构，直接把完整故事装进标准流行曲式；或先给固定曲式，用户追问后再机械补预副歌。
- 用“更紧、托起来、往上走、戏腔一点”代替曲式设计，没有说明节奏、和声、旋律、音域、句法或停顿究竟改变什么。
- 用升调、爆发高音、突然停顿或密集配器冒充高潮与反转。
- 用传统乐器、戏腔、军鼓或环境音给题材贴标签。
- 为迁就旋律改变事实、人物责任和总线结论，却不回选题。
- AI 生成第一版听起来完整便直接采用，没有总线、词曲、结构与传播回查。
- 把 MiniMax 的完整模板全部复制进项目，或同时打开过多风格家族，导致参考失去职责边界。
- 把 Style Prompt 写成分析报告、禁止清单或散文，超过已核实的平台硬上限后直接截断；或把项目工作预算误称为平台硬上限。
- 没有先完成逐段逐句演唱判断便堆入局部标签，或用控制标签增删、替换、解释歌词正文。
- 用户已经明确嵌入格式，却把`｜`写到中括号外、把控制另做成表格，或只交裸歌词让用户自行回填。
- Style Prompt、乐段标签和句级标签重复描述同一唱法，或用更多近义控制词制造细致感，却没有增加独立可听决定。
- 目标接口未明确时把某套项目语法冒充平台通用语法；反过来，也不得拿通用文档的缺省格式覆盖用户已经明确的当前接口。
- 把没有真实音频验证的提示词预期写成已经成立的演唱和制作事实。
- 未说明音频职务便把内部草图上传生成；或把局部、无演唱、尚未通过旋律试听的音频当成整首 Cover/Remix 源。

## 9. 理论边界

本 Skill 采用 Pat Pattison 的 prosody 原则：歌词、旋律、和声、节奏和声音选择应共同支持同一中心情绪与目的；并吸收 MiniMax Music 3 对结构化 Caption、分段控制和渐进式风格检索的实践。这里把它落实为“音乐必须实现选题总线”，不把英语重音、韵律和和声习惯机械套进中文歌曲。曲式与预副歌的具体研究边界见[曲式结构与音乐叙事](../../references/laohu-lyric-composing/曲式结构与音乐叙事.md)。

期待、延宕、解决、重复和变奏可以帮助组织听觉叙事，但它们不证明复杂和声、频繁转调或更多配器更高级。最终仍以人物、歌词、实际演唱、听众理解和作品用途验证。
