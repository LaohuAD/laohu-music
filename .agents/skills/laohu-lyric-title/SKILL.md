# 老胡歌词歌名

歌名不是剧情摘要，也不是给作品贴情绪标签。它是听众接触歌曲的第一个解释入口，也是听完以后重新理解整首歌的最后一个词。歌名初稿与正式歌名都必须先像一个真实可用的歌名；两者的差别是证据成熟度与锁定状态，不是前者可以降低体裁和命名质量。命名时必须读取选题交付的[作品总线与跨阶段交接](../../references/laohu-lyric-topic/16-作品总线与跨阶段交接.md)：歌名只能压缩总线，不能另起一个更容易点击的主题。

## 命名箴言

```text
歌名是门，不是摘要。
一词归全歌，不能另立命题。
先取证，再命名。
听前留一问，听后添一义。
短非德，怪非新。
```

命名仍按四层工作：灵魂找全歌真正要留下的关系判断；筋骨看标题怎样随段落和成曲改变听法；血肉只从已成立的物件、动作、原话和关系证据取材；表皮检查报幕、重音、字形、搜索和记忆。下面的五门是条件化验收，不是平均打分表；前一层不成立，后一层不能补救。

本 Skill 完成的是一次命名转译：从作品总线、歌词记忆、听觉记忆、人物动作和现实用途取证，经不同命名机制形成真正不同的候选，再用听前承诺、听后增义和全歌回插裁决。歌名可以从歌词外的声音记忆中长出来，但不能给作品增加歌词与成曲没有偿还的新冲突。

## 1. 先分清三种名称

- **路线标签**：帮助创作者比较方向或识别项目，只需清楚说明人物处境或核心冲突；它不必像作品名，也不得对外冒充歌名。
- **歌名初稿**：作品第一次进入真正命名后的当前歌名。它必须已经像一个可以报幕、推荐、印在封面上的歌名，只是尚未得到完整歌词、成曲和发布场景的全部反证；后续发现更强证据时直接重起或改写。
- **正式歌名**：歌词与成曲完成后锁定的作品入口。它要兑现整首歌，不提前替听众解释结局，也不能只对内部创作者有意义。

路线标签与歌名属于两种产物，不能靠改状态直接升级。同一组文字若要从路线标签成为歌名初稿，必须重新参加候选生成和淘汰。歌名初稿可以推翻，但不能因“以后还能改”便先交一句剧情说明、管理员结论或文件夹名称。

正式命名默认发生在词曲回填完成、发布主音频已经确定或至少存在近最终试听版本以后。灵感、选题、写词和谱曲阶段都可以生成、保留和重起歌名初稿；没有经过完整歌词、实际主 hook、成曲重音和听众记忆反证时，不得宣布正式定名。用户因委约必须提前锁定名称时，记录它会限制什么，并在成曲后再做一次强制复核。

## 2. 命名准入

开始正式命名前，至少拿到作品总线卡和：

```text
谁在唱、唱给谁、为何此刻开口
→ 全歌最重要的人物动作、关系变化或未完成事件
→ 主歌、副歌、桥段与结尾分别新增什么
→ 哪个物件、原话、称呼、地点或意象反复出现并改变含义
→ 目标歌手、听众、曲风、用途和发布场景
→ 哪些名称只是在解释命题，哪些已经进入歌词或声音记忆
→ 歌名要替总线兑现哪一项听前承诺与听后增义
```

只有题材、气质或一句模糊灵感时，先回 `laohu-lyric-topic`。选题阶段可以提出歌名初稿验证方向，但必须标明它仍可能被歌词推翻。完整歌词已有、歌名未定时，先从作品取证，不从“高级、电影感、古风、爆款”反推名字。

### 歌名初稿最低门

歌名初稿可以缺少成曲证据，不能缺少歌名资格。交付前至少完成一次跨机制生成、母义去重和主推荐裁决，并同时通过：

```text
像歌名：放进“下面请听《……》”和“你去听一下《……》”都自然，不像剧情梗概、创作备注或分集标题
→ 属于本作：至少连接一项已成立的人物选择、关系反差、关键动作、物件、原话或仪式
→ 准确而不说尽：听前给出正确问题或气质，不把死亡、背叛、牺牲方式或作者结论全部解释完
→ 留有增义：能够指出完整歌词或成曲将来要怎样使它多一层意思；目前只能假设的部分必须标明
→ 可推翻：写清缺少哪些歌词、声音或传播证据，以及出现什么新证据时必须重起
```

任一项不成立，就只保留路线标签并明确“歌名初稿尚未形成”；不得为了文件命名或阶段完整，拿说明句填上歌名字段。

## 3. 核心裁决顺序

歌名候选按以下顺序淘汰。前一层不成立，不用后面的传播分数救它。

### 第一门：作品归属

候选必须抓住全歌最不可替换的一项：核心物件、人物动作、关键原话、关系称呼、地点、仪式、时间节点、反复变义意象或中心判断。把它换到五首同题歌上仍成立，淘汰。

### 第二门：准确而不泥实

准确指向作品真正处理的关系与情绪，不等于把剧情结果说破。直接点明伤口只有在它比意象更能统领全歌时才是优点；若它提前泄露转折、压扁多义、缩窄共鸣或像剧情标签，淘汰或降为路线标签。

### 第三门：听前承诺与听后增义

听前，歌名应给出正确题材、气质或悬念，不误导听众。听后，它应因歌词中的事实、重复或反转获得第二层含义。一个标题听前听后完全一样，只负责说明故事，通常还没有完成命名。

### 第四门：声音与记忆

读出声、报幕、口头推荐、放进副歌或结尾试唱。检查字词切分、歧义、拗口、连续相近音、长度、重音和记忆线索。简短不是硬指标；多一个字若能增加关系、节奏和辨识度，可以保留。

### 第五门：传播与场景

检查歌手身份、曲风、影视或品牌用途、封面识别、搜索碰撞、同名作品和目标听众。传播不能反过来篡改作品：一个容易点击但不属于这首歌的名字，仍然是坏歌名。

详细标准读取[歌名功能、来源与理论边界](../../references/laohu-lyric-title/歌名功能来源与理论边界.md)。

命名回查总线：删除歌名后，作品的核心变化仍应由歌词、声音和画面共同成立；歌名只是把听众引向这次变化。若一个名字要求正文改写主矛盾、人物结尾或价值判断，说明它正在绑架作品，退回选题，不得为了名字迁就整首歌。

## 4. 候选生成程序

### 第一步：建立作品命名账

只从作品已有证据中列材料，不先写标题：

```text
人物与称呼
核心物件与道具
人物持续动作
关键原话或未说完的话
决定命运的地点、时间或仪式
主歌到结尾发生的关系变化
副歌最容易被记住的声音单位
成曲中最稳定的动机、停顿、唱法或音色记忆
听前普通、听后变义的词
```

每项写明它在哪一段出现、是否改变人物行动、能否至少两次变义。只有气氛，没有段落职务的物件不能成为核心候选。

### 第二步：跨机制生成

内部至少从四种不同机制生成候选，不得围绕一个词换近义词。机制不同必须改变名字依靠的作品证据和听后增义方式；同一母义换字数、语气和近义词仍是一条路线。优先考虑：

- 物件或道具；
- 人物动作或未完成仪式；
- 原话、称呼或关系句；
- 地点、时间、身份或声音符号；
- 悬念、反差或双重解释；
- 能在副歌反复的中心句。

不是每类都要公开，也不是类型越多越高级。内部生成的目的，是防止第一反应垄断命名。

### 第三步：母义去重

把修辞拿掉，用普通话解释每个候选在说什么。多个名字都只是“婚礼没有完成”或“他一直没回来”，归为一组，只留承载力最强者。候选数量多而母义相同，不算发散。

### 第四步：按五门淘汰

先归属、再准确与留白、再听后增义、再声音记忆、最后传播适配。不得把各项平均打分后让一个作品归属很弱的名字靠搜索性胜出。

### 第五步：放回整首歌

检查候选是否能自然出现在歌词、报幕、封面和听众转述中。若为了让歌名成立必须重写正文，先判断是标题发现了作品真正的中心，还是标题绑架了作品。后者淘汰标题。

完整生成、比较与淘汰方法读取[歌名生成、比较与复核](../../references/laohu-lyric-title/歌名生成比较与复核.md)。

## 5. 强制比较格式

对外不倾倒所有内部候选。保留一个主推荐和二至四个机制不同的强候选；每个候选说明：

```text
它抓住全歌哪项证据
→ 听前给出什么期待
→ 听后增加什么含义
→ 能否进入副歌、结尾、报幕和封面
→ 最大优点与致命风险
→ 为什么胜出或被淘汰
```

候选之间必须有裁决。`都不错，看你喜欢`等于没有完成命名。成曲证据仍不足但初稿最低门已经通过时，给当前歌名初稿与改判条件；最低门也未通过时，明确尚无歌名初稿，不拿路线标签顶替。

具体候选的逐项校准只作为案例保存在[歌名生成、比较与复核](../../references/laohu-lyric-title/歌名生成比较与复核.md)。主流程不从某一次胜出结果推导“物件名、事件名或关系句天然更优”；每次仍按作品归属、泄底程度、听后增义、声音记忆和传播场景重新裁决。

## 6. 与其他 Skill 的交接

- `laohu-lyric-topic` 决定作品写什么，可以调用本 Skill 产生歌名初稿验证主题集中度。
- `laohu-lyric-writing` 让核心词、记忆句和段落重复真正进入歌词；本 Skill 不为了保住标题强迫正文迁就。
- `laohu-lyric-composing` 检查标题句的音节、重音、旋律位置与演唱记忆。
- `laohu-lyric-cover` 使用正式歌名设计视觉层级，不替文字命名。
- `laohu-natural-dialogue` 负责向用户讲清比较，不得把专业淘汰磨成平级菜单。

歌名初稿在选题确认、歌词定稿、成曲完成和发布前至少复核三次。每次复核直接更新当前初稿，不创建版本名；成曲改变了重音、重复位置或听众记忆中心时，必须允许旧初稿被推翻。

## 7. 直接淘汰

- 用一句路线说明、剧情摘要或管理员结论冒充歌名。
- 因为“更直接、更痛、更准”便提前泄露结局。
- 用抽象大词、拼接隐喻、生僻典故或古风词库制造重量。
- 候选只换近义词、字数和语气，母义完全相同。
- 歌名与歌词没有可指认的证据，只靠作者解释建立关系。
- 只做搜索、点击和封面判断，没有作品归属与听后增义。
- 只因短便判优，或只因长便判劣。
- 为避免同名故意造怪词，牺牲自然中文与口头记忆。
- 把歌名初稿当沉没成本，拒绝让完整歌词和成曲推翻它。
- 用“初稿、暂定、以后再改”为不像歌名、只会解释剧情的名称降低标准。
- 给出一串候选却不推荐、不淘汰、不说明改判条件。

## 8. 交付

```markdown
## 当前裁决

## 作品命名证据

## 主推荐
- 歌名：
- 听前承诺：
- 听后增义：
- 进入歌词与声音的位置：
- 最大风险：

## 强候选与淘汰

## 歌名初稿 / 正式歌名状态

## 成曲后复核项
```

格式服从任务。用户只问两个名字哪个好，可以直接比较；判断依据仍必须覆盖作品归属、泄底、增义和声音传播，不能只谈个人喜好。
