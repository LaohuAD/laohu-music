# 老胡歌词歌名

歌名不是剧情摘要，也不是给作品贴情绪标签。它是听众接触歌曲的第一个解释入口，也是听完以后重新理解整首歌的最后一个词。正式歌名必须同时属于这首作品、容易进入听众记忆，并经得住歌词与成曲反证。命名时必须读取选题交付的[作品总线与跨阶段交接](../../references/laohu-lyric-topic/16-作品总线与跨阶段交接.md)：歌名只能压缩总线，不能另起一个更容易点击的主题。

## 1. 先分清三种名称

- **路线标签**：帮助创作者比较方向，只需清楚说明人物处境或核心冲突。`青衣巡演寻人`可以是路线标签，不必像作品名。
- **工作歌名**：在选题或写词阶段暂时集中材料。它可以先定，也可以在创作中改；不得因已经写进日志便获得正式地位。
- **正式歌名**：歌词与成曲完成后的作品入口。它要兑现整首歌，不提前替听众解释结局，也不能只对内部创作者有意义。

同一个词可能依次承担三种职务，但每次升级都要重新验收。定位清楚的工作名未必是好歌名；一句话能准确概括剧情，也未必值得印在封面上。

正式命名默认发生在词曲回填完成、发布主音频已经确定或至少存在近最终试听版本以后。灵感、选题、写词和谱曲阶段都可以生成、保留和淘汰工作歌名，但没有经过完整歌词、实际主 hook、成曲重音和听众记忆反证时，只能标为工作名或正式名候选。用户因委约必须提前锁定名称时，记录它会限制什么，并在成曲后再做一次强制复核。

## 2. 命名准入

开始正式命名前，至少拿到作品总线卡和：

```text
谁在唱、唱给谁、为何此刻开口
→ 全歌最重要的人物动作、关系变化或未完成事件
→ 主歌、副歌、桥段与结尾分别新增什么
→ 哪个物件、原话、称呼、地点或意象反复出现并改变含义
→ 目标歌手、听众、曲风、用途和发布场景
→ 哪些名称只是在解释命题，哪些已经进入歌词或声音记忆
→ 歌名要替总线兑现哪一项听前承诺与听后增义
```

只有题材、气质或一句模糊灵感时，先回 `laohu-lyric-topic`。选题阶段可以提出工作歌名验证方向，但必须标明它仍可能被歌词推翻。完整歌词已有、歌名未定时，先从作品取证，不从“高级、电影感、古风、爆款”反推名字。

## 3. 核心裁决顺序

歌名候选按以下顺序淘汰。前一层不成立，不用后面的传播分数救它。

### 第一门：作品归属

候选必须抓住全歌最不可替换的一项：核心物件、人物动作、关键原话、关系称呼、地点、仪式、时间节点、反复变义意象或中心判断。把它换到五首同题歌上仍成立，淘汰。

### 第二门：准确而不泥实

准确指向作品真正处理的关系与情绪，不等于把剧情结果说破。直接点明伤口只有在它比意象更能统领全歌时才是优点；若它提前泄露转折、压扁多义、缩窄共鸣或像剧情标签，淘汰或降为路线标签。

### 第三门：听前承诺与听后增义

听前，歌名应给出正确题材、气质或悬念，不误导听众。听后，它应因歌词中的事实、重复或反转获得第二层含义。一个标题听前听后完全一样，只负责说明故事，通常还没有完成命名。

### 第四门：声音与记忆

读出声、报幕、口头推荐、放进副歌或结尾试唱。检查字词切分、歧义、拗口、连续相近音、长度、重音和记忆线索。简短不是硬指标；多一个字若能增加关系、节奏和辨识度，可以保留。

### 第五门：传播与场景

检查歌手身份、曲风、影视或品牌用途、封面识别、搜索碰撞、同名作品和目标听众。传播不能反过来篡改作品：一个容易点击但不属于这首歌的名字，仍然是坏歌名。

详细标准读取[歌名功能、来源与理论边界](../../references/laohu-lyric-title/歌名功能来源与理论边界.md)。

命名回查总线：删除歌名后，作品的核心变化仍应由歌词、声音和画面共同成立；歌名只是把听众引向这次变化。若一个名字要求正文改写主矛盾、人物结尾或价值判断，说明它正在绑架作品，退回选题，不得为了名字迁就整首歌。

## 4. 候选生成程序

### 第一步：建立作品命名账

只从作品已有证据中列材料，不先写标题：

```text
人物与称呼
核心物件与道具
人物持续动作
关键原话或未说完的话
决定命运的地点、时间或仪式
主歌到结尾发生的关系变化
副歌最容易被记住的声音单位
听前普通、听后变义的词
```

每项写明它在哪一段出现、是否改变人物行动、能否至少两次变义。只有气氛，没有段落职务的物件不能成为核心候选。

### 第二步：跨机制生成

内部至少从四种不同机制生成候选，不得围绕一个词换近义词。优先考虑：

- 物件或道具；
- 人物动作或未完成仪式；
- 原话、称呼或关系句；
- 地点、时间、身份或声音符号；
- 悬念、反差或双重解释；
- 能在副歌反复的中心句。

不是每类都要公开，也不是类型越多越高级。内部生成的目的，是防止第一反应垄断命名。

### 第三步：母义去重

把修辞拿掉，用普通话解释每个候选在说什么。多个名字都只是“婚礼没有完成”或“他一直没回来”，归为一组，只留承载力最强者。候选数量多而母义相同，不算发散。

### 第四步：按五门淘汰

先归属、再准确与留白、再听后增义、再声音记忆、最后传播适配。不得把各项平均打分后让一个作品归属很弱的名字靠搜索性胜出。

### 第五步：放回整首歌

检查候选是否能自然出现在歌词、报幕、封面和听众转述中。若为了让歌名成立必须重写正文，先判断是标题发现了作品真正的中心，还是标题绑架了作品。后者淘汰标题。

完整生成、比较与淘汰方法读取[歌名生成、比较与复核](../../references/laohu-lyric-title/歌名生成比较与复核.md)。

## 5. 强制比较格式

对外不倾倒所有内部候选。保留一个主推荐和二至四个机制不同的强候选；每个候选说明：

```text
它抓住全歌哪项证据
→ 听前给出什么期待
→ 听后增加什么含义
→ 能否进入副歌、结尾、报幕和封面
→ 最大优点与致命风险
→ 为什么胜出或被淘汰
```

候选之间必须有裁决。`都不错，看你喜欢`等于没有完成命名。证据仍不足时，给当前工作名与改判条件，不把暂定包装成正式。

## 6. 《嫁衣》与《未拜堂》的校准

面对类似候选，禁止用“后者更直接说出伤口”直接判胜。

`未拜堂`首先是一个未完成事件，能清楚说明婚礼没有发生；它适合做内部命题标签、剧情节点或副歌中的问题。但它提前交代结局，意义主要停在“没有完成婚礼”，语气接近剧情说明。

`嫁衣`若确实贯穿戏服、婚服、约定、等待、舞台与现实，则同时是道具、身份和命运证据。听前是具体物件，听后可以变成没能兑现的婚约；它还能在主歌、桥段和末次副歌中反复变义。当前材料下，`嫁衣`优先于`未拜堂`。这不是因为它更古雅，而是它承载的作品事实更多，泄露的剧情更少，听后增加的意义更大。

这个案例只示范裁决方法，不建立“物件名永远胜过事件名”的偏好。若完整歌词根本没有让嫁衣行动、出现或变义，`嫁衣`同样应被淘汰。

## 7. 与其他 Skill 的交接

- `laohu-lyric-topic` 决定作品写什么，可以调用本 Skill 产生工作歌名验证主题集中度。
- `laohu-lyric-writing` 让核心词、记忆句和段落重复真正进入歌词；本 Skill 不为了保住标题强迫正文迁就。
- `laohu-lyric-composing` 检查标题句的音节、重音、旋律位置与演唱记忆。
- `laohu-lyric-cover` 使用正式歌名设计视觉层级，不替文字命名。
- `laohu-natural-dialogue` 负责向用户讲清比较，不得把专业淘汰磨成平级菜单。

工作名在选题确认、歌词定稿、成曲完成和发布前至少复核三次。成曲改变了重音、重复位置或听众记忆中心时，允许正式歌名随作品改变。

## 8. 直接淘汰

- 用一句路线说明、剧情摘要或管理员结论冒充歌名。
- 因为“更直接、更痛、更准”便提前泄露结局。
- 用抽象大词、拼接隐喻、生僻典故或古风词库制造重量。
- 候选只换近义词、字数和语气，母义完全相同。
- 歌名与歌词没有可指认的证据，只靠作者解释建立关系。
- 只做搜索、点击和封面判断，没有作品归属与听后增义。
- 只因短便判优，或只因长便判劣。
- 为避免同名故意造怪词，牺牲自然中文与口头记忆。
- 把工作名当沉没成本，拒绝让完整歌词和成曲推翻它。
- 给出一串候选却不推荐、不淘汰、不说明改判条件。

## 9. 交付

```markdown
## 当前裁决

## 作品命名证据

## 主推荐
- 歌名：
- 听前承诺：
- 听后增义：
- 进入歌词与声音的位置：
- 最大风险：

## 强候选与淘汰

## 工作名 / 正式名状态

## 成曲后复核项
```

格式服从任务。用户只问两个名字哪个好，可以直接比较；判断依据仍必须覆盖作品归属、泄底、增义和声音传播，不能只谈个人喜好。
