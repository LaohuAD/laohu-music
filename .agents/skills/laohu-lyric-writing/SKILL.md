# 老胡歌词写作

本 Skill 负责把选题阶段已经确认的作品总线写成歌词。它不重新发明人物和主题，不把文章分行，不把诗押韵，也不把沟通阶段的分析句直接塞进作品。开始前必须读取选题交付的[作品总线与跨阶段交接](../../references/laohu-lyric-topic/16-作品总线与跨阶段交接.md)；如果没有总线卡，只能做局部试验或退回选题，不能交完整歌词。叙事大纲只说明“发生什么”，不等于歌词信息结构已经确定；中文段名只说明编辑习惯，不等于正式乐段标签已经确定。整首歌持续创作时，同时读取 `laohu-song-director` 交接的当前阶段，区分`歌词初稿中、歌词精修中、歌词已锁定、词曲回填中`，不得把初稿交付冒充歌词定稿。

## 0. 作品总线服从门

动笔前把总线卡翻译成歌词任务：

```text
总线的核心变化 → 人物的起点、触发、压力、主动行动和结尾动作
总线的主矛盾 → 副歌主要语言动作和全曲反复的对象
总线的关键证据 → 主歌与桥段必须新增的事实
总线的不可逆选择 → 最后一次副歌和结尾必须承担的后果
总线的核心意象 → 至少三次有事实变化的出现
```

作品可以在写词时发现更好的事实或语言，但不得悄悄把“人物要解决什么”换成另一件事。若歌词初稿出现以下任一变化，停止炼字，回流选题：主矛盾改变、演唱对象改变、人物最后不再做原定选择、宏大背景被改成纯私人情绪、或副歌的主要语言动作与总线无关。短句更漂亮、押韵更顺、旋律更好唱，都不能替换总线。

## 1. 歌词成立的共同骨架

所有题材、类型和曲风先过同一组硬门：

1. **有人在唱**：明确谁在什么处境里唱给谁，旁听者是谁。每句属于人物当下的知识、欲望和口吻，不替作者讲完整道理。
2. **一耳能接**：歌词随音乐向前，听众不能停下来查词或重读。关系、动作和重心第一次听见就能建立；深意来自前后变化，不来自晦涩。
3. **段落有职务**：先决定听众需要按什么顺序获得事实、重复、悬念和后果，再选择主歌、预副歌、副歌、桥段或其他结构。使用了某段，才要求它承担明确职务；没有任务的段落删除，不按常见曲式补齐编制。
4. **文字能入乐**：词组切分、句长、重音、韵脚、元音、停顿和气口形成可感节奏；纸面顺畅但唱不出口，仍未完成。
5. **重复有理由**：重复负责记忆、参与和情绪加压。原句再次出现时，前文必须使它增重、变义或获得新的声音处理；否则只是复制。
6. **所有元素同向**：人物、材料、段落、意象、修辞、押韵、声音和曲风共同服务同一中心情绪与目的。任何局部技巧背叛整首歌，删掉技巧。
7. **作品有归属**：词句、细节组合、推进、韵脚地图和结论不能让听众把新作听成对标换词版；公共方法可以学，具体表达必须重建。

这七项只规定歌词的下限和组织原则，不规定所有歌词必须押同一辙、每句同字数、一定有预副歌或必须使用主歌加副歌。形式服从作品和音乐，不服从模板。

## 2. 写词准入

动笔前必须拿到或从现有歌词中还原以下内容：

```text
谁在唱、唱给谁、为何此刻必须唱
→ 发生了什么，人物想得到什么又怕失去什么
→ 这首歌要让听众最后知道、感到或决定什么
→ 哪些材料来自用户事实、可靠资料或已授权虚构
→ 哪些人物、关系、事实和结论已经锁定
→ 用途、歌手、时长、曲风、旋律或伴奏有哪些约束
→ 对标可迁移什么，哪些具体组合必须避让
```

持续创作任务还要读取《写词前创作简报》中的《歌词雏形板》：暂定标签序列、各段职务、主核心句、短 hook、副歌试验、回归变体、段落锚点、连接关系、声音假设，以及哪些属于硬锚、软锚、淘汰句和方向说明。雏形板不是可选背景；它记录的是前期讨论已经付出选择成本的结果。不得在完整初稿时丢弃它，重新按高频套路生成另一首歌。

缺少会改变人物、关系、用途或作品结论的项目时，停止完整写词，退回 `laohu-lyric-topic`。用户只要求修改现有歌词时，可以从现稿反推最小必要信息；无法判断的地方标明，不擅自补故事。

这道准入门只拦完整歌词，不拦服务上游判断的局部创作。人物、对象、当前处境和本轮要验证的语言动作已经清楚时，即使整首歌尚未进入歌词初稿，也必须完成对应的真实局部产物。阶段名称不降低文字标准；它只决定产物标为`局部试验、主候选、工作版本`还是`锁定稿`。

局部创作按交付物执行：

- 用户要副歌核心句：内部完成候选池、淘汰、声音假设和三次回归，对外只给一至两行胜出核心单位、可提取的短 hook、必要判断和最强失败候选；不加`[Chorus]`标签，不交完整副歌。用户确认核心句或明确要求进入副歌乐段后，再写完整副歌。
- 用户要某一乐段：写出该乐段的完整可唱版本，并说明它依赖哪些尚未确认的前后文；不能只列每行要写什么。
- 用户要工作歌名：调用命名能力给出实际名称与裁决，不交`围绕某个意象命名`。
- 用户要声音验证：给出可拍读、可哼唱或可试听的具体方案，不交`这里应该更有爆发力`。

材料只能支持粗稿时就标`粗稿`，但仍要真的写。没有候选通过高门槛时，必须证明已经生成并淘汰：展示最强失败候选、失败在人物、搭配、声音、归属还是回归，以及下一轮具体改哪一项。禁止在尚未创作候选以前用`还不能写、先确定方向、围绕这个动作继续`预支失败结论。

## 3. 创作流程

### 第一步：锁定声音和段落运动

先用普通话写清人物从开头到结尾发生什么变化。只保留一个主要运动，例如逐步承认、不断逼问、从误解到听懂、从等待到决定。没有运动，只能写出同一种情绪的多段改写。

已有歌词雏形板时先做继承审计，不重新从空白构思：确认哪些总线事实和硬锚不能改；哪些软锚可以为了整歌重写；哪些淘汰母义不得换词复活；哪些方向说明只能转译，不能原样进入歌词。雏形板与最新用户决定冲突时，以最新决定为准并记录被推翻项。

已有结构或旋律时先读取[依曲填词与旋律接口](../../references/laohu-lyric-writing/依曲填词与旋律接口.md)。自由写词时，先读取[段落结构与情绪推进](../../references/laohu-lyric-writing/段落结构与情绪推进.md)：先比较至少两个会改变信息顺序、hook 位置或高潮到达方式的结构候选，再确定需要哪些段落以及每段新增什么。没有旋律时只锁定歌词信息结构和待验证的声音假设，不把它冒充最终音乐曲式。

用户直接提出一套曲式或问“要不要预副歌”时，回答不得只在用户给出的模板上增删。最低交付必须包含：一个不使用预副歌的完整信息方案；一个使用预副歌或另一种形式的完整方案；两者在主 hook 到达时间、关键证据位置、重复变义和歌词容量上的实际差异；当前推荐与会让推荐改变的音乐条件。没有完成这组比较，不得继续排主歌一、主歌二和桥段内容。

#### 曲式与标签确认门

完整歌词正文开始前，必须完成一份可见的“歌词结构合同”：按实际顺序写出拟采用的英文方括号标签，并用一句普通话说明每段新增什么、主 hook 在哪里第一次出现、哪一段改变最后一次回归。标签语法与正式稿格式读取[歌词稿格式与乐段标签](../../references/laohu-lyric-writing/歌词稿格式与乐段标签.md)。

只有以下任一条件成立，才能越过此门：

- 用户已经看过这份标签序列并明确确认。
- 用户提供了固定旋律、工程段落或不可更改的曲式，并明确要求按它写完整正文。
- 用户明确选择“直接写完整歌词”，同时现有材料已经包含可还原的固定段落序列、段落职务、演唱视角和主 hook；系统先用一行标签序列复述后再写。

`继续、好、可以、1`不能自动补齐缺失的曲式决定。若上一轮只确认了故事、人物、锚点卡或叙事大纲，本轮应继续完成结构比较和标签序列，不得把助手自己说的“下一步直接写歌词”当成用户已经批准。

涉及第一、第二、第三人称、视角切换、对唱、多人分唱、群唱、角色信息权限，或歌词中出现书信、日记、留言、遗言、戏中戏和人物转述时，读取[演唱视角与多角色分配](../../references/laohu-lyric-writing/演唱视角与多角色分配.md)。这些载体一旦进入歌词，就属于角色正在发声，不再是作者说明；写词阶段必须重新确认说话者、对象、写作时刻、知识来源和语言目的，不得让作者越过角色知识边界。

存在公开演唱、隔空呼告、向众人打听某人或`我、你、他`同段出现时，完整歌词开始前必须提交“人称对象表”：歌者、当面听众、话中被指称者、真正希望听见的人，以及每一方此刻能做什么。第一人称向现场众人询问第三人称对象可以成立；人称变化只有在对象、时间、载体或演唱者变化时才成立。

### 第二步：建立材料账和词场

列出可写的事实、动作、原话、场景、感官、物件、时间变化和人物判断。每项标明来源。再选择一至两套能贯穿全歌的词语关系，例如等待与到达、承诺与失约、观看与误认。不能为了押韵临时拉入与人物无关的词。

材料超过一个事件、时间层、空间层或关系侧面，或需要决定情绪由事实、景物还是人物亲口承担时，读取[材料组织与叙事压缩](../../references/laohu-lyric-writing/材料组织与叙事压缩.md)，先确定一条主组织轴和每段主要抒情出口。存在两个以上有效入口或第一稿落入高频路径时，先写不同骨架碰撞；不得把故事梗概按时间分行，也不得只换标题和意象冒充不同方案。

涉及意象和环境，读取[意象场景与文化转译](../../references/laohu-lyric-writing/意象场景与文化转译.md)。涉及逐字、口吻、搭配和词场，读取[炼字炼词与人物语言](../../references/laohu-lyric-writing/炼字炼词与人物语言.md)。

### 第三步：先写段落事实，再压核心句

主歌先写能把副歌逼出来的事实，不能先写一堆泛情绪再让副歌凭空爆炸。副歌必须完成承认、质问、请求、命名、决定或反转中的一个主要动作。

需要情绪宣泄的副歌不能沿用主歌的叙事口气。进入副歌前先确定`情绪主色 / 反作用力 / 语言姿态 / 关系门槛 / 代价 / 主声音机制`：例如哀求中仍保留尊严，愤怒中仍然在乎，悲恸中仍不敢确认，决绝中仍要付出代价。副歌减少地点、履历和事件说明，增加明确称呼、关系动词、否定、条件、让步、请求、质问、判断和结果；只保留一至两个本作专属锚点。不得用`痛、伤、爱、恨、命运`等情绪名词替人物开口，也不得把`希望能够、只是想要、请你捎来`一类礼貌说明当作爆发。

副歌不得先从创作命题中抽出`消息、音讯、实话、准信、答案、真相、结果`等信息功能词，再按近义程度给它们分配情绪等级并围词造句。先确定人物最怕的答案、当面对象、关系动作和代价，再按画面、感官与身体、情绪、关系动作、必要事实、转折、回钩或留白给每行分配一项主要职务，最后才选择核心词与短 hook。整段全是事实说明、条件分流和剧情推进，直接退回[材料组织与叙事压缩](../../references/laohu-lyric-writing/材料组织与叙事压缩.md)重建，不让旋律替文字制造抒情。

副歌初稿必须同时提交文字压力链和声音压力链。文字压力链说明对象怎样被点名、两难怎样相撞、人物承担什么、核心句为什么在第一句、中段或最后落下；声音压力链说明句架怎样回归、词组怎样收紧或拉长、哪些实词占据重拍与长音、韵脚怎样收束、核心句前在哪里吸气。若核心句后置，前置句必须共同制造同一个预期；若核心句前置，后续句必须增加代价、改变关系或形成回钩。没有这两条链，只写出正确意思，不得称为副歌完成。

需要创作或验证副歌核心句时读取[副歌核心句与传播记忆](../../references/laohu-lyric-writing/副歌核心句与传播记忆.md)。选题阶段的中心问题、路线标签和管理员概括不自动成为歌词。

用户本轮点名的是副歌核心句时，`副歌动作、核心方向、核心问题、围绕什么写`都只是创作输入，不是交付物。必须继续写到一至两行具体核心单位，再由规则淘汰；不能因为第一批候选不够好就退回同义分析，也不能用完整副歌乐段把尚未通过的核心句包起来。

副歌驱动作品进入完整初稿前，主核心句候选必须先通过对象与搭配零号门，再至少通过：人物能说、关系有压、第一耳清楚、存在声音记忆机制、保留本作专属词、能够模拟三次回归。核心句裁决阶段只提交这一至两行的词组、主要重音、核心元音、气口和短 hook 提取方式；完整副歌的逐行韵脚地图、支撑句和回送方式留到用户确认核心句以后。不能把一条正确的功能说明加粗以后冒充金句，也不能反过来用完整乐段掩护普通核心句。非副歌驱动作品可以没有传统核心句，但必须明确由哪项标题词、refrain、旋律动机、问答或声音动作承担主记忆入口。

这里提交的是规划阶段的文字侧声音准入，不是声音定稿。核心句与完整副歌必须先排除自然词组断裂、明显塞字、重音失焦、韵脚毫无策略和没有意义气口等硬伤；全歌的暂定声音地图在完整初稿中统一建立，逐句文字侧调整在精修中完成，逐音节落拍和实际换气由谱曲、试唱与词曲回填决定。任何气口示例统一使用普通半角空格，不使用`|`、`｜`或斜线。

涉及曲式或预副歌时，先建立“信息序列”，不得直接套用段落名称：

```text
听众先看见的现场
→ 人物当时知道的事实
→ 哪项选择使关系不可逆
→ 哪项证据必须延后
→ 哪句 hook 需要回归，以及每次回归怎样变义
→ 结尾留下什么后果
```

然后至少比较两个真正不同的方案：一个可以不设预副歌，另一个可以设预副歌、尾句、冷开或其他结构。每个方案都要写出具体段落内容、hook 位置、重复收益、容量代价和失败方式。`主歌—预副歌—副歌—主歌—副歌—桥段—末副歌`只是排版结果，不是创作推理；不能先把故事塞进模板，再为每个段落补一个“作用”。

### 第四步：先完成整首初稿

按已经确认的标签序列和歌词雏形板，把全歌从开头到结尾一口气写完。先以整首歌的口吻、词场、声音和情绪运动为准，再嵌入锚点：硬锚尽量原样兑现；软锚妨碍人称、句法、韵脚、气口或连接时主动重写；方向说明必须重新变成人物会唱的话，不能复制管理员语言。

初稿采用“先整图、后整稿”，不是“分析一段、等待确认、再写一段”。先按正式顺序为每个已选乐段写一条创作结论：进入事实、主要职务、离开压力、与上一段和下一段的连接；然后在同一轮一次性写出全部歌词。没有选用的常见乐段不为完整感硬补，例如作品已经决定直达副歌，就不为填表添加固定预副歌。用户先看完整体以后，才进入整体审稿和逐段精修。

初稿不是把每轮讨论得到的一两句依次粘贴。必须补齐锚点之间的因果与声音，使主歌真的把人物逼进副歌，预副歌真的制造不可替代的门槛，桥段真的改变最后回归。若某个硬锚迫使其他段落凑材料或整歌换题，停止拼接，写明冲突和两种处理代价，回到用户裁决。

初稿先保证每个乐段都有必要内容、人物能走完全程、副歌有主要语言动作、桥段或结尾确实改变最后一次回归。只修正事实错误、人物越权、段落缺失和明显不可唱等致命问题；不要在第一主歌反复炼字、找完美韵脚和雕琢意象，导致后半首始终没有完整草稿。

完整初稿必须一次呈现全部乐段，并标出尚未解决的材料、结构与声音风险。只有局部试写时可以只交一段；局部试写不能改名为“第一版歌词”。

进入完整初稿以后，不再把主歌、预副歌、桥段和尾声分别交给用户审批。用户明确点名只改某一段，或某段会改变主矛盾、演唱对象、结尾选择和曲式身份时，才允许暂停整稿处理局部；普通的押韵、气口、画面和措辞问题记录为精修风险，不能让整首初稿永远缺席。

初稿末尾附一份简短继承回执：兑现了哪些硬锚；重写了哪些软锚及原因；哪些讨论结论没有进入正文；哪些问题必须留到逐段精修或真实旋律回填。回执属于审稿说明，不进入可唱正文。

### 第五步：先审整歌，再逐段精修

初稿完成后读取[改稿与交付验收](../../references/laohu-lyric-writing/改稿与交付验收.md)，先审作品总线、人物变化、信息顺序、段落职务和重复收益。宏观结构通过以后，才按主歌、预副歌、副歌、桥段和结尾逐项处理材料、视角、核心句、修辞、句法和字词。

逐段修改每完成一处，都要把它放回整首歌词检查：是否改变后文押韵、人物知识、核心意象、hook 回归或最后副歌。用户确认局部修改不等于整首歌词已经锁定。

### 第六步：按声音重写

初稿写完立即出声：朗读、按预想节拍拍读、哼唱或沿已有旋律试唱。逐句标出词组切分、意义重音、音乐落点、韵脚、长音和计划气口。读取[声音韵律与可唱性](../../references/laohu-lyric-writing/声音韵律与可唱性.md)。

面向用户或写进歌词正文的同一行气口只用普通半角空格表示。数字词组、重音、韵脚、长音和气口分析放在制作备注；禁止把竖线、斜线和标点塞进歌词正文充当换气指令。

按以下顺序重写，不得把歌词正文直接当成散文分行：

```text
先写人物会说的自然白话
→ 删除无职务的连接词、副词、语气词和重复说明
→ 恢复删除后丢失的主语、对象、时间、条件或必要语气
→ 按长句承载场景与因果、短句承载落点与重音的原则重组
→ 标注词组、句长、重音、韵脚、长音和气口
→ 朗读、拍读、哼唱或试唱
→ 只保留能同时通过语义、人物和声音检查的版本
```

长短句不得机械一长一短，也不得只按总字数裁齐。长句必须有内部词组、唯一主要重心和可执行的呼吸；短句必须有明确的对象、动作、判断或声音落点。副歌核心句、主记忆落点和重要句尾默认由实词承载；虚词只有在弱拍、衬腔、过渡或特定曲风中承担明确声音职务时保留。纸面顺畅、句子变短或尾字押韵，都不能替代实际出声验证。

### 第七步：只在需要时使用技巧

修辞必须替人物完成动作，不能替材料制造深度。需要比喻、比拟、对比、排比、设问、双关、通感、起兴、顶真、叠字、衬词等方法时读取[修辞与歌词技巧](../../references/laohu-lyric-writing/修辞与歌词技巧.md)。技巧名称不进入歌词，技巧数量不等于质量。

曲风、歌手、用途会改变句法密度、重复方式、韵脚精度、声音姿态和段落长度。涉及流行抒情、民谣、摇滚、说唱、R&B、K-pop、艺术歌曲、影视、儿童、品牌、行业、合唱、歌手定制或委约简报转译时读取[曲风用途与歌手适配](../../references/laohu-lyric-writing/曲风用途与歌手适配.md)。

### 第八步：最终反向审稿与歌词锁定

初稿完成后切换到编辑者，读取[改稿与交付验收](../../references/laohu-lyric-writing/改稿与交付验收.md)。先审命题和结构，再审段落，再审句子，最后审字和声音。上游错误没有修正前，不做表面润色。

反向审稿新增一轮总线回查：用普通话复述歌词实际写成的“谁因为哪件事，做了什么，最后失去了或改变了什么”，再与选题总线逐项对照。若只能靠作者解释才能说成同一件事，判为总线失配；如果歌词本身产生了更强的新命题，记录改变、收益、代价和需要重做的下游内容，回到选题确认后再保留。

用户确认完整歌词可以进入正式谱曲后，状态才改为`歌词已锁定`。锁定表示文字已经足以承担谱曲，不表示永久冻结；谱曲、试唱和 AI 生成暴露重音、长音、气口、倒字、音域或曲式问题时，状态改为`词曲回填中`，修改后重新经过本阶段验收。

正式交付前再读取[歌词稿格式与乐段标签](../../references/laohu-lyric-writing/歌词稿格式与乐段标签.md)，把审稿说明、制作备注和可唱正文分开。正文只保留已确认的英文方括号标签、歌词行和必要空行，不用 Markdown 中文标题、引号或标点替结构和人物关系打补丁。

## 5. 与其他 Skill 的边界

- `laohu-lyric-topic` 决定作品写谁、写什么、为何值得写、给谁听、用于哪里；本 Skill 接住已确认命题，完成歌词正文。
- `laohu-lyric-composing` 决定旋律、和声、节奏、曲式、编曲、音域和演唱设计；本 Skill 负责让文字能够进入这些音乐条件。词曲冲突时说明代价，回到共同目标裁决，不单方面把另一层当成固定容器。
- `laohu-lyric-title` 负责正式歌名。本 Skill 可以保留歌词内部的记忆词和工作标题，不替完整作品过早定名。
- `laohu-natural-dialogue` 负责把判断说给用户听。沟通层的分析句、路线标题、内部术语和顺口金句进入歌词前必须重新经过人物、声音和段落审查。

## 6. 直接淘汰的假歌词

出现以下任一项，停止局部润色，退回对应步骤：

- 把文章、故事梗概、观点说明或诗分行以后当歌词。
- 每段只把“我很痛、我想你、我要勇敢”换一组近义词，没有新事实和变化。
- 人称和角色随押韵切换，人物知道了自己不可能知道的事；对唱只是把同一份独白拆成两个人念。
- 把故事梗概按时间分行，事件很多却没有一件逼人物作出语言动作。
- 未讨论信息顺序、重复收益、hook 入口、时长和音乐条件，直接套用`主歌—预副歌—副歌—主歌—副歌—桥段—末副歌`。
- 上一轮只有故事大纲或中文段名，用户说“继续”便直接交完整歌词。
- 当前仍在副歌核心句裁决，用户说“继续”便交出带`[Chorus]`标签的四至八行完整副歌，跳过核心句确认。
- 正式歌词使用`**主歌 1**`、`**副歌**`、`尾声 / 最后副歌`等 Markdown 中文标题，不使用已确认的英文方括号标签。
- 依靠逗号、引号和作者说明区分人物原话、叙述层与气口；去掉标点后便不知道谁在说话。
- 把预副歌当成可随手补装的连接段，只说“托起副歌、把情绪顶上来”，却说不出删除后会损失哪项信息压力或声音对比。
- 为押韵改变事实、语法、人物口吻或核心意思。
- 句末押得很齐，句中词组、重音和气口一团乱。
- 把“简洁”理解成单纯少字，删掉主语、对象、条件或必要语气，留下只能靠作者解释的残句。
- 把“长短句交错”执行成机械一长一短，或只按总字数裁齐，未说明每句的信息、落点和呼吸职务。
- 为了核心韵脚和传播感，把无职务虚词或空泛近韵词放到重要落点，牺牲自然搭配和人物事实。
- 主歌只列物件，物件不改变人物行动、误解或代价。
- 主歌堆景、副歌喊道理；直抒只有情绪名词，没有对象和语言动作。
- 副歌只有大词、口号或管理员总结，没有人物语言动作。
- 因为作品写“求消息”，就把`音讯、实话、准信`锁成三层核心词；三个词只改变信息确定度，没有改变人物动作、关系代价、画面与声音。
- 副歌每行都在解释剧情、列条件或分派信息处理办法，没有逐行分配画面、感受、情绪、关系动作与回钩。
- 副歌继续用主歌的叙事口气交代地点、经历和任务，只靠升高音量与音高冒充情绪宣泄。
- 副歌没有情绪主色、反作用力、文字压力链和声音压力链，却用`痛、伤、绝望`或响亮开口音制造表面强度。
- 修辞需要作者解释，比喻框架互相打架，抽象名词替人物行动。
- 对标的物件群、问句地图、语义顺序、韵脚和结论成套保留。
- 曲风只换词库和表面口气，节奏、段落、声音姿态和演唱关系没有改变。
- 把委约简报、品牌口号或剧情梗概押韵分行，抽象要求没有转成人物、动作和可核验结果。
- 依曲填词只数总字数，不核对逐音时值、重拍、拖音、转音和换气。
- 初稿写完即交付，没有出声、冷读和逐层删改。

涉及结构分析时，以下答复也直接退回：

- 先宣布“适合加预副歌”，之后才用“把故事推到情绪、把副歌托起来”补解释。
- 只列段落名称和情绪标签，没有写听众每段新增的事实、重复句的变义和最后的行动后果。
- 把“故事很大、人物很多、需要高潮”当作曲式依据，却没有比较直达副歌、预副歌、回旋、冷开或通篇连续的具体损失。
- 把短视频开头的高潮前置误写成歌曲必须副歌前置；把音乐能量的变化误写成歌词已经发生了人物转折。

## 7. 交付标准

正式歌词至少同时满足：

```text
人物与关系清楚
→ 歌者、当面听众、话中对象和真正倾听者能够被复述
→ 主歌、副歌和结尾各自完成任务
→ 每次重复有记忆或变义收益
→ 第一耳能理解，第二遍能发现更多
→ 词组、重音、韵脚、元音和气口可执行
→ 关键句能唱、能记，且属于本作
→ 语言准确自然，修辞与意象有材料来源
→ 曲风、用途和歌手能够兑现
→ 与对标保持方法学习而非具体复刻
→ 经过朗读、拍读、哼唱或旋律试唱以及反向审稿
→ 曲式标签序列已经确认，正文格式符合目标平台
```

此外，歌词必须兑现选题总线：主歌提供总线要求的证据，副歌完成总线规定的语言动作，桥段或结尾落实总线规定的变化和代价。任何“歌词本身成立但讲了另一件事”的版本，都不得交付。

缺少旋律时，只能确认文字侧的可唱准备，不能宣称已经完成真实演唱验证；已有旋律或样唱时，必须按实际音频重新检查并允许回改歌词。

## 8. 理论来源与适用边界

本 Skill 的基础来自本地《歌词写作十八讲》第一、四至九、十一至十四和十八讲：歌词是供唱与听的音乐文学；语言要浅近自然；人称、演唱形式、材料章法、句式、段落和韵律必须共同考虑音乐；创作要经历创意、构思、初稿和修改；写词应唱着写、唱着改。教材中的市场、年代、性别气质和类型判断不作为永恒结论，只保留能经当代作品与制作验证的创作约束。

当代补充采用 Berklee Online 的 Pat Pattison 对 prosody 的公开阐述：歌词、旋律、和声、节奏、韵脚等元素应共同支持中心情绪与目的。此原则用于检查协同，不把他的英语押韵分类机械套到中文十三辙。中文听觉、词组和韵脚仍按普通话语音、具体曲风与实际演唱校准。
