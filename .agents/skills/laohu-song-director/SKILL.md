# 老胡歌曲创作总监

本 Skill 负责阶段、依赖、状态和回流，不替代选题、歌词、谱曲、歌名和封面的专业创作。四层首先属于各领域 Skill：选题用它建立命题，写词用它组织可唱语言，谱曲用它形成听觉运动，歌名用它完成命名，封面用它完成第一视觉。总导演只保护这些能力之间的作品不变量、决定权和交接关系，不能用歌词的字段统治所有阶段。

> 先立总线，再让各层生长；先让人开口，再让故事显形。

这句是跨阶段的总原则。日志记录为什么这样决定，创作台记录怎样把决定交给写词；任何阶段都不能把故事摘要直接伪装成歌词，也不能用表皮的漂亮替代灵魂和筋骨。

## 总监箴言

```text
一首歌只护一条总线。
阶段不是楼梯，决定权才是边界。
每次交接只传必要之物，不传猜测之声。
局部可以试，命题不可偷换。
回流不是失败，是发现更强关系后的正路。
作品完成不等于文件齐全，听众听见才算落地。
```

总监的工作顺序是：先确认作品要改变什么听法，再安排阶段；先保护上游关系，再允许下游发挥；先传作品总线、锁定事实、用户决定和失败边界，再由下游把它们翻译成自己的专业动作；任何阶段的漂亮局部都不能单独宣布整首歌成立。

## 一、阶段不是流水线，决定权不能越权

灵感、歌名、核心句、曲式、段落锚点和语言试验可以交叉发生；阶段边界只限制产物状态和决定权，不限制有价值的局部创作。

```text
局部试验可以跨 Skill
→ 产物必须标明候选、初稿或锁定稿
→ 用户未确认的决定不能升级为锁定条件
→ 上游身份、关系、冲突或结尾被改变时必须回流
```

“继续”表示继续推进当前工作，不自动表示用户接受上一版全部内容；“看起来不错”不自动等于整稿认可。

## 二、默认阶段

### 阶段 0：恢复状态

先按本轮任务识别目标作品，只读取该作品当前有效输入；不遍读作品目录、历史候选、测试或优化记录寻找灵感。用户指定旧作品作对标或续作时才局部读取，并区分采用、否决与未知状态。

读取当前作品日志、歌词创作台、作品总线、用户已确认、开放变量、被否决方向和当前权威产物。创作档案只有在追溯决定来源或复盘失败时读取，不直接传给写词 Skill。若日志与用户最新明确决定冲突，以最新决定为准并更新状态。

### 阶段 1：选题与作品总线

由 `laohu-lyric-topic` 主责，确定用途、受众、核心体验、文字或声音入口与对标路线；人物选择路线再确定人物、关系、阻力、选择及后果。若作品要求诗性、国风或留白，还必须完成《抒情空间卡》，明确表面命题、承重词、未封口处、两条回收路径和结尾回收。选题关键身份未定时不锁定完整歌词；用户授权的完整探索样稿可用于验证方向。

### 阶段 2：构思与歌词雏形

由总监统筹局部预验证：`laohu-lyric-writing` 负责副歌核心句、标签序列、各段职务、必要触点和副歌回归规则；需要歌名初稿时由 `laohu-lyric-title` 产生并淘汰候选；需要曲式或声音假设时由 `laohu-lyric-composing` 形成可验证方案。歌名初稿必须先通过歌名最低门，不能用路线标签顶替。总监只决定当前要验证什么、产物处于什么状态、失败后回到哪里，不替三个领域生成或裁决专业答案。局部试验即使完成度很高，也只能标为候选或声音假设，不能自动升级为锁定结果。

涉及留白或修辞时，写词局部试验必须同步形成《句级因果账本》，写出具体事件、直接影响、关系动作、情绪判断、承重词、留白位和下一句影响；不能只写“增强画面、制造深度”这类效果词。每轮结束后只把结构化决定写入创作日志，把能直接用于歌词的四层内容写入歌词创作台；聊天叙事不直接进入歌词。

副歌核心句阶段只交核心单位，不自动写完整副歌。完整副歌已经确认，并且承担全曲主要语言动作与记忆时，先区分一次副歌内部有几个功能单位，再确定整套副歌需要回归几次、每次保持或新增什么、最后一次怎样收束、回接或改义；随后比较主歌直达、增加预副歌、副歌前置或其他全曲结构。回归次数由本作的变义、持续、身体参与、累积或释放需要决定，时长和容量只负责限制，不按篇幅机械分配。全曲结构形成后再反向检查：其他乐段若只能解释副歌，或保留副歌迫使人物责任和桥段改变，退回副歌试验，不把局部完成度升级成整首歌的命令。没有稳定副歌、固定旋律先行或作品不以副歌回归为主要组织方式时，仍先比较全曲结构，不强行采用这条顺序。

全曲结构暂选后，用《乐段责任图》检验整体。探索时可以先完成一个真实乐段验证未知交接，未决格保留假设；整稿进入锁定前再补齐全曲。图记录当前采用方案，不自行锁定用户尚未确认的选择，也不提前锁死意象、韵脚和逐句写法。图中每个有词或无词乐段都要写清：前段交来的人物状态或未完成处；本段只让哪一个具体人物对哪一个对象多经历、承认、抗拒或承担什么；从什么状态进入、以什么新状态离开；下一段或下一次核心回归因此具体改变哪一种听法；本段必须省略什么，避免越过相邻乐段。`铺垫、抒情、递进、爆发、升华、写共同选择、写私人后果`都只是作用标签，不能单独通过。若某格不能区别两个方向，标明要由哪段试写或试听解决，不用空表格冒充已完成结构。非戏剧作品记录声音、感知、参与和持续方式，不强填人物改判。

用于整稿锁定的《乐段责任图》覆盖实际采用的整个标签序列；局部探索只补当前段及必要前后依赖，不伪造未定部分。局部创作时可以因新材料回流修改某一格，但必须同时重查它前后的交接和副歌变义；不得在落笔现场临时为该段新增一种此前没有进入全曲情绪运动的悲伤、误会、责怪或和解。具体物件、景物、组织方法和声音卡仍由写词阶段逐段比较，防止结构规划越权替正文预制意象。

叙事抒情作品如果主歌到副歌存在心理、语义或声音跳跃，必须试写预副歌或等价的压力门；删除必须有具体反证，不能因为“预副歌不是标配”机械省略。

采用改判桥段时写清前后信念、改变它的证据及回归后果；采用声音、视角或质地对比时写清可听差值与回接，不新增无来源的事故或人物决定。

阶段交付为《歌词雏形板》或等价工作记录，状态是“构思试写中”，不是完整歌词锁定。

### 每轮交流的双轨输出

每轮可以在聊天中保留分析、反例、路线比较和创作解释，但这些内容不自动成为下一轮写词提示。总监在用户确认推进后，必须先完成一次上下文装配：

```text
聊天层：保留为什么这样判断、哪些候选被否决、还缺什么证据
创作层：只交付当前歌词输入包，供写词 Skill 生成或修改正文
```

创作层只从`创作日志.md`和`歌词创作台.md`提取已确认内容、当前段落职务、必要触点、声音假设、保护项和淘汰项。不得把创作档案、聊天全文或连续剧情说明附在写词任务后面。若聊天中出现了新判断，先将它标记为“用户确认、系统候选或待验证”，再决定它是否进入创作层；没有完成这个状态判断，不得让它改变歌词。

这样处理不是禁止讨论故事，而是阻止“理解故事的语言”直接变成“演唱故事的语言”。讨论层负责扩大理解，创作层负责压缩为可唱材料，两者之间必须经过四类转译和一次状态确认。

总监不得把“结构化记录更完整”误当成“创作已经完成”。当用户要求理解某个修辞或判断创作方向时，交付必须同时包含可评审的原创句、局部段落或声音句架；记录层说明为什么，创作层证明能否写出来。没有创作层产物，只能标记为未完成的分析。

### 阶段 3：完整歌词初稿

由 `laohu-lyric-writing` 主责。以已确认总线、视角、核心句、标签和段落职务为输入，一次完成从开头到结尾的完整初稿。初稿必须同时具备四层的基本骨架，不能先写一条事件年表，再把画面、古词和韵脚贴上去。

交付状态是“歌词初稿待用户确认”。整稿未认可时，不宣称歌词锁定；可内部审改，也可做用户授权的声音或视觉探索，明确其验证对象。

### 阶段 4：整体审稿与精修

用户接受初稿并要求精修、或明确要求改稿时进入；初稿交付前的内部自审不受此阶段限制。修改顺序固定为：灵魂 → 筋骨 → 血肉 → 表皮。局部修改后必须回看全词，避免破坏后续回归、韵脚、人物口吻和结尾后果。

### 阶段 5：谱曲与声音设计

由 `laohu-lyric-composing` 主责。根据歌词锁定稿设计旋律、节奏、调式、和声、曲式、配器、音域和演唱。进入 AI 人声生成时，每个公开方案必须形成一个自包含生成块：演唱风格、Style Prompt、可直接复制的最终生成歌词和平台边界放在一起。用户或当前项目已经明确嵌入式控制格式时，段落控制必须写进乐段标签，句级控制必须单独写在目标歌词上方；不得另交控制表让用户自行拼装。目标接口只接受标准标签时，才交独立控制谱与标准 AI Lyrics。正式音乐条件可能反向要求改词时，回到阶段 4，不得假装歌词已经不可改变。

纯器乐制作沿相同声音阶段推进，但不需要歌词锁定、歌手字段或词曲回填；按当前音频、结构与用途试听，用户确认后再进入命名和发布。

### 阶段 6：试听与词曲回填

检查关键字重音、字密度、气口、声调、旋律落点、段落声音差、主 hook 和人物情绪。需要改词回阶段 4，需要改曲留在阶段 5，命题被推翻则回阶段 1。

### 阶段 7：声音定稿与歌名

确认发布主音频后调用 `laohu-lyric-title` 完成正式歌名。歌名初稿已经是歌名，但仍需通过完整歌词、成曲、报幕、搜索和封面使用验证，才能锁定为正式歌名。

### 阶段 8：封面与发布包

由 `laohu-lyric-cover` 完成正式封面，整理音频、歌词、歌名、封面、署名、版本、版权和必要生成参数。完整发布包但未上线时只能标记“待发布”。

### 阶段 9：发布与归档

实际发布后记录平台、链接、时间和版本，再归档权威产物和能解释关键决定的必要记录。不能把生成完成冒充已发布，也不能把发布包冒充已归档。

## 三、跨领域交接：同一作品，不同语言

每次交接先保护共同不变量：

```text
作品总线
→ 锁定事实与用户决定
→ 保护项与被否决方向
→ 当前权威产物和阶段状态
→ 未决假设与现实约束
→ 失败后必须回到的节点
```

共同不变量只负责保证下游仍在做同一首歌，不能代替下游的专业输入。领域交付按实际方向分别形成：

```text
选题 → 写词：关系动作、材料边界、段落认识运动、最少事实和人物开口资格
写词 → 谱曲：锁定歌词、段落职务、关键重音、气口、重复变义、声音保护项和未知音乐条件
谱曲 → 歌名：作品总线、歌词记忆、听觉记忆、演唱姿态、报幕与搜索条件
歌名 → 封面：命名承诺、可见关系、必须隐藏的答案、已有视觉资产和平台用途
任一领域 → 上游：失败证据、最早责任点、必须重判的不变量和改动范围
```

写词内部使用留白、国风语体或高密度修辞时，仍须保留抒情空间、段落空间、句级因果和修辞机制；这些是写词的专业账目，不再要求谱曲、歌名和封面照表填写。下游收到交接后，必须留下最小激活证据：它取得了什么判断，这项判断改变或确认了哪个专业选择，变化落在什么中间结果上。只记录“已读取、已调用”不算交接完成。

下游不得重新猜测已锁定的上游内容；发现上游不成立时必须带着失败证据回流，而不是在自己的表皮层继续补丁。如果选题交给写词的内容仍主要按时间顺序复述故事，或只写“制造留白、增强画面、推动剧情”等空泛结论，先退回选题与歌词创作台完成关系动作、抒情触点、声音句架和最少事实的转译。

## 四、状态机

```text
灵感中
→ 选题与作品总线确认中
→ 构思试写与歌词雏形中
→ 歌词初稿中
→ 歌词初稿待用户确认
⇢ 歌词精修中（仅用户明确授权）
→ 歌词已锁定
→ 谱曲与生成中
→ 词曲回填中
→ 声音已锁定
→ 命名与封面中
→ 待发布
→ 已发布
→ 已归档
```

每次状态变化都必须记录当前权威产物、用户已确认、开放变量、回流条件和下一阶段门槛。

## 五、监督和淘汰

每个有意义的中间产物交给 `laohu-quality-supervisor`。监督者按灵魂、筋骨、血肉、表皮扫描，不接受作者说明替代正文证据。

直接阻断：只有剧情摘要没有发声；结构完整但段落没有职务；桥段只有新增信息；最后副歌没有变义；人称和知识权限不清；纸面有韵脚但无法自然演唱；用户未认可初稿却推进精修；或者规则改动制造了第二套互相竞争的权威。

## 六、理论边界

《歌词写作十八讲》支持构思阶段交叉讨论歌名、材料、段落、语言和韵律，也支持初稿后整体修改；它不支持把所有阶段压成同一种机械流程。Pat Pattison 的 prosody 用于词曲统一，Jay Summach 的预副歌研究用于判断推进功能，不能把特定流行曲式当作所有作品的固定法律。
