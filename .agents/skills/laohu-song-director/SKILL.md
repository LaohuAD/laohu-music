# 老胡歌曲创作总监

本 Skill 对一首歌从灵感到归档的完整结果负责。它不替代选题、写词、谱曲、歌名和封面的专业能力；它负责决定当前处于哪一阶段、这一阶段必须交出什么、什么还不能锁定、何时调用哪个 Skill、何时必须回流。

## 阶段交付前的总监自审

每次阶段性答复、交接建议、路线裁决或作品状态更新，第一次写出的内容只能作为内部草稿。总监必须把候选交给 `laohu-quality-supervisor` 做全维度扫描，不能只检查上轮已经暴露的那个问题。监督至少覆盖任务阶段、作品总线、事实材料、人物视角、信息顺序、下游依赖、专业性、传播和格式；总监再根据责任归属决定返工或回流。

发现命题、人物、冲突、信息顺序或阶段状态错误时，必须回到最早责任节点修正，不能在交接话术里把错误包装成“下一步再优化”。发现只有措辞问题才进入下游精修；发现用户材料不足但当前判断仍可推进，交付最强暂定方案并标明改判条件。阶段自审通过只表示内部交付门通过，不表示已经完成试唱、成曲、陌生听众或发布验证。

## 一、默认主线不是唯一创作法

V4 默认采用先词后曲的依赖顺序：

```text
灵感种子
→ 故事与情感简报
→ 构思试写与歌词雏形
→ 歌词完整初稿
→ 歌词整体审稿与逐段精修
→ 歌词锁定
→ 谱曲、编曲、演唱与生成
→ 词曲回填与声音锁定
→ 正式歌名与封面
→ 发布、完成状态与归档
```

这条主线适合用户先有故事、人物、文字或对标的任务，不是歌曲创作唯一合法顺序。《歌词写作十八讲》明确区分先作词后谱曲与先作曲后填词；已有旋律、伴奏、节拍、topline 或成曲时，从相应阶段进入，再补影响当前结果的最小上游判断。

不得为了流程整齐，要求已有成熟旋律的用户重新从空白灵感开始；也不得因为用户已经有一段副歌或一个歌名，就假装整首作品的故事、曲式和情感运动已经成立。

## 二、六组名称必须分开

流程中最容易出错的不是漏步骤，而是把不同成熟度的产物叫成同一件事：

| 早期产物 | 后期产物 | 边界 |
| --- | --- | --- |
| 灵感或故事梗概 | 作品总线与创作简报 | 梗概说发生什么；总线说明为什么值得唱、人物如何变化 |
| 路线标签 | 工作歌名 | 路线标签方便讨论；工作歌名暂时集中作品材料 |
| 工作歌名 | 正式歌名 | 正式歌名必须经完整歌词和近最终成曲反证 |
| 副歌核心问题或语言动作 | 副歌核心句 | 前者规定人物要完成什么；后者才是经过写词与声音验证的具体文字 |
| 歌词信息结构 | 音乐曲式 | 前者决定事实、hook 与重复顺序；后者还受旋律、和声、速度、时长和歌手限制 |
| 情绪曲线 | 音乐能量曲线 | 前者写人物怎样变化；后者写声音怎样让这种变化被听见 |

灵感阶段可以提出工作歌名、hook 候选、曲风和曲式假设，但必须标明状态。候选不能因为出现得早便获得正式地位。

成熟状态不是创作开关。某项产物尚未定稿，只表示它以后必须接受更多反证，不表示现在只能讨论“方向”。总监一旦决定借用下游能力验证当前阶段，就必须让该能力完成一次真实创作循环并返回可比较产物；总监负责给它标明状态、记录风险和决定是否采纳，不得把`未锁定`误写成`不创作`。

## 三、默认十阶段

### 阶段 0：接收灵感与恢复状态

先判断输入属于一句灵感、完整故事、对标歌词、已有歌词、已有旋律、已有伴奏、AI 样歌还是既有成曲。已有作品目录时读取`创作日志.md`和当前权威文件，确认最新用户决定、当前阶段、锁定项和开放项。

交付：本轮真实入口、当前阶段和下一道决定性门槛。不得用固定问卷重走用户已经完成的工作。

### 阶段 1：讲清故事、感情与作品任务

由 `laohu-lyric-topic` 主责。故事背景可以完整，但必须继续压成歌曲需要的关系和情绪因果：

```text
谁在什么时代、地点和关系里
→ 此刻发生哪件触发事件
→ 人物原本想得到或保住什么
→ 哪项现实阻力使普通办法失效
→ 人物怎样理解这件事
→ 因此产生什么情绪、身体反应、防御和行动
→ 事件引出什么认识、疑问或价值冲突
→ 人物最后必须亲手做什么
→ 这首歌为谁、在什么场景、完成什么现实任务
```

这里的“故事讲清楚”不是把所有经历都准备塞进歌词，而是建立一个足够完整的故事母体，再挑出歌词真正需要的关系证据。

阶段交付：《作品总线卡》《歌词创作命题》《故事与情感简报》。核心人物、演唱对象、当前场景、主矛盾、情绪因果、结尾方向、用途和不可降级资产必须经用户确认。

### 阶段 2：构思、试写与形成歌词雏形

选题、写词、谱曲和歌名能力按需协作，但仍由本 Skill 统筹。进入完整歌词前必须讨论并标明以下内容的成熟状态：

- 工作歌名：用于集中材料，不冒充正式发行名。
- 副歌语言动作：人物在副歌要承认、质问、请求、命名还是决定什么。
- hook 候选：副歌驱动作品在完整初稿前必须选出一条通过人物、关系、第一耳、作品归属、记忆机制和三次回归模拟的主核心句候选，并确定短 hook；它仍须经过整歌与真实声音复核，不得提前标为最终核心句。
- 演唱视角：谁唱给谁，第一、第二、第三人称或多角色怎样分配。
- 曲风与声音参考：它怎样改变语言密度、节奏、演唱和受众，不只列风格标签。
- 歌词信息结构：事实、悬念、重复和结尾按什么顺序被听见。
- 暂定音乐曲式：使用 `[verse]`、`[chorus]` 等标签展示；无旋律时写明待验证条件。
- 情感基调与情绪曲线：人物每段相信什么、感受什么、采取什么动作。
- 音乐能量假设：哪里收、哪里放、哪里留白；未谱曲时不得写成已确定事实。
- 目标时长、歌手、用途、平台和版权等现实约束。

本阶段模拟真实创作者从片言只语逐渐形成初稿准备的过程，不按表格顺序机械推进。歌名、核心句、主歌画面、预副歌转折、曲式、节奏型或结尾句可以先后交叉出现；任何有价值的局部灵感都先记下，再放回作品总线、人物视角、段落运动和声音条件中验证。阶段门槛只要求它们最终咬合，不要求灵感按流水线到达。

默认采用以下循环，次序可跳转但任务不能缺失：

```text
讲清故事母体与中心情感
→ 用人物粗话确定副歌最必须说什么
→ 生成并淘汰核心句与短 hook
→ 对外只交一至两行核心单位并由用户裁决
→ 核心句确认后再放进四至八行副歌试验
→ 反推主歌必须提供哪些场景与证据
→ 判断是否需要预副歌，以及它缺少哪一道压力
→ 试写关键乐段的一至两句锚点
→ 设计第二次与最后一次副歌怎样变体
→ 比较曲式和声音假设
→ 回看整首歌是否仍在完成同一条总线
```

仍处在本阶段时，每轮讨论只集中解决一个最会改变作品身份的问题，但必须留下可积累的结果：一项明确裁决、一段真实试写、一个被保留或淘汰的理由，以及它怎样改变其他乐段。不能每轮重新解释故事，也不能讨论完副歌以后在写完整初稿时把全部结论丢掉重新生成。

这条局部聚焦规则只属于构思试写，不得延长到完整初稿。对于副歌驱动作品，当作品总线、演唱视角、标签序列、主核心句、第一次完整副歌以及后续副歌怎样变义已经足以决定作品身份，未完成的主歌、连接、桥段和尾声默认作为初稿要解决的创作任务，不再逐项设置用户审批门。它们只有在会改变主矛盾、人物选择、结尾方向、演唱对象或曲式身份时，才退回本阶段单独裁决。

构思阶段仍要为核心句和完整副歌完成文字侧声音准入：自然词组、句长风险、主要重音、韵脚策略、意义气口和主声音机制至少有一版可执行假设。这里的目的只是防止把天生拗口的硬锚带进全歌，不追求逐字落拍和真实换气锁定。全歌的暂定声音地图在阶段 3 建立，文字侧精修在阶段 4 完成，真实旋律与歌手条件下的最终落位留给阶段 6；不得把四层工作挤在规划阶段一次做死，也不得全部推迟到精修才第一次处理。

讨论结果统一沉淀为《歌词雏形板》，纳入《写词前创作简报》，不额外制造版本文件：

```text
作品总线与当前演唱视角
→ 工作歌名与状态
→ 暂定标签序列和每段职务
→ 主核心句、短 hook、当前成熟状态；确认核心句后再记录完整副歌试验
→ 每次副歌回归前新增什么，以及哪一两处需要变词
→ 各乐段的进入事实、新增内容、离开压力和一至两句锚点
→ 主歌怎样引出副歌；预副歌存在或删除的证据
→ 已确认硬锚、可改软锚、被淘汰句和仍待验证项
→ 词组、韵脚、重音、气口和音乐能量的暂定假设
```

不是每个乐段都必须硬写一句漂亮话。没有合格句时保留清楚的段落事实和语言任务，不能为了填满雏形板制造低质量歌词。锚点句只有在它实际验证了人物、关系、声音或段落连接时才保留。

阶段交付：《写词前创作简报》《歌词雏形板》、已确认的标签序列，以及副歌驱动作品已经逐步确认的主核心句、短 hook、完整副歌试验与失败风险。这里的“逐步确认”不能压成一次交付：先裁决一至两行核心单位；用户确认核心句或明确要求进入副歌乐段后，才写完整副歌试验。没有完成结构比较、视角、段落连接和主 hook 验收，用户只说“继续”时仍留在本阶段；这些决定已经足以支撑完整初稿时，用户说“继续”必须进入阶段 3，不能再发明桥段、尾声或每一段主歌的独立确认门。非副歌驱动、分节歌或通篇连续作品必须另行说明主记忆入口，不为满足流程硬造核心句。

其中`副歌语言动作`只是输入，不能冒充`主核心句候选`。当用户要求确定副歌核心、否决现有核心句或指出它不触达时，本阶段必须调用 `laohu-lyric-writing` 与[副歌核心句与传播记忆](../../references/laohu-lyric-writing/副歌核心句与传播记忆.md)，内部完成候选生成、编辑淘汰、声音假设和三次回归模拟；对外只交付一至两行胜出核心单位、可提取的短 hook、主要声音判断，以及最强失败候选为何被砍。若没有候选通过，也要给出真实写过的最强失败稿和失败证据；禁止只把`在戏里留空位、围绕接唱写、用停顿等消息`作为本轮成果。核心句未经用户确认时，不得加`[Chorus]`标签或扩写四至八行支撑句；确认以后再把完整副歌作为下一项独立变量解决。

主核心句候选尚未产生时，不继续用更多结构、意象和剧情分析掩盖缺口。结构可以并行试验，但下一次对用户的核心交付必须先解决已经点名的核心句问题。

### 阶段 3：完成歌词完整初稿

由 `laohu-lyric-writing` 主责。以《歌词雏形板》为直接输入，不重新猜故事、曲式、核心句和各段职务。先区分用户确认的硬锚、允许重写的软锚和只供理解的方向说明，再把全部已确认乐段一口气写完整，保证人物、事实、段落职务和主要语言动作能够从头走到结尾。

初稿在同一轮内按两层交付，不按乐段暂停等待确认：先用一份顺序段落图说明每段从什么事实进入、完成什么、怎样把压力交给下一段；随后一次呈现带正式标签的完整歌词。段落图负责让用户看见整体推理，歌词正文负责让用户听见整体作品。写到主歌、连接或桥段时发现普通软锚不够好，直接在总线和硬锚范围内重写并在回执说明；只有发现身份级冲突才停止整稿并退回用户裁决。

完整初稿不是把零散锚点按顺序粘起来。写词者必须统一人称、语气、词场、句长、韵脚、声音密度和段落连接；软锚妨碍整歌时主动重写，硬锚妨碍整歌时指出冲突并回到用户确认。完成后逐项回查雏形板：哪些讨论成果被兑现，哪些因整体需要被改写，哪些开放项仍需后续精修。

完整初稿必须建立整首歌的暂定声音秩序：每个乐段的句长层级、自然词组、主韵与换韵、重音、意义气口，以及主歌、副歌和桥段之间的声音差。它不要求逐字音高和真实换气已经锁定，但不能只交语义正确的分行文字，再把全部节奏和可唱性留给精修或谱曲。

初稿阶段只修会让整首歌无法成立的错误，不在第一主歌上反复炼字到忘记后面的歌。

阶段交付：一份从开头到结尾完整、使用正式乐段标签的歌词初稿，以及初稿仍未解决的结构、声音和材料风险。

### 阶段 4：整体审稿后逐段精修

仍由 `laohu-lyric-writing` 主责。修改顺序固定从大到小：

```text
作品总线与人物
→ 整歌运动与曲式信息结构
→ 每个乐段的职务和新增事实
→ 演唱视角与角色权限
→ 副歌核心句、hook 与重复变义
→ 意象、修辞与词场
→ 句法、用字、用词和韵脚
→ 词组、重音、节奏、音律、气口和听觉歧义
→ 正式歌词格式
```

用户提出逐段修改时，每次改动必须回看全词。不能把局部句子改漂亮，却破坏后文押韵、人物口吻、核心意象或最后副歌。

阶段交付：用户确认的“歌词锁定稿”。锁定表示它已经足以进入正式谱曲，不表示以后禁止为旋律和演唱回改。

### 阶段 5：谱曲与声音设计

由 `laohu-lyric-composing` 主责。根据歌词锁定稿设计旋律动机、速度、节奏、拍号、调式、和声、音乐曲式、段落能量、配器、编曲、音域、演唱和声音参考。

写词前讨论的曲式只是约束与假设。正式谱曲发现预副歌多余、核心句需要提前、桥段容量不够或某行无法自然落音时，提出具体改判依据，不得默默改变歌词结构。

阶段交付：可执行的谱曲与声音方案，或可试听的 demo / AI 生成版本。

### 阶段 6：生成试听与词曲回填

谱曲主责，写词辅助。任何第一版 demo、AI 生成或真人试唱都必须回查：

- 关键字是否落在正确重音、长音和音域位置。
- 句长和气口是否逼歌手在错误位置换气。
- 韵脚、声调和旋律是否造成误听或倒字。
- 主歌、副歌、桥段是否真正形成声音区别。
- 主 hook 是否成为听众实际记住的入口。
- 音乐是否改写了原定情绪曲线、人物责任或结尾判断。

需要改词时回到阶段 4；需要改结构、旋律或制作时留在阶段 5；发现整首歌命题被声音推翻时回到阶段 1。词曲回填没有完成，不得把“已经谱曲”写成“作品完成”。

阶段交付：词曲锁定稿、最终段落结构、确认歌词、确认演唱与近最终音频。

### 阶段 7：声音定稿与发布身份

完成必要的编曲、演唱、编辑、混音、母带或 AI 音频筛选，确认当前音频是发布主版本。随后调用 `laohu-lyric-title` 正式命名：工作歌名可以保留，也可以被歌词和声音推翻。

正式歌名必须同时经过完整歌词、主 hook、成曲重音、口头报幕、搜索与封面使用验证。没有近最终音频时可以给强候选，不能假装已经完成最终命名。

阶段交付：发布主音频与正式歌名。

### 阶段 8：封面与发布包

由 `laohu-lyric-cover` 完成正式封面。封面探索可以提前，正式封面必须以发布主音频、正式歌名、平台画幅和作品总线为准。

同时整理发布包：最终音频、最终歌词、正式歌名、封面、创作者与演唱者署名、版本号、平台说明、版权与素材授权、必要的生成参数或工程说明。缺少实际需要的权利和署名信息，不得只凭封面完成便进入发布。

阶段交付：发布就绪包，状态记为`待发布`，不是`已发布`。

### 阶段 9：发布、完成与归档

实际发布前做最后一致性检查：音频、歌词、歌名、封面、署名、版本和平台描述是否属于同一作品。实际发布成功后记录平台、链接、时间和最终版本，状态改为`已发布`。

归档只保存权威产物和能解释关键决定的必要记录：

```text
创作日志
最终歌词
发布主音频与必要工程
正式歌名裁决
最终封面与发布尺寸
署名、版本、授权和发布信息
必要的生成参数与可复现设置
```

讨论流水、被淘汰的普通候选和没有复盘价值的中间文件不进入长期归档。发布包完整但尚未上线，可标`制作完成 / 待发布`；只有实际上线才标`已发布`。归档完成后标`已归档`，不能用一个`已完成`掩盖发布与归档是否真实发生。

## 四、状态机

每部正式作品只保留一个当前状态：

```text
灵感中
→ 选题与故事确认中
→ 构思试写与歌词雏形中
→ 歌词初稿中
→ 歌词精修中
→ 歌词已锁定
→ 谱曲与生成中
→ 词曲回填中
→ 声音已锁定
→ 命名与封面中
→ 待发布
→ 已发布
→ 已归档
```

`创作日志.md`至少记录：当前状态、当前权威产物、用户已确认、开放变量、被否决方向、待回填问题、下一阶段门槛和最近一次回流原因。最新用户决定高于旧日志；改变状态时更新日志，不保存聊天流水账。

## 五、阶段交接规则

进入下一阶段必须同时满足：

1. 当前阶段的核心交付已经存在。
2. 用户已经确认会改变作品身份的决定。
3. 下一阶段依赖的信息完整。
4. 剩余开放项不会立即推翻下一阶段。
5. 已锁定、待验证、禁止改变和回流条件能够被复述。

局部试验可以跨阶段，阶段所有权不能偷换。选题阶段试写两句副歌不等于进入完整写词；写词阶段哼唱不等于完成谱曲；封面草图不等于正式视觉已经确定。

“不等于进入下一阶段”只决定状态，不构成降低试验质量的理由。局部试验必须足够完整，能让当前阶段据此作出保留、淘汰或回流判断；只描述未来要写什么，没有实际句子、名称、声音或画面可评审，不算局部试验。

## 六、非标准入口

- **先曲后词**：先由谱曲 Skill还原旋律、节奏、曲式、情绪与字数约束，再由选题确定相容的人物和命题，进入依曲填词。
- **伴奏或 beat 先行**：先确定律动、段落循环、声线和 topline 空间，再建立故事与语言动作。
- **歌名先行**：把名称当题目假设，不能把它当正式歌名；作品不兑现时放弃名字。
- **副歌句先行**：把句子当局部试验，检查人物、对象、声音和可展开性；不能围着一句漂亮话硬编整首歌。
- **已有歌词**：逆向还原总线，判断需要改词、谱曲、命名还是发布，不重走已完成阶段。
- **已有成曲**：先诊断词曲、演唱、制作与发布身份，再决定回流或进入正式命名和封面。
- **委约任务**：先锁定硬条件、审批对象、权利与交付，再按最接近的入口推进。

## 七、直接淘汰

- 把完整故事背景直接分行当歌词。
- 灵感刚出现便同时锁死正式歌名、最终副歌句和音乐曲式。
- 只写第一主歌便开始逐字精修，整首歌词始终没有完整初稿。
- 总线、视角、标签结构和副歌骨架已经足以进入初稿，用户说“继续”后仍只写桥段、尾声或下一段主歌，并要求逐项确认。
- 把歌词信息结构称作最终音乐曲式，或把情绪曲线称作已经完成的编曲能量。
- 歌词定稿后谱曲，发现重音、气口和句长问题却拒绝回填。
- AI 第一版完整好听便直接进入封面，没有词曲、结构和主 hook 回查。
- 封面探索稿先行，反过来要求歌名、歌词和成曲迁就一张漂亮图。
- 发布包未完整或实际未上线便标记`已发布`；没有归档权威文件便标记`已归档`。
- 为了遵守顺序，要求先曲作品重新走一遍先词流程。

## 八、理论依据与边界

《歌词写作十八讲》第九讲把歌词创作写成创意、构思、初稿、修改与定稿，明确构思会同时考虑主题、材料、角度、段落、语言风格和韵律，实际思考不必按顺序进行；写初稿则是“从片言只语开始，逐渐丰富展开”，并强调“唱着构思、唱着下笔、唱着修改”。第十二讲说明歌名可以先取、后取或交叉进行；第十三讲明确歌曲既可先词后曲，也可先曲后填词；第十四讲要求修改从主题、结构、语言、风格和可唱性逐层进行。V4据此采用默认依赖、交叉构思、歌词雏形和整体初稿，而不是把一种个人工作习惯写成固定流水线。

Pat Pattison 的 prosody 原则用于校准词、旋律、和声、节奏与表演必须共同服务同一中心情绪与目的。因此“歌词锁定”与“词曲锁定”分成两个状态：前者允许进入谱曲，后者才表示歌词已经经受真实声音反证。
