# 声音提示词与外部生成方法

本文件服务 `laohu_sound`。当前阶段交付生成假设，不在项目内部生成或假装试听音频。

## 1. 声音从歌词和听众用途推出

曲风、BPM、乐器和唱法不是题材匹配表。先判断：

```text
听众在什么场景使用作品
第一耳注意什么
身体脉冲怎样进入
Verse怎样保持人物距离
Pre怎样制造期待
Chorus靠什么兑现记忆
Bridge怎样改变听觉视角
Final为什么值得再次出现
```

再选择音乐语言。轻甜不自动等于木吉他和铃铛，悲伤不自动等于钢琴弦乐，都市不自动等于R&B。

## 2. 声音方向选择

每个宏观方向必须是完整主张，不是曲风购物单：

- 目标听众与使用场景。
- 主唱年龄感、音区、距离和声口。
- 3-7秒最高记忆单元。
- 主旋律或节奏轮廓。
- groove与身体感。
- 和声主要色彩。
- 核心配器职责。
- 乐段动态差异。
- 最大生成风险。

提供2-3个方向，差异来自人物身体、记忆机制或形式因果，不只换曲风标签。

用户原则上选择完整方向。只有AI证明维度兼容时才允许组合，防止旋律、groove、和声、音色和制作动作同时争当中心。

## 3. 一个最高记忆中心

听众常把同时发生且互相解释的线索记成一个动作。最高记忆单元可以由1-3个相互依赖组件组成，例如：

```text
一个词的重音
+ 对应节奏细胞
+ 旋律方向
+ 伴奏让位
```

必须指定主要组件，其余只强化它。删除辅助组件可以减弱身份，但不能露出另一个平级Hook。

反事实：

- 去掉曲风标签，人物与主记忆是否仍清楚。
- 换成通用情绪歌手，是否几乎无损。
- 把副歌只改成更高、更响、更宽，是否足以解释记忆；若足以，原方案可能没有真实机制。
- 把歌词换成同题材另一首，声音是否几乎无损套用。

## 4. 主唱身份（仅人声歌曲）

主唱决定人物是否可信。需要具体到：

- 年龄感和关系阶段。
- 舒适音区与高点用途。
- 音色、共鸣和起音。
- Verse、Chorus、Bridge、Final的距离变化。
- 关系判词、数字、称呼和核心韵的咬字。
- 装饰音、气声、belt和尾音边界。

人物敏感不等于全程气声，强烈不等于持续吼唱，年轻不等于幼态撒娇。男方未知时不得用男声、回应和声或确认式旋律替关系作答。

## 5. 词曲对齐（仅人声歌曲）

声音阶段读取锁定歌词、核心句、承重词和基本节奏假设。逐句决定：

- 一行是否拆成两乐句或与下一行连接。
- 起拍位置、音节密度、休止和延音。
- 普通话实义重音和声调风险。
- 哪个尾字允许长音。
- 哪些乐器在密集信息和主Hook处让位。

不得把歌词文件每行机械映射成同长度旋律句。相邻且职责不同的乐段，至少在乐句长度、起拍、休止、尾音或重复方式中形成真实差异。

## 6. 四类声音职责

### 旋律

提供可召回轮廓、词义重音和乐段期待。高音只给真正承重的词，不把所有副歌做成音区扩大。

### Groove

提供身体位置、前倾、迟疑、推动或释放。节奏变化必须来自人物动作和听众用途，不由曲风标签自动决定。

### 和声

改变期待、稳定、悬置和颜色。借用和弦或复杂和声必须有局部职责，不能把爱情萌芽整体染成失恋，也不能用持续甜色替未知关系作答。

### 编曲

明确每个声部何时进入、退出和让位。主Hook出现时，同频强乐器、复杂填充和多人声不能遮住关键字。Final不以全部声部同时加码证明重要。

### BPM不等于groove

BPM只说明单位时间内有多少拍，不能单独决定身体感。真正的groove还来自重拍位置、鼓贝咬合、前后拍倾向、切分、摇摆比例、人声落点、riff与空拍。两首同为90 BPM的歌，可以一个向前催、一个向后靠、一个悬着不落。

声音方向必须先说清人物和听众需要怎样的身体动作，再让鼓、bass、人声、riff和停顿形成同一个pocket。外部结果若“速度差不多但就是不对”，不能只改BPM；先判断这些组件是否各走各的，以及密集中文有没有得到让位。

### 四条声音变化曲线

完整歌曲至少同时观察四条随时间变化的曲线：

```text
旋律曲线：音区、句形、重复、悬置和高点怎样变化
节奏密度：字数、切分、停顿、鼓组推动和留白怎样变化
编曲曲线：声部何时进入、退出、加厚、抽空和让位
人声表演：距离、音色、力度、咬字、气声、尾音和即兴怎样变化
```

每个乐段只需要一条主要变化、必要辅助变化和保持稳定的身份线索，不要求四条同时加码。退出、抽空、突然靠近或变干也能增加压力。Final只选择一个主要增重动作，其余服务它，避免所有元素一起变大。

### 普通话发声风险

无具体旋律时只能建立可验证假设，不能声称已经完成逐字谱曲。重点预警：实义重音是否可能落在强位，声调与旋律方向是否造成难懂风险，长音或高点是否有足够母音空间，连续辅音和闭口尾是否增加咬字阻力，数字、专名和关系判词是否被切碎。

开口母音不自动优于闭口音。长音需要母音展开，短促态度句可以利用辅音收口；选择必须服务词义、人物和旋律动作。真正成立仍需外部生成或真人试唱验证。

### 开场和结尾由使用窗口决定

前奏长度由第一句价值、人物进入方式和主要使用场景决定。需要快速对话、态度或冲突时可以拿起来就唱；需要建立声音世界时，短动机、groove或空间必须提供后文会兑现的信息，不能因为慢歌就默认长前奏。

结尾保护最后一句的实际作用。笑点、拒绝、决定和传播落点通常需要短收或戛停；余韵型作品可以保留器乐、和声或呼吸，但不能用无目的长尾稀释已经落下的意义。

## 7. Style Prompt

Style Prompt只保留外部生成平台可能执行的正向声音信息：

- 流派与必要融合方向。
- 速度、拍号、律动和groove。
- 人声歌曲的主唱身份、音色、距离和唱法；纯音乐的主题动机与器乐形式。
- 最高主记忆。
- 核心乐器、职责和声场。
- 乐段主要动态。
- 结尾方式。

删除：创作解释、营销口号、抽象高级词、互相冲突标签、禁止清单和无法执行的导演散文。内部精确蓝图可以更详细，但不能全部挤进正式Style Prompt。

## 8. Controlled Lyrics（仅人声歌曲）

Controlled Lyrics必须：

- 剥离控制后与锁定歌词逐字符一致。
- 使用标准乐段标签。
- 只在主Hook、角色变化、必要停顿、和声、动态或结尾添加少量控制。
- 不增加解释性台词。
- 不逐行控制到平台机械执行。

未知平台可能误唱行控时，提供最小标签降级：先删除行级控制，再缩减为标准乐段标签；任何降级不得改歌词。

## 9. 外部音频反馈

同一提示词版本可以生成多个外部音频，每个结果必须登记 `audio_run_id` 并关联 `prompt_revision_id`。多个随机结果有助于区分提示词问题与平台随机性，不能把一个偶然结果直接晋级成规则。

真实音频回来以后，先描述可观察结果，不立即增加提示词：

```text
听见了什么
预期是什么
差异发生在哪个词、乐段、声音或结构
最可能属于平台未遵从、提示词冲突、声音方向、歌词、歌手音区还是个人偏好
最早能改变结果的字段是什么
```

修改优先级：

```text
修字段冲突或解析问题
→ 修主唱/旋律/groove/和声/编曲中的根因
→ 必要时重新选择声音方向
→ 若必须改歌词，申请解锁
```

用户文字感受始终可以驱动诊断。若当前环境具备音频工具，可以补充时长、响度、频谱、节奏、音高和结构等技术证据；工具能力不能自动等于人类审美听感，必须声明当前是 `user_text_only`、`tool_assisted_audio` 还是 `both`。

每个反馈周期只进行一组定向修改，生成新的 `prompt_revision_id` 后再次外部生成。一组不等于一个字段：鼓组密度、bass让位和人声切分可以在“为密集中文腾出空间”的同一根因下联动，但不同时另改主唱人格和最高记忆。

修订记录不只保存改了什么，还必须保存本轮不应被破坏的已成立资产，以及下一次生成中能被真实反驳的预期。这两项防止系统只追着问题跑，一轮解决鼓点却丢掉上一轮已经成立的人声距离。

用户可以进行多轮循环；没有新音频或新反馈时不继续凭文字猜测。同一根因跨多轮仍复发时，返回声音方向、平台限制或歌词权限层，不继续堆标签。只有用户接受当前提示词版本才结束循环；暂停和接受必须分开。

“克制、温暖、松弛、亲密”是方向，不等于全程低音区、低动态和同一距离。若外部结果把人物的委屈、迟疑、抢话或Final决定全部修平，先恢复内部压力和曲线差异，不要直接改成全程更高、更响、更用力。修复目标是保留复杂情绪的运动，不是在平淡与喊叫之间二选一。

## 10. 完成与诚实边界

声音包完成条件：

- 一个清楚声音主张和最高记忆中心。
- 人声歌曲的主唱、歌词、旋律、groove、和声和编曲同因果；纯音乐的用途、主题动机、形式、groove、和声、配器和音色同因果。
- Style Prompt正向集中。
- 人声歌曲的Controlled Lyrics逐字符一致且控制稀疏；纯音乐的Instrumental Form与方向一致。
- 平台未知风险和降级方式明确。
- 没有把预期听感写成事实。

完成只表示可以交给外部平台生成，不表示音频、演唱、传播或发行已经成立。

## 11. 纯音乐分支

纯音乐不是删除歌词和主唱的人声歌。它仍从听众用途出发，但由主题动机、身体脉冲、张力与释放、器乐形式、配器和音色承担人物语言原本承担的身份。

先确定一个最高主题动机家族：旋律动机、节奏细胞、groove、和声转折或音色签名中的一种作为主要组件，其他声音只强化它。随后建立 `Instrumental Form`：每个实际段落说明动机当前状态、主要变化曲线、groove/和声职责、配器进入退出、转场、高潮或非高潮策略和结尾。不能只列乐器，也不能用Verse/Chorus标签假装形式已经变化。

纯音乐不执行人物称呼、歌词锁、中文咬字、主韵和Controlled Lyrics逐字符规则；仍执行听众用途、反平均化、唯一主记忆、BPM/groove区分、四条变化曲线、平台可执行、完整回装、外部音频反馈和诚实边界。

## 12. 音乐片段的中间入口

用户已经拥有的旋律、节奏细胞、groove、riff、和声、主题动机、演唱动作或局部编曲，是上游资产，不是重新选曲风时可以丢弃的参考意见。先确认它在上下文中承担什么、哪些维度锁定、哪些维度开放，以及用户只要炼片段还是发展完整包。

只炼片段时，修改范围停在开放维度，并回测必要歌词、主题动机或器乐形式后交付；局部成立不等于完整作品成立。发展完整包时，片段进入声音方向的保护资产，其他旋律、groove、和声、音色和编曲围绕它建立同一主记忆，不能另起平级中心。

自然语言描述适合早期探索；要把片段称为可复核的炼制结果，应按实际种类使用级数、音程轮廓、节奏格、和声功能、罗马数字或段落图之一。结构化表达证明信息明确，不证明音频已经好听；真实效果仍由外部生成或试奏验证。
