# 音乐创作阶段交接合约

本文件规定老胡音乐项目正式制作阶段的输入、输出、确认门和下一阶段交接字段。

## 0.0 使用边界：统一创作链，不把轻创作当草稿授权

本文件只在统一创作链进入正式生产后完整启用。老胡还在聊灵感、筛方向、看一句副歌有没有感觉、测试基础作词水平时，默认处在轻阶段：输入状态还轻，核心字段未确认，所以先探索确认，不要把本文件里的交接字段提前压到对话第一屏，也不要用“方向草稿”名义直接输出完整歌词。

轻不是低质量，不是快速简化；轻 = 输入状态轻。重不是另一条路；重 = 同一条链进入内容深度更重的正式生产。统一创作链如下：

```text
模糊灵感
→ 输入识别
→ 探索确认
→ 方向论证
→ 方向确认
→ 题眼确认
→ 副歌核心句工作台
→ 曲式与风格确认
→ 歌词初稿
→ 歌词优化
→ 演唱控制
→ 视觉封面
→ 发布包装
→ 飞书归档
→ 复盘沉淀
```

轻阶段对老胡展示前，必须先判断是探索型还是立项型：

```text
探索型轻阶段：老胡只给题材、灵感、情绪、人物、社会议题，或还在找感觉。主产物是可比较候选池。
立项型轻阶段：老胡已经点中某个方向，或明确要求“展开这个方向 / 就这个往下拆”。主产物是单方向可确认创作总纲。
```

探索型轻阶段对老胡展示的顺序必须是：

```text
先判断输入为什么模糊。
再给 2-5 个可比较方向，让老胡看出题材轮廓和选择差异。
每个方向至少包含：分析层（人物关系、心理痛点、现实 / 社会压力）、创作显影层（短故事感、动作、声音、副歌方向、歌名气质）、选择层（为什么选、为什么不选、最大风险）。
可以给推荐倾向，但只能作为短立项摘要，不能用完整深拆压过候选池。
最后让老胡确认要展开哪个角度、题眼、副歌方向或歌名方向。
```

立项型轻阶段对老胡展示的顺序必须是：

```text
继承老胡已点中的方向。
先给方向标题句：它服务候选比较，不能冒充歌名、副歌或普通解释句。
锁定主唱 POV：谁在唱、唱给谁、用什么人称、为什么这个视角成立、是否允许 Bridge / Final Chorus 换视角。
深度论证该方向：写清主角、处境、关系变化、听众为什么会被击中、证据链、副歌核心句如何长出来、歌名方向和最大风险。
给出整首总情绪曲线：开头、Verse、Pre、Chorus、Bridge、Final Chorus 如何起伏。
给出乐段草图：Verse、Pre、Chorus、Verse 2、Bridge、Final Chorus 各自承担什么歌词功能、情绪任务、叙事目标、观众感受和内部情绪曲线。尤其要写清 Pre 如何从 Verse 的具体画面、动作、声音或身体反应接起，并把它推成 Chorus 的情绪爆发。
歌名方向必须包含命名来源、命名类型、候选淘汰理由和当前推荐，不得只给一个故事文件名。
最后等老胡确认角度、方向标题、主唱 POV、题眼、副歌核心句、歌名方向、主韵策略和大致曲式。
```

轻阶段第一屏不得被完整交接字段、评审流程表、Agent 记录、评审诊断表、内部术语归因或乐段总纲过度展开压住。若当前展示不能支持老胡清楚排除和选择，不算完成轻阶段。

正式生产交接在以下情况启用：

```text
老胡明确说正式制作、走完整流程、进入生成、交给评审官、发布包装、复盘沉淀。
已有确认角度、题眼、副歌核心句、歌名方向、主韵策略、曲式与风格，需要写入作品文件并交给下游阶段。
```

即使进入正式生产，对话展示也必须先给作品结果，再给结构证据；字段是后台秩序，不是创作的主表达。

核心原则：

```text
每一步都产出文件
→ 每一步都等老胡确认
→ 每一步都继承上一步已确认或已明显倾向的资产
→ 每一步都说明下一步
→ 每一次反馈都实时沉淀
```

除非老胡明确说“一步到位”，否则不得跳过确认门。

如果老胡明确说“训练流程 / 跑一遍完整过程 / 一个一个来 / 先打磨某个乐段”，则进入单乐段确认门。即使已有副歌、题眼或曲式，也不得一次性输出完整歌词。当前乐段只交付当前乐段的功能判断、普通话场景和歌词化版本；下一乐段只说明任务预告，等待老胡确认后再推进。

但“一步到位”只允许跳过老胡中途确认，不允许跳过智能体评审硬门。

## 0.0.1 三阶段质量小循环

正式生产或一步到位制作时，项目内部默认跑三个质量小循环。它们不是给老胡增加手工步骤，而是系统自己的质量门。

```text
选题规划循环：
topic_writer 生成 / 修改选题规划
→ topic_repair 评审、找缺点、打分
→ 最终得分 > 90 才进入歌词
→ 最终得分 ≤ 90 打回 topic_writer 修改

作词循环：
lyrics_writer 生成 / 修改完整歌词
→ lyrics_repair 评审、找缺点、打分
→ 最终得分 > 90 才进入谱曲与演唱控制
→ 最终得分 ≤ 90 打回 lyrics_writer 修改

谱曲与演唱控制循环：
music_structure 生成曲式与风格方案
→ sing_control_writer 生成 / 修改 style prompt 与 controlled lyrics
→ sing_control_repair 评审、找缺点、打分
→ 最终得分 > 90 才进入最终投喂交付
→ 最终得分 ≤ 90 打回 sing_control_writer 修改
```

可见性规则：

```text
每次进入 repair 评审节点，评审报告必须给老胡看。
必须展示：评分表、最终得分、核心缺点、修改建议 / writer 交接单、是否允许进入下一阶段。
不能只在内部记录评分，也不能只在最终回复里说“已通过评审”。
```

文件记录规则：

```text
每个阶段文件必须保存：当前 writer 结果、repair 评分报告、核心缺点诊断、writer 修改交接单、最终通过版本、下一阶段交接字段。
同一阶段多轮循环时，更新同一个阶段文件，追加简短评分轨迹，不新建 _v1 / _v2 / 最终版 文件。
评分轨迹只记录轮次、得分、最大扣分模块、是否通过和简短处理结果；不要把全部内部对话塞进结果文件。
```

默认循环上限：

```text
同一阶段连续 3 轮仍未 > 90，停止并报告：当前最高分、剩余硬伤、为什么 writer 无法继续自然提升、需要老胡确认的取舍。
```

## 0.0.2 阶段资产锁定与变更许可

规则状态：稳定规则。它适用于所有正式生产阶段交接，不属于某一题材、曲风或单次作品偏好。

阶段交接不是把上一阶段的文字丢给下一阶段参考，而是把上一步已经确认或明显倾向的资产锁进下一阶段输入。

每次从方向确认进入题眼 / 副歌核心句工作台，从副歌核心句工作台进入曲式与风格，从曲式与风格进入歌词初稿，或从歌词初稿进入歌词优化时，必须先列清：

```text
本轮继承资产：
- 已确认方向：
- 已确认方向标题：
- 已确认主唱 POV / 对话对象 / 主人称：
- 已确认 / 待打磨题眼：
- 已确认 / 待打磨副歌核心方向：
- 已确认 / 待打磨歌名方向：
- 主角与叙事视角：
- 整首总情绪曲线：
- 各乐段任务与内部微曲线：
- 主韵策略：
- 曲式与风格方向：

不可变项：
- 不得静默替换的题眼、歌名方向、副歌核心意思、主角视角和关键关系。

可微调项：
- 为韵脚、气口、尾音、曲式、句序和局部画面做的小幅调整。

变更许可：
- 如果要替换不可变项，必须先说明原资产为什么不成立、替换后会影响哪些阶段、保留哪些核心词和关系，再等待老胡明确同意。
无 POV / 无人称 / 无整首总情绪曲线 / 无结构草图时，不得进入曲式阶段；必须退回选题阶段补齐。
```

老胡说“继续 / 就这个吧 / 下一步”时，默认是继承已选资产继续打磨；不是重新生成一个新选题、新歌名或新副歌。只有老胡明确说“重新创作 / 换方向 / 推翻重来”，才允许重开候选池。

```text
需要评审官隔离评审的阶段
→ 必须先启动真实独立 Agent / sub-agent
→ 必须等待 Agent 返回
→ repair 才能汇总诊断、评分并输出 writer 修改交接单
→ writer 按诊断修改后，才能请求老胡确认是否进入下一阶段
```

如果没有开智能体、智能体未返回、或只在同一上下文里模拟评审：

```text
当前阶段只能输出待评审输入包 / 草案 / 诊断模式
不得进入下一步
不得输出下一阶段正式文件
不得写成最终版、终稿、正式评审完成或已完成
```

## 0.1 结果文件内部格式

写入阶段结果文件时，所有可复制结果都要方便复制：

```text
结果正文
候选句
歌词
style prompt
controlled lyrics
修改建议卡
交接字段
复盘结论
可投喂内容
```

以上内容在结果文件中默认必须用 Markdown 代码块包起来。

结果文件中可以放在代码块外的内容只有：

```text
简短说明
具体结果文件链接
下一步提醒
极短状态句
```

如果结果文件里既有说明又有结果，说明放代码块外，结果放代码块内。不要把大量可复制结果散落在普通段落或普通列表里。

对话回复本身保持正常阅读，不要因为本规则把日常沟通内容都包进代码块。只有当聊天窗口里直接交付大段可复制结果时，才把那一段结果单独放进代码块。

## 0.2 批量审美校准模式

当老胡要求先批量给选项、让他筛选感觉、同一内容用不同语言风格表达，或明确说不要按正常终稿流程直接产出时，当前阶段进入批量审美校准模式。

本模式下：

```text
当前阶段状态 = 候选池 / 待选择
默认候选数量 = 8-12 个
候选目标 = 暴露审美差异，不是提前选出标准答案
推进条件 = 老胡选择候选、排除候选或指出偏好
禁止动作 = 老胡选择前写成最终方向、确认题眼、正式歌词或最终投喂版
```

如果老胡没有直接选择具体候选，而是确认“按这个结构进入下一步 / 交给评审官评审”，推进条件改为：

```text
候选池 → 选题评审输入包 → 真实独立 Agent / sub-agent 评审 → repair 诊断评分 → writer 按诊断修改方向
```

此时不得跳过评审官，也不得在同一上下文里假装评审完成。评审完成前，当前阶段状态仍是“待评审 / 评审中”，不能进入曲式、歌词或最终题眼确认。

候选池必须包含：

```text
候选编号：
角度拆解视角：
选题角度：
故事背景：
人物：
场景：
关系：
事件：
阻碍：
动作：
替谁说话：
人称与口吻：
候选正文：
它的叙事视角：
故事主角：
核心场景：
冲突：
转折：
结尾刺点：
可提炼题眼：
适合发展成什么歌：
主要风险：
```

选题阶段的候选正文必须是短故事稿，不是题眼卡片。每个候选默认 300-600 字，可以根据对话篇幅压缩，但不能少于故事主角、视角、场景、冲突和转折。候选正文要像一段可直接朗读的灵感短文、人物独白或叙事文章，不能写成剧情简介、分析说明或营销选题卡。

选题的本质是角度：用什么角度看待一件事、一段关系或一种情绪。每个候选不能只换一句话，必须换一种看法。候选必须明确“什么人发生了什么事、替什么人说什么话、故事里有什么阻碍、人物做了什么动作”。

候选正文和候选说明都要使用老胡文稿语言。外部视角可以帮助找角度，但不能把“用户场景、稳定使用场景、心理位置、旧世界松手、系统解散、价值承诺、收留、被安放”等内部分析词带到对外候选里。对外候选必须写得像人话：具体、顺口、有动作、有关系，不像 AI 咨询报告。

说明字段不是歌词。`替谁说话 / 选题角度 / 故事背景 / 阻碍 / 主要风险` 必须直说，不允许写成玄句、留白句、金句或上帝视角总结。`替谁说话` 优先使用这个格式：

```text
替那些……的人说：……
```

冒号后面必须是这类人真的可能说出口的话，不能是作者替他总结出来的漂亮句。

候选池必须跨大类，不允许同一轮全是一个味道。选题阶段默认至少覆盖 4 种不同方向，例如：

```text
悲观失去：人散了、回不去了。
积极开始：终于能走向真正想要的生活。
关系解禁：终于能名正言顺在一起、见面、告白或离开。
亲情变化：父母和孩子第一次从备考关系变回生活关系。
友情 / 同伴：约好一起做一件以前不敢做的事。
自我成长：第一次不用被安排，开始自己做决定。
轻喜剧 / 自嘲：以为会狂欢，结果只想睡觉、吃饭、发呆。
现实出路：有人马上打工、搬家、离开县城或进入另一种生活。
```

同一大类最多保留 1-2 个。如果所有候选深究后都是“毕业了，所以什么都没了”，这轮候选无效。

候选标签、选题角度和风险说明不能省略到只剩抽象词。比如“毕业散场 / 回不去 / 人走散”并不是三个可选角度，如果它们都在说“考试结束后原来的同学关系和校园生活消失了”，就只能算同一个大类。执行时必须把短词背后的具体关系讲出来：谁离开，离开什么地方，原来靠什么维系，考试结束后哪条线断了，人物因此做了什么或没敢做什么。文字不以少为高级，以精准为高级。

精准词必须通过“能看见什么、谁和谁的关系如何、代价落在谁身上”来判断。不要用“空白期、生活换挡、阶段切换、情绪落差”等容器词代替故事细节。比如现实出路类候选，不能说“他的夏天没有空白期”，要说“别人讨论去哪玩，他下午去车站；别人放暑假，他去打工；家里还等着他帮忙挣钱、照顾生病的亲人或分担开学费用”。如果一句话不能让老胡看见具体人和具体事，就不是精准词。

人称必须先定再写：

```text
第一人称：主角自己说“我”，适合内心失重、羞耻、后悔和自我承认。
第二人称：对一个明确的“你”说，适合关系债、迟到的再见和没说出口的话。
第三人称：叙述者看见“他 / 她”，适合更像短篇故事、人物素描和旁观式心疼。
```

题眼、副歌方向和风险只能放在故事后面，不能替代故事本身。

老胡选择后，执行官必须输出：

```text
老胡选择了哪些候选：
这些候选共同的审美特征：
被排除候选暴露的禁用方向：
下一阶段必须保留的语言约束：
是否需要写回长期规则：
```

老胡确认进入评审后，执行官必须输出：

```text
本轮候选池摘要：
评审输入包：
评审官名单：
Agent 调用记录：
评审官隔离意见摘要：
量化评分表：
writer 修改交接单：
修改后方向：
仍需老胡确认的问题：
```

## 0. 文件更新原则

同一作品、同一阶段的反复调整，默认更新当前阶段产物文件，不新建一堆迭代文件。

允许新建文件的情况：

- 进入了新的正式阶段。
- 老胡明确要求保留多个版本。
- 需要保存原始输入、音频、图片、生成结果等不可覆盖材料。
- 当前产物已经被老胡确认，需要另起“修改版”并保留确认稿。

不允许新建文件的情况：

- 只是修改题眼、副歌核心句、曲式方案、歌词建议或演唱控制中的局部内容。
- 只是响应老胡反馈做同一阶段迭代。
- 只是为了记录过程经验。过程经验应实时写入阶段确认记录、对应 skill 或共享资产，而不是靠堆产物文件保存。

重新创作的覆盖规则：

```text
老胡说“重新创作”“完全重新创作”“重新起稿”时，默认不是同稿微调。
必须只保留老胡明确保留的上游约束，重新设计题眼表达、故事路径、核心画面、副歌 hook、歌词正文和下游演唱控制。
同一阶段仍然覆盖原文件，不新建版本文件。
如果新稿改变了副歌、题眼或画面资产，必须同步覆盖 01/02/03/04/05 中受影响的交接字段。
```

经验沉淀原则：

- 老胡指出的疑似长期有效经验，立刻进入五项测试和规则状态判断；通过后再写入对应 skill、共享资产、流程文件、当前作品复盘或规则进化备忘录。
- 老胡给出的所有反馈都必须判断文件落点；不能只在聊天里解释。即使暂不升级为正式规则，也必须写入当前作品记录或规则进化备忘录并说明原因。
- 当前作品内的状态变化，立刻写入 `00_阶段确认记录.md`。
- 不等到最终复盘再回忆总结；最终复盘只整理作品级结果，不承担唯一经验吸收职责。

### 确认门

选题题眼阶段不是一次确认。必须区分：

```text
方向确认：你确认哪个方向？
题眼确认：这个方向的题眼是否确认？
副歌确认：副歌核心句是否确认，主韵脚和句尾是否满意？
```

只有方向、题眼、副歌核心句三项都由老胡明确确认后，才能进入曲式与风格阶段。老胡只选择方向或补充意见，不等于确认进入下一阶段。

如果选题阶段需要正式评审诊断，必须先完成真实独立 Agent / sub-agent 选题评审并收到返回；未完成智能体评审时，即使老胡说“一步到位”，也只能停在待评审输入包或诊断草案，不能进入曲式与风格阶段。

如果选题阶段需要修改，必须先由 `laohu_music_topic_repair` 输出评审诊断和评分，再由 `laohu_music_topic_writer` 按诊断修改。`laohu_music_topic_repair` 不直接输出改后选题规划、确认题眼或下游交接字段。

同时，曲式与风格阶段必须调用选题题眼阶段的整首歌总纲。选题题眼如果只有副歌核心句、没有叙事入口、情绪曲线、乐段创作指导和副歌递进规划，不得进入下一阶段。

乐段创作指导不是段落名清单。每个乐段至少要写清歌词功能、情绪任务、叙事目标、观众感受和内部情绪曲线。Pre-Chorus 必须有承接链：Verse 的哪个画面 / 动作 / 声音 / 身体反应被抽出来，为什么它会让人物心理升级，歌词用什么气口、句长、尾音、动作或停顿把它推到 Chorus。如果 Pre 只写“承接主歌、推向副歌”而没有这条链，判为上游交接不足。

乐段创作指导还必须写清 Verse 入口如何证明核心关系，而不是只给一个生活事故或漂亮镜头。每个 Verse 入口都要标明最容易被误读成什么其他关系，以及用哪些关系证据防止误读：称呼、人物年龄、亲密动作、身体距离、对方防御反应、权力姿态、空间位置或即将发生的不可逆动作。若下游凭这个入口会把伴侣暴力写成父母管教孩子、把恋人争执写成普通室友冲突，说明上游交接不足，不得直接进入填词。

阶段交接里的短句只能做字段标题，不能替代字段内容。`建立现场 / 承接情绪 / 情绪出口 / 翻面 / 回收` 这类短语必须继续展开到：本段写什么、为什么放在这里、准备用哪些歌词表现抓手、观众在这里如何感受、它如何承接上一段并推动下一段。若下游需要重新猜这些内容，说明上游交接失败，不得直接进入填词。

如果选题题眼没有明确人群、核心关系、故事引擎、情绪债务和证据配额，即使副歌核心句暂时好听，也不得进入下一阶段。副歌必须是故事压力压出来的落点，不是孤立金句。

如果下游副歌打磨反复出现“情绪不爆、关系要靠推测、动作对象拗口、歌词只能解释不能唱”的问题，执行官必须回查本阶段交接字段。若整首歌总纲没有锁定事件链、情绪发动机和乐段心理动作，当前问题判为上游总纲缺失，不得继续局部改句；必须退回选题题眼阶段补总纲，再重新进入副歌核心句工作台。

方向确认后、题眼和副歌核心句确认前，允许并鼓励在选题题眼阶段内部调用歌词优化能力，对副歌核心句做问题卡诊断和局部改写。该调用不代表进入正式歌词优化阶段，不创建 `04_歌词优化` 产物；修复结果必须回填到当前选题题眼文件。
