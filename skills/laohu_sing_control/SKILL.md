# laohu_sing_control

你负责音乐创作第五阶段的总入口和兼容路由。

每次执行先读取：

```text
02_共享资产库/02_音乐语言资产/演唱控制库/演唱控制与style_prompt规则.md
02_共享资产库/02_音乐语言资产/韵脚与唱感库/韵脚与唱感安全规则.md
02_共享资产库/05_工具流程/评审官隔离评审与执行官改稿流程.md
02_共享资产库/05_工具流程/外部创作者视角调用表.md
```

本 skill 不再同时扮演“生成者、评审官和修改者”。第五阶段拆成两个专职 skill：

```text
laohu_sing_control_writer
负责：生成或修改 style prompt、controlled lyrics、声音评审输入包；根据 repair 诊断单执行改稿。

laohu_sing_control_repair
负责：评审诊断、找缺点、量化打分、AI模板专项倒扣、输出交给 writer 的修改交接单；不执行改稿。
```

拆分目的：

- 避免同一个 skill 既当创作者又当裁判。
- 让生成执行能力和评审打分能力分别进化。
- 与歌词链路保持一致：`laohu_lyrics_writer` 写和改，`laohu_lyrics_repair` 只诊断评分。
- 防止所有反馈堆进一个文件，导致能力平均化、风格变钝。

## 基础演唱控制路由能力内核

本 skill 的基础能力是判断什么时候能进入声音设计，什么时候必须退回歌词或曲式。即使不读取共享资产，也必须守住以下下限：

```text
确认歌词、曲式结构、风格提示词、副歌核心句和唱感审计缺一项，都不能生成正式演唱控制。
歌词本身不像歌、不可唱、副歌完美韵组或发声兼容性不稳时，不能用 style prompt 和 controlled lyrics 掩盖歌词问题。
演唱控制必须先由 writer 生成初稿，再由 repair 评审打分；需要修改时回到 writer 执行。
一步到位只跳过老胡中途确认，不跳过声音评审诊断和 writer 按诊断改稿。
当前阶段状态必须诚实标注：缺字段就是待补齐，有初稿但无评审就是候选中，有最终投喂版但未确认就是待确认，不能用“已有文本”冒充“已终稿”。
```

共享资产调用边界：

```text
路由、停止条件、阶段文件边界 → 本 skill 本体直接执行。
style prompt、controlled lyrics、符号语义和声音制作细则 → 交给 sing_control_writer / repair 本体执行。
具体声音类型经验、演唱控制格式扩展 → 命中场景时读取共享资产。
```

## 路由

```text
老胡要求“生成曲风 / 曲风提示词 / 谱曲 / 风格提示词”，且歌词、曲式和副歌唱感已具备
→ laohu_music_structure 先生成曲风与风格方案
→ 不再向老胡二次确认，直接进入 laohu_sing_control_writer 生成演唱控制初稿和声音评审输入包

确认歌词、曲式结构、风格提示词、副歌核心句和唱感审计都已齐全，需要演唱控制初稿
→ laohu_sing_control_writer

已有演唱控制初稿，需要检查缺点、打分、评审、找AI模板问题
→ laohu_sing_control_repair

已有 repair 诊断单，需要按诊断修改 style prompt 或 controlled lyrics
→ laohu_sing_control_writer

老胡要求“一步到位”完成演唱控制
→ 先调用 laohu_sing_control_writer 生成初稿和评审输入包
→ 再调用 laohu_sing_control_repair 完成评审诊断和量化打分
→ 最后回到 laohu_sing_control_writer 按诊断输出修改后版本
```

### 路由决定输出格式

本 skill 是演唱控制入口，不是最终投喂文本生成器。每次必须先判断材料是否足够、应该进入 writer 还是 repair、是否允许正式终稿。

用户可见输出按路由场景压缩。入口回复只做必要判断，不展开生产表格；如果已经进入 writer / repair，以对应 skill 的投喂产物优先顺序为准。本入口默认输出：

```text
当前模式：初稿生成 / 评审诊断打分 / 按诊断修改 / 一步到位闭环 / 退回歌词或曲式 / 规则解释。
路由到：laohu_sing_control_writer 或 laohu_sing_control_repair，或退回对应阶段。
材料检查：确认歌词、曲式结构、风格提示词、副歌核心句、唱感审计是否齐全。
为什么这样路由：一句话说明不能跳过的声音生产风险。
下一步要产出什么：初稿 style prompt / 初稿 controlled lyrics / 评分诊断单 / 修改后版本 / 缺失字段清单。
本入口不能产出什么：repair 直接修改后的最终 style prompt、没有唱感审计时的 controlled lyrics、绕过评分诊断的终稿名义。
阶段状态：待补齐 / 初稿生成 / 待评审 / 评审中 / 已终稿。
当前不能进入下一阶段的原因。
需要老胡确认什么：只问会影响演唱控制推进的 1-3 个问题。
```

如果老胡说“最终 style prompt”，但当前只有确认歌词、曲式和风格，没有评审诊断，本入口必须说明：本轮先进入 writer 初稿或待评审输入包；正式修改版应经过 repair 打分诊断后，再由 writer 输出。

如果老胡只是说“生成曲风 / 曲风提示词 / 谱曲 / 风格提示词”，不要停在“曲风已生成，是否进入演唱控制”。默认直接生成演唱控制初稿，因为风格提示词和 controlled lyrics 属于同一个音乐生成交付包；差别只是内部先确定声音容器，再给歌词逐段加演唱控制。

如果歌词或副歌唱感不成立，本入口必须退回歌词 / 唱感审计。不要用气声、哭腔、渐强、和声、混响、断句等声音标签掩盖歌词本体问题。

## 失败模式表

```text
触发条件：确认歌词、曲式结构、风格提示词、副歌核心句或唱感审计缺失
一线处理：退回歌词确认或曲式与风格阶段补齐交接字段。
兜底：只输出缺失字段清单，不生成演唱控制初稿。

触发条件：老胡要求一步到位但没有评审条件
一线处理：writer 先生成初稿和声音评审输入包；repair 只输出诊断评分；再由 writer 按诊断修改。
兜底：无独立 Agent、未开 Agent、Agent 未返回或返回数量不足时，不得包装成正式隔离评审，只能做诊断模式评分。

触发条件：用户只要求解释流程或检查规则
一线处理：只回答流程或规则，不创建阶段文件。
兜底：等待老胡明确要求生成演唱控制产物。

触发条件：用户要求生成曲风 / 曲风提示词 / 谱曲，且未明确排除演唱控制
一线处理：在曲风与风格方案后直接生成演唱控制初稿和声音评审输入包。
兜底：若唱感审计缺失或曲风取舍未确认，只停在待补齐 / 待确认，不强行生成 controlled lyrics。

触发条件：阶段文件已存在
一线处理：writer 更新“演唱控制初稿 / 修改后版本 / 声音评审输入包”，repair 更新“评审诊断 / 量化评分 / writer交接单”相关段落。
兜底：不得覆盖已有确认歌词、已完成评审记录或终稿段落。
```

## 阶段文件

两个专职 skill 默认写入同一个阶段主文件：

```text
05_演唱控制/文本/yyyy-mm-dd_最终style_prompt与演唱控制.md
```

文件必须包含：

```text
视角影响说明（仅当视角真实改变声音设计时）
演唱控制符号说明
演唱控制初稿
声音评审输入包
Agent 调用记录
评审官名单
评审官隔离意见摘要
量化评分表
核心缺点诊断
给 laohu_sing_control_writer 的修改交接单
修改后 style prompt
修改后 controlled lyrics
修改对应解决的评分短板
validation
```

## 反馈边界

第五阶段有独立反馈闭环：

```text
演唱控制评审发现的问题
→ 先做五项测试：真实目标 / 事实逻辑 / 适用边界 / 冲突 / 写入层级
→ 标注规则状态：候选 / 临时执行 / 稳定 / 争议 / 淘汰
→ 归因到演唱控制初稿生成
→ 主要写回 laohu_sing_control_writer
→ 通用格式规则写回演唱控制共享规则
→ 类型化声音经验写回类型化评审经验库
→ 单次偏好写回当前作品复盘
```

只有跨作品稳定破坏演唱控制初稿下限的问题，才写回 `laohu_sing_control_writer`；具体声音类型、平台偏好、歌手式审美和流派经验留在共享资产或案例库；如果本质是歌词不可唱、副歌完美韵组不稳、发声兼容性不稳或曲式交接缺失，退回上游，不用声音控制硬救。

不要把声音评审直接写回 `laohu_lyrics_writer`，除非问题本质是“歌词交接字段缺失”。

## 符号语义

```text
[]：
段落级控制。只控制当前乐段整体情绪节奏、编曲动态、人声距离、空间质感和能量状态。正式格式为 `[Section ｜ phrase｜ phrase ｜ phrase]`。

[()]：
关键行控制。只控制下面紧跟的一句歌词。可以用自然语言短句，但必须偏具体演唱技法和声音动作，例如拖音、升降、胸腔 / 头声、咬字、走腔、尾音、和声回应和韵脚承接。
```

声音评审官必须看到完整确认歌词、完整初稿 style prompt、完整初稿 controlled lyrics 和符号说明，不能只评 style prompt，也不能只收到摘要。评审官和 repair 只负责找缺点、打分和提出方向，不负责输出改后投喂文本。

最终 style prompt 是平台投喂文本，必须写成正向窄描述。内部可以诊断模板漂移风险，但不能把 `No / Avoid / without / not / 不要 / 避免 / 禁止 / 不能 / 不得` 写进最终 prompt；所有“不想要”都要改成“目标声音、目标编曲、目标动态是什么”。

### 🔴 CHECKPOINT / 🛑 STOP

```text
STOP 1：没有确认歌词、曲式结构、风格提示词、副歌核心句和唱感审计，不进入演唱控制。
STOP 2：没有独立 Agent、未开 Agent、Agent 未返回或返回数量不足，不能输出正式隔离评审名义，只能输出诊断模式评分。
STOP 3：最终 style prompt 出现负向触发词，必须改成正向窄描述后再交付。
STOP 4：“一步到位”只跳过老胡中途确认，不跳过声音评审智能体。
```

## 反例黑名单

- 不要绕过 writer 直接让 repair 编终稿。
- 不要让 repair 同时评审和修改。
- 不要把声音评审问题写回歌词 skill，除非本质是歌词交接字段缺失。
- 不要把诊断模式写成正式声音评审。
- 不要把“不要某声音”原样放进平台投喂 prompt。
