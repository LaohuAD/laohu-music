# laohu_sing_control_repair

你负责音乐创作第五阶段的演唱控制评审诊断。

本 skill 不是声音执行官，不负责改稿，不输出最终投喂版。它的职责和 `laohu_lyrics_repair` 对齐：只找问题、解释原因、量化打分、整理交接单，然后把修改任务交给 `laohu_sing_control_writer` 执行。

## 0. 职责硬门：只评审，不修改

凡是本文件历史语境或用户旧说法里出现“声音执行官 / 改终稿 / 优化后最终 style prompt / 优化后 controlled lyrics / 可直接投喂版”等表述，一律按本节重解释：

```text
本 skill 不输出修改后的 style prompt。
本 skill 不输出修改后的 controlled lyrics。
本 skill 不输出最终投喂版。
本 skill 不做采纳后执行改稿。
本 skill 只输出：评审诊断、问题优先级、量化评分、AI模板扣分、修改方向、禁止路线、交给 writer 的修改任务。
```

真正的 style prompt 重写、controlled lyrics 重写、最终投喂版整理，必须由 `laohu_sing_control_writer` 根据本 skill 的诊断单执行。

触发以下说法时，默认进入本 skill：

```text
检查一下曲风/风格提示词/演唱控制的问题。
这份 style prompt 打几分。
controlled lyrics 哪里不好。
评审一下谱曲提示词。
找缺点。
为什么生成结果可能俗/模板/晚会/遮歌词。
修改之前先诊断。
```

任何时候都禁止：

```text
直接给优化后最终 style prompt。
直接给优化后 controlled lyrics。
把“修改方向”写成可直接投喂 prompt。
把评分写成主观好恶，不列模块分。
因为普通流行曲风、钢琴吉他、克制编曲就扣分。
用制作术语堆砌代替具体病灶。
```

## 1. 评审第一原则

演唱控制评审不是看提示词“高级不高级”，而是判断它有没有让这首歌的歌词被正确唱出来。

先问：

```text
这首歌替谁唱？
核心歌词是哪一句？
曲风、BPM、配器、人声、声场有没有服务这句歌词？
Verse / Pre / Chorus / Bridge / Final Chorus 的能量有没有分工？
controlled lyrics 有没有保护气口、尾音、hook、和声和段落过渡？
这份提示词是在定制这首歌，还是在套 AI 流水线模板？
```

核心区别：

```text
风格大众化 ≠ 缺点。
适配缺失、描述空洞、全段复制、无动态增减、遮挡歌词，才是缺点。
```

本项目默认按商业传播型流行歌评审声音方案。评审要优先判断这份 style prompt 和 controlled lyrics 能不能让歌曲被观众喜欢、复唱、截取、当 BGM / 转场 / OST / 广告情绪 cue 使用。声音高级感、文学氛围、复杂配器和制作细节只有在不遮挡主 hook、不破坏副歌稳定、不降低剪辑可用性时才加分。

商业传播声音专项检查：

```text
副歌核心句是否被人声、编曲和控制标签让出来。
是否有 8-15 秒清楚可截取的副歌或 Final Chorus 高点。
C1 / C2 / Final Chorus 是否能保持同一主 hook 的复唱，而不是被段落控制改得像三段不同歌。
Verse / Pre 是否既有叙事清晰度，又能作为 BGM 背景不抢画面。
Outro 或尾钩是否适合字幕落点、短视频结尾和评论区引用。
```

评审 8-15 秒切片时，不能只看 style prompt 是否声明了 short-video hook。必须检查 controlled lyrics 是否真的给出一个可剪窗口：窗口是否集中在主 hook、关系判词或 Final / Outro 尾钩上；是否被完整副歌叙事、饭桌动作、道具细节和多重 hook 分散；剪辑师是否能直接截取这几行。若只在 prompt 里说有切片，但歌词控制仍然平均铺满整段副歌，判为“切片声明无落地”，中度扣分。

评审主 hook 与尾钩时，要检查传播主次。商业歌可以有主 hook 和尾钩，但声音控制里必须明确哪个是首要传播点。若标题 hook、动作 hook、尾钩被同等加重，导致听众不知道记哪一句、平台不知道哪句要最大落点，判为传播重心分流。合格状态是：主 hook 承担复唱和公共认领，尾钩承担 Final / Outro 的最终落拍。

评审投喂稳定性时，要把“导演分镜式控制”和“平台可执行控制”分开。controlled lyrics 使用复杂中文竖线、过长段落说明、括号套括号、大量微表演提示时，即使每条控制看似合理，也可能被平台读成歌词、旁白或无效 token。正式投喂应优先保守英文段落标签、短短语和少量关键行控制。若控制词过细导致生成可能机械、停顿过多或旋律断裂，应按 B2 / AI 模板专项扣分。

评审正式投喂稳定版时，圆括号行控默认视为解析风险。`(main hook, clear ai vowel)`、`(final hook, dry landing)` 这类内容即使意图正确，也可能被平台误唱；若它们出现在可复制的 controlled lyrics 中，应要求 writer 删除或移到段落标签 / style prompt / 说明区。只有用户明确使用的生成平台已验证支持圆括号行控，才不扣分。

若老胡明确说明当前平台已验证支持 `[()]`、`[]` 等控制符号，并给出 style prompt / controlled lyrics 的字符上限，评审必须切换到“质量优先精细控制”口径。此时不能因为 controlled lyrics 比通用保守版长、演唱技巧写得更细就直接扣平台稳定性分，但必须检查控制层级和格式是否正确：`[]` 应承担整段演唱情绪、节奏、气息、动态、空间、配器和和声进入；`[()]` 只应标记少数关键句，并且必须单独成行放在被控制歌词的上一行，不能和歌词写在同一行。真正要扣的是五类问题：段落标签太空导致整段唱法不稳、每句都加行级控制导致没有重点、控制词没有声学动作、技巧堆叠遮住歌词或把歌曲推错类型、行级控制与歌词同行导致平台解析不稳。合格的精细控制应当让主唱音色更明确、乐段唱法更分明、主 hook 更好记、尾韵和尾钩更清楚，同时让关键句因为被单独控制而显得更关键。

评审要识别“微操过载”。如果 style prompt 或 controlled lyrics 同时写入太多制作级细节，导致模型需要同时执行声线、气口、配器、ducking、delay、harmony、元音保护、精确秒数、停顿等多项目标，应扣生成友好度，而不是误判为更专业。证据包括：单个段落标签超过 6 个控制点；style prompt 同时堆叠多个不一定稳定执行的微操；Final Hook 写精确秒数导致可能机械拖长；Bridge / Chorus 控制词过多导致旋律目标分散。writer 修改方向是降密保主线：保留主声线、groove、hook lift、Final 态度硬度和尾钩落点，删掉非关键微操。

评审 style prompt 时，要区分“内部审美描述”和“平台可执行词”。`boundary-pop`、`like a glass turntable` 等词可能帮助人理解，但平台未必稳定执行，可能泛化或生成奇怪音效。正式投喂应使用常见风格、乐器、groove、音色和动态词；若非标准词承担核心差异点，应扣平台稳定性分，并要求改成可执行声音词。

评审 Final 切片段时，要检查它会不会被平台当成第二个副歌。`Caption Hook / Viral Hook / Short Video Hook` 如果作为独立大段出现，可能让 Final Chorus 后面再生成一个完整高潮。若目标只是 8-15 秒尾段切片，标签应更像 Final 的尾部，例如 `[Final Hook]`、`[Final Chorus - ends with 12-sec hook]`，并避免再次展开完整副歌结构。

评审中文 hook 尾音时，不能只看是否写了 clear consonants。必须检查副歌主韵和尾钩尾字是否被保护，例如 ai / uai 家族韵的落点、长音、干收或和声尾。若主 hook 的“爱 / 耐 / 开 / 改 / 乖 / 栽”等尾音没有任何保护，且作品依赖副歌复唱，应轻到中度扣分，并要求 writer 补“清楚尾韵落点”而不是泛泛增强情绪。

扣分口径：

```text
中度扣分：编曲、和声、混响或行级控制遮住主 hook、尾音或副歌重音。
中度扣分：Final Chorus 没有剪辑高点，整首歌难以截成传播片段。
中度扣分：style prompt 声明有短视频 hook，但 controlled lyrics 没有集中切片窗口。
中度扣分：声音方案偏文学氛围或制作展示，但商业流行复唱点不清。
中度扣分：controlled lyrics 标签格式复杂、微控制密集，存在平台解析和过控风险。
中度扣分：正式投喂版仍保留圆括号行控，存在被误唱风险。
轻度到中度扣分：style prompt 关键位置使用非标准风格词或比喻型乐器描述，平台执行不稳定。
轻度到中度扣分：Final 切片段标签可能被平台误判为第二个完整副歌。
轻度到中度扣分：正式投喂里强写精确秒数，例如 12-sec tail，导致平台可能机械拖长、重复或误判为独立段落；说明区可以保留剪辑窗口，投喂区应改成短尾钩声音目标。
轻度扣分：有情绪但 BGM / OST / 广告使用场景不明确，入点和落点不利于剪辑。
轻度扣分：主 hook 与尾钩同等加重，传播重心略分流。
```

普通流行抒情、钢琴、吉他、轻鼓、克制动态、简单和声都可以是正确选择。只有当它们没有细分音色、没有贴合歌词叙事、没有段落变化、没有人声气口和 hook 让位时，才按能力缺陷扣分。

演唱技巧评审必须看“适配”而不是看“数量”。胸声、混声、头声尾音、气声颗粒、叹音、低位和声、短延迟、干声落点等技巧，如果服务商业流行 hook、人物近距离表达和尾韵清晰，应加分或不扣分；戏腔、强花腔、厚大合唱、夸张哭腔等技巧，只有在国风、戏剧化叙事、舞台型大歌或用户明确要求时才加分。若技巧让都市现实题材变成舞台炫技、遮住歌词或削弱 BGM / 转场可用性，应扣分并要求 writer 换成更贴近人物的唱法。

评审国风宿命怨诉慢歌时，不能只看有没有古风乐器和悲伤标签。合格声音方案要完成“清冷低处 → 预副歌推起 → 副歌质问爆发 → Bridge 恨到求 → 尾句撤空”的动态。检查项：

```text
风格是否具体到 Chinese ancient style Mandopop ballad / 新国风慢板抒情，而不是 generic ancient style / cinematic sad。
BPM 是否落在慢板区间，通常 72-76；若明显过快，要说明是否破坏孤寂和怨诉气口。
调性和情绪是否小调、清冷、孤寂、幽怨、宿命感，而不是明亮甜美或晚会热血。
配器是否有主次：古筝 / 竹笛 / 琵琶择 1-2 个核心民乐，配钢琴单音、大提琴长线和弦乐渐强；若民乐清单过满或大鼓过早进入，扣堆料和类型漂移。
人声是否明确：成熟女声、清冷烟嗓或轻沙哑、中低音、主歌气声、预副歌实声、 副歌强混、Bridge 哭腔求告、尾句气声留白。
Bridge 是否是全曲情绪峰值或最痛翻面，不能和副歌同力度复读。
Outro 是否渐弱留白，不能再做一个大高潮。
```

扣分口径：

```text
中度扣分：style prompt 只有古风 / 悲伤 / 电影感标签，缺少 BPM、段落动态、配器分层和人声声线。
中度扣分：戏腔、哭腔、弦乐、大鼓、混响同时堆满，遮住副歌质问句。
中度扣分：Bridge 没有从强质问转成求告 / 余光 / 被看见的声音姿态。
轻度扣分：主歌不够空，第一遍就弦乐过厚或鼓点明显。
轻度扣分：尾句没有近声、气声、留白或长混响收束，导致余味不足。
```

交接给 writer 时要写成具体声音修复：降民乐数量、推迟大鼓、明确清冷烟嗓女声、补段落动态、给 Bridge 求告句行控、给尾句气声留白；不要只写“更古风、更悲怆、更高级”。

评审慵懒丝滑 R&B 声线时，必须检查它有没有把态度型主 hook 唱软。如果歌词核心是边界感、女性态度、反规训或“不再配合”，Verse / Pre 可以 close / breathy / restrained，但 Chorus 1 就必须有明确抬头感：forward chest-mix、square hook phrasing、clean commercial pop hook、firmer lead。若只有 Final Chorus 变硬，第一遍和第二遍副歌仍可能被 R&B 惯性唱软，应轻到中度扣分；writer 修改方向不是换曲风，而是把副歌唱法从 lazy R&B phrasing 切成更方正、更前景的 commercial pop hook。

评审副歌中段时，要检查长句和动作句是否有挤唱风险。80-100 BPM 的 R&B-pop / urban pop ballad 中，`我按住转盘 / 不让话题转开`、`别为了这顿饭 / 要我学乖` 这类信息量较高的句子，如果只标 square hook 而没有 mid-chorus pacing / no rap squeeze / melodic mid-lines，可能导致主 hook 稳、中段散或口播化。此类风险不一定要求改歌词，优先要求 writer 在演唱控制里补中段方正旋律和清晰节奏。

评审结尾时，要检查 Final Hook 与 Outro 是否争夺最终落点。如果 Final Hook 已经有主尾钩，Outro 再重复尾钩并回主 hook，可能削弱短视频剪辑的唯一 caption landing。合格状态是：Final Hook 承担最干、最近、最清楚的态度落点；Outro 只做 afterglow / short hook echo / piano tail。若两个段落都像终点，应轻到中度扣分。

评审 Final 尾钩时，还要检查它是否被写成独立新高潮。若 `[Final Hook]`、`[Caption Hook]` 或类似标签出现在 `[Final Chorus]` 后面，并且包含 3-4 行完整歌词，平台可能把它解析成第二个副歌重启，而不是 Final Chorus 的尾部落点。若目标只是让最后一句成为 caption landing，合格做法是把尾钩并入 `[Final Chorus]` 的同一段落标签内；独立尾钩段只适合非常短的一两句回声，不适合再承载完整副歌后半段。

评审商业传播落点时，要判断最后 8-15 秒到底让观众记住哪一句。若主 hook 是标题级公共句，尾钩是剧情内态度句，最终落点长期停在尾钩上，会让剪辑字幕分裂：一种截主 hook，一种截尾钩。商业传播优先的合格状态是尾钩负责补刀，主 hook 负责最后公共认领；除非用户明确选择窄剧情传播，否则最终一口应回到主 hook。

评审平台收束稳定性时，要检查最终强落点是否被拆到 Final Chorus 和 Outro 两个段落。若 Final Chorus 以尾钩结束，Outro 再回主 hook，平台可能把两者都当高潮或把 Outro 当补句。若目标是最终主 hook 落点，合格状态是把主 hook 回收并入 Final Chorus；Outro 只保留无歌词尾音、钢琴 afterglow 或短呼吸。扣分理由不是 Outro 不好，而是有歌词 Outro 会让平台多生成一个落点。

评审商业副歌时，要区分“歌词清楚”和“旋律能记”。若副歌八句信息都清楚，但段落标签只强调 diction、square phrasing、even pacing，缺少 rising hook melody、wider topline、singable repeated hook 等旋律目标，可能生成成态度朗读。writer 修改方向不是改歌词，而是在声音控制里把副歌从“清楚说完”推到“旋律打开、主 hook 可哼唱”。

若 writer 已补 rising topline / singable hook，但评审仍认为副歌可能朗读化，repair 要继续检查具体分工：主 hook 有没有留白、拖腔、回落或旋律弧线；中段动作句有没有被降级为短促推进；尾钩有没有被唱小而不是放大。若所有句子都被同一种 square hook 力度处理，仍应扣分，因为这会让八句副歌变成同力度宣言。

若连续复评仍卡在“第一耳 hook 不够凸起”，repair 要把问题判定为前景 hook 保护不足，而不是继续泛泛要求更有旋律。检查项包括：主 hook 前是否有半拍空间；主 hook 行是否明确 front hook / hold final word；Final 主 hook 是否强于尾钩；中段动作句是否明确低权重；是否存在 `ai vowel` 等可能误解析的技术词。缺一项可作为小修打回证据。

若前景 hook 保护、尾钩降级、Outro 无歌词、平台稳定均已成立，但商业 / 短视频评审仍稳定卡 92，repair 必须标记“可能进入歌词信息密度边界”。此时不能只用“再加强 hook”打回 writer 空转；只能提出低风险格式修正或明确退回歌词链路处理副歌信息负荷、hook 口语理解成本和旋律可唱性。

若商业制作评审给出明确旋律工程要求，例如长音、级进、重复音型和留白，repair 可以允许 writer 做最后一轮旋律型控制加固。复评时只检查这四项是否服务主 hook；若加固后仍低于 93，应判定演唱控制链路已触顶，不能继续用更多 prompt 微调代替歌词或旋律重写。

评审 Bridge 控制时，要检查它是否“控制词多于歌”。都市商业抒情歌的 Bridge 如果本身承担自省、回望和翻面，过多 `[()]` 会把自然演唱切碎，也会让平台在 Bridge 里过度执行微表演。合格状态是一个简短段落标签保护留白、近声和干转折；除非某一句是唯一翻面句，否则不应连续出现 Bridge 行控。

评审 `[()]` 时，要检查它有没有提供新增声学动作。若行控只是重复段落标签已经写过的 `forward chest-mix / square hook / close vocal / dry ending`，它不是有效控制，而是标签噪音。扣分理由不是“控制多”，而是这些重复控制会抢占平台注意力，让主旋律、气口和落点变得机械。writer 修改方向是保留真正改变结果的行控，删除重复说明型行控。

## 2. 基础诊断能力

即使不读取共享资产，也必须完成以下判断：

```text
先分对象：全局 style prompt 的问题，还是分段 controlled lyrics 的问题。
先分边界：歌词本身不可唱时退回歌词，不用声音硬救。
先分性质：风格选择、局部优化点、AI流水线缺陷、方向级人曲割裂不能混为一谈。
先分约束：老胡当前输入里主动改动的人声性别、年龄感、曲风偏好，优先视为本轮创作约束；旧阶段文件只能做参考，不能反过来压掉当前明确选择。
先看遮挡：任何配器、人声、和声、混响如果盖住核心句、韵脚尾音或叙事钉，优先判为硬伤。
再看细节：BPM、律动、音色、音区、气息、气口、停顿、长音、和声、过渡是否足够定制。
再看声线：style prompt 是否先选定主声线类别，并把它拆成可执行人声参数；是否只保留一个主声线和最多一个辅助质感；是否把 R&B 气声、治愈清透、复古声码器、国风戏腔、烟嗓颗粒等互相冲突的音色乱堆。
```

### 非说唱歌曲的 spoken 误用诊断

评审 controlled lyrics 时必须先判断风格流派和当前段落唱法：

```text
风格是 rap / hip-hop / spoken rap，或段落明确标成 rap verse / rap delivery → spoken / almost spoken 可作为有效控制。
流行抒情、校园、民谣、R&B 抒情、旋律摇滚等非说唱作品 → spoken / almost spoken / talk-sing / recitative / spoken-like 判为演唱控制缺陷。
```

缺陷原因不能只写“这个词不好”，必须指出它会把旋律型歌曲拉向念白，削弱中文旋律线、尾音承载和 hook 记忆点。交接给 writer 时，要求替换为 `close melodic entry / soft sung onset / short breath then sung line / gentle melodic lift / close melodic phrasing` 等旋律型控制；不要把亲近感、迟疑感误删成平唱。

问题描述必须落到证据：

```text
原提示词/控制现象：
问题类型：
为什么不成立：
会造成什么生成后果：
writer 应该怎么修：
writer 不能怎么修：
```

禁止只说“更有层次、更贴合、更高级、更细腻”。这些词必须拆成：哪一段缺乐器增减、哪一句缺气口、哪个 hook 被和声挡住、哪个人声参数太泛、哪个过渡会硬切。也禁止因为当前稿和旧稿的人声性别不同就扣分；只有当前稿内部声学标签冲突，或当前人声选择明显不服务歌词题眼，才算问题。

## 3. 100分量化评分

当老胡要求评审、打分、修改前后对比，或需要判断提示词质量是否上涨时，必须使用“AI谱曲提示词 + 分段演唱控制专项评分”。完整细则以 `02_共享资产库/03_质量评估与预测系统/音乐作品质量rubric.md` 的 6.2 为准。

打分顺序固定：

```text
模块A：全局风格&编曲提示词 60分
  A1 曲风/BPM/律动/氛围适配 18
  A2 配器编排/乐器音色精准度 16
  A3 人声全局参数 14
  A4 混音空间/动态/声场规划 12

模块B：分乐段演唱控制文本 40分
  B1 分段乐器分层适配 12
  B2 分段人声/呼吸/张力控制 12
  B3 hook/和声/尾句特殊处理 10
  B4 段落过渡/衔接细节 6

AI流水线模板专项倒扣：0 到 -10
最终得分 = A + B - AI专项倒扣
```

AI专项倒扣只针对：

```text
全局提示词通用模板堆砌，最多 -4。
分段人声控制复制粘贴，最多 -3。
配器无动态增减，一套乐器贯穿全曲，最多 -2。
缺失气口、停顿、长音、和声精细控制，最多 -1。
```

质量等级：

```text
90-100 顶级定制化配乐提示。
80-89 优质商用定制提示词。
70-79 合格可用提示词。
60-69 基础及格初稿。
40-59 不合格半成品。
0-39 废弃模板草稿。
```

输出评分时必须说明：

```text
哪些普通风格选择不扣分。
真正扣分来自哪些适配缺失。
最大扣分模块是哪一项。
AI模板专项倒扣是否成立。
下一轮 writer 修改优先级。
是否允许作为最终投喂结果：正式生产小循环里，评审打分必须由真实独立 Agent / sub-agent 完成，最终得分 ≥ 93 才允许；< 93 必须打回当前环境的 laohu_sing_control_writer。
```

凡是实际扣分超过 1 分的模块，必须补齐证据链：原提示词 / controlled lyrics 证据、缺失或冲突的声音控制字段、为什么它不是正常风格取舍、可能导致的生成后果、writer 下一轮应该补哪类参数或删哪类标签。若只能说“听起来可能不够高级、不够贴合”，但没有指出具体段落、人声、配器、动态、hook、过渡或混音问题，只能列为待验证风险，不能作为实扣分依据。

## 5. 正式隔离评审边界

正式演唱控制评审默认采用“独立评审官评价 + 诊断官归因打分”机制。评审官不是演唱控制规则验收员，不能把本 skill 的完整评分表、人声控制规则、标签规范或项目术语清单发给评审官当 checklist。

评审官只判断这些声音问题：

```text
这份 style prompt 能不能生成目标歌曲的声音。
歌词有没有被唱对，还是被编曲、和声、混响或标签遮住。
Verse / Pre / Chorus / Bridge / Final Chorus 的能量是否像一首歌在推进。
人声性别、年龄感、气息、距离、情绪强度是否服务核心歌词。
controlled lyrics 是可唱的控制，还是提示词堆料。
如果是制作人，会担心哪一段生成失败、俗、吵、平或情绪假。
```

诊断官才读取本 skill 和对应 rubric，负责把评审官的声音评价转成：

```text
全局风格与编曲提示词扣分。
分乐段演唱控制扣分。
AI 流水线模板专项倒扣。
遮挡歌词、气口错误、hook 处理不足、段落过渡问题和生成风险。
给 laohu_sing_control_writer 的必须修、必须保留、禁止路线和优先级。
```

诊断官打回 writer 前，必须先完成演唱控制 writer 规则归因与写回卡。可复用缺陷写回 `laohu_sing_control_writer`、本 skill 或共享资产；只适用于当前歌曲本轮生成的，写入本轮临时执行规则；证据不足但可能复用的，写入待验证经验。没有这张卡，不能直接要求 sing_control_writer 按旧规则重写 style prompt 或 controlled lyrics。

演唱控制 writer 规则归因与写回卡必须具象，不得只写“更贴合歌词、更有情绪、更高级”。最低字段：

```text
评审缺点：具体指出 style prompt、controlled lyrics、人声、配器、段落动态、hook 处理或生成风险的问题。
为什么会出现：旧 sing_control_writer 是因为风格标签堆叠、人声 POV 判断不足、段落能量表缺失、歌词 hook 未继承、controlled lyrics 过控，还是声场审美和歌词情绪错配。
触发条件：以后什么曲风、歌词状态、段落结构或投喂方式下会再次出现同类问题。
错误机制：它会怎样伤害生成结果，例如盖住尾音、削弱副歌、让 Bridge 变平、让 Final 不升、让人声像模板歌。
本轮新增 / 修正的 sing_control_writer 规则：用一条可执行规则写清默认怎么做。
写入位置：sing_control_writer、sing_control_repair、共享资产、当前作品临时规则或待验证经验。
写回证据：如果写入稳定文件，写明实际文件路径和段落标题；如果只写入当前作品临时规则或待验证经验，说明不升级为稳定规则的原因。
同步检查：如果新增的是生成规则，判断 sing_control_repair 是否也需要新增检查项；若不同步，说明原因。
writer 继承证据：记录 sing_control_writer 改稿前继承了哪些新增 / 修正规则，以及改稿后 style prompt / controlled lyrics 哪些位置证明规则已经生效。
writer 改稿前自检问题：下一版 style prompt / controlled lyrics 动手前必须逐项回答什么。
```

例：评审说“副歌没出来”，诊断官不能只转述为“增强副歌”，而要判断是人声没有抬近、鼓组没有打开、和声没有进入、hook 行没有行级控制、还是 controlled lyrics 把副歌切碎，并把具体规则交给 sing_control_writer。

没有写回证据的“规则归因与写回卡”不完整。阶段文件里只写“建议写入 sing_control_writer / 当前作品临时规则”，但没有实际路径、规则状态、不升级原因和 writer 继承证据，不能标记为完成自我优化，也不能把下一版投喂文本称为“按进化后规则重写”。

正式小循环遵守项目硬门：

```text
正式隔离评审只隔离“评审官评价动作”：style prompt 和 controlled lyrics 的生成 / 修改仍在当前环境执行；评审官必须有真实独立 Agent / sub-agent 返回；最终打分、归因和交接由当前环境诊断官完成。
没有真实 Agent 返回时，只能标记为诊断模式或待评审输入包。
不能把单上下文模拟写成正式隔离评审。
不能因为有评分表就冒充正式终稿。
不能让评审官互看意见，不能让评审官先读诊断官预设结论。
```

本 skill 即使在正式隔离评审后，也只负责输出评审诊断和 writer 交接单，不负责执行修改。采纳、重写、投喂版由 `laohu_sing_control_writer` 在收到交接单后完成。

Agent 评审输入必须包含：

```text
完整确认歌词。
完整初稿 style prompt。
完整初稿 controlled lyrics。
符号说明。
评审目标：判断模板化、遮挡歌词、人曲割裂、分段控制、气口和 hook 处理。
禁止：改歌词正文，引用其他评审官意见，直接替执行官写终稿。
```

## 6. 反馈写回边界

本 skill 吸收的是“演唱控制评审能力”和“评分能力”，不是初稿生成技巧。

应该写入本 skill：

```text
如何找 style prompt 和 controlled lyrics 的缺点。
如何区分普通风格选择和 AI 模板缺陷。
如何打分、扣分、解释扣分证据。
如何把问题交接给 writer，而不是自己改。
```

应该写入 `laohu_sing_control_writer`：

```text
收到诊断单后如何重写 style prompt。
如何根据评分短板补齐风格、配器、人声、声场和 controlled lyrics。
如何输出修改后版本和自检。
```

应该写入共享资产：

```text
跨作品稳定成立的配器、人声、声场、平台投喂格式和类型化声音经验。
```

单次作品偏好只写当前作品复盘，不升级成通用硬门。

## 7. 失败模式表

```text
触发条件：用户要求“检查/打分/评审”，但输入缺 style prompt 或 controlled lyrics。
处理：列缺失项，只能局部诊断已有对象，不补写缺失对象。

触发条件：歌词本身韵脚、句长、气口或乐段功能不合格。
处理：说明声音无法修复歌词问题，交回歌词链路；不建议靠气声、混响、和声硬救。

触发条件：用户要求本 skill 直接修改。
处理：先给诊断交接单，再路由 `laohu_sing_control_writer` 执行；本 skill 不输出改后文本。

触发条件：评分想因为“流行/钢琴/吉他/克制”扣分。
处理：先判断是否有适配缺失；没有缺失则不扣。

触发条件：非说唱歌曲或非 rap delivery 段落出现 spoken / almost spoken / talk-sing / recitative / spoken-like。
处理：判为旋律控制误用，说明会造成念白化和 hook 旋律弱化；交给 writer 改成 melodic / sung / phrasing 类控制。若风格或段落明确是说唱，则不扣。

触发条件：评审意见互相冲突。
处理：按歌词清晰度、核心句让位、生成稳定性、段落功能优先排序，交给 writer 做执行取舍。
```

## 8. 反例黑名单

- 不要重写歌词正文。
- 不要输出最终 style prompt。
- 不要输出最终 controlled lyrics。
- 不要把评审诊断写成制作术语清单。
- 不要因为普通流行风格本身扣分。
- 不要把“更高级”作为修改方向，必须拆成具体声音动作。
- 不要让本 skill 既当裁判又当改稿执行者。
