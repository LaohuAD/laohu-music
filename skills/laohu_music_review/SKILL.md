# laohu_music_review

你负责音乐创作第六阶段：审查、复盘和经验整理。

注意：经验沉淀不是只在最终复盘时发生。老胡在任何阶段指出的疑似长期有效经验，都应当实时进入五项测试和规则状态判断；通过后再写入对应 skill、共享资产、流程文件、当前作品复盘或规则进化备忘录。最终复盘只负责整理作品级结果、生成反馈和发布反馈，不承担唯一的经验吸收职责。

## 审查对象

- 选题题眼。
- 曲式与风格。
- 歌词。
- 歌词优化过程。
- 最终 style prompt。
- 演唱控制。
- AI 平台生成结果。
- 发布包装和反馈。

本 skill 必须独立完成审查、复盘和经验回流判断。共享资产只用于补充校验和决定规则应该写回哪里。

## 基础审查复盘能力内核

本 skill 的下限不是写总结，而是判断作品链路哪里真的影响了结果，并把经验写回正确位置。即使不读取任何共享资产，也必须自带以下能力：

```text
区分作品问题、阶段问题、skill 基础能力问题、共享资产上限规则问题和单次审美偏好。
检查题眼、曲式、歌词、演唱控制、生成结果之间是否一脉相承。
判断失败来自方向错、词不行、唱不顺、风格泛、prompt 泛、控制过密、平台生成偏差，还是发布包装问题。
每条疑似长期有效经验都要先过五项测试、标注规则状态，再决定写回哪里：对应 skill 本体、共享资产、类型经验、规则进化备忘录或作品复盘。
不能把所有经验都塞进共享库；凡是通过测试后确认决定某阶段下限的，必须写回对应 skill。
```

经验分流下限：

```text
影响阶段初稿下限，且通过五项测试 → 写回对应 skills/laohu_*。
影响多个阶段协作和停止条件，且通过五项测试 → 写回 AGENTS.md / 核心规则 / 流程文件。
影响特定风格、题材、词池、长案例 → 写回共享资产或案例库。
只来自一次偏好但有价值 → 写入当前作品复盘或规则进化备忘录。
已经被两次以上验证的同类问题 → 复测边界和冲突后，升级成正式 skill 规则或共享规则。
```

### 规则进化审查硬门

复盘和审查不能把老胡反馈、评审意见或发布数据直接写成永久规则。每条可复用观察必须先完成五项测试，并标注规则状态。

```text
真实目标测试：这条反馈真正要解决作品质量、创作体验还是长期系统问题？
事实与逻辑测试：它是否有证据，是否有反例，是否过度概括？
适用边界测试：它适用于所有作品、某类题材 / 曲风 / 平台，还是当前个案？
冲突测试：它和已有硬门、流程、共享资产、案例经验是否冲突？
写入层级测试：它进入 writer、repair、review、共享资产、质量系统、案例库、当前作品复盘，还是规则进化备忘录？
```

规则状态：

```text
候选规则：证据不足但值得观察。
临时执行规则：先在 1-3 次作品中试用。
稳定规则：多次验证有效，或一次强反例证明硬门缺失。
争议规则：有用但场景边界明显，不能进入基础内核。
淘汰规则：误导创作，需要删除、降级或迁出核心执行区。
```

规则权限：

```text
拦截级：不通过就不能进入下一阶段，必须内部重写或退回上游。
流程级：改变执行顺序、停止条件、确认门和写回路径。
诊断级：用于 repair / review 定位问题和归因。
增强级：提高上限，适用于特定题材、曲风、平台或案例。
记录级：当前作品观察、待验证线索或一次性偏好。
```

五项测试前必须先给出底层逻辑提取：

```text
表层反馈：这次被指出的具体问题。
真实表达：老胡真正要求系统以后避免或做到的事情。
共同错误结构：换作品、换阶段、换文件后，同类问题会怎样再次出现。
底层破坏点：它破坏作品质量、创作体验、流程责任、文件职责或规则分层中的哪一项。
默认行为改变：哪个 skill、共享资产或流程文件下次要提前判断、拦截、追问、迁移、降级或删除。
```

写回前必须同时给出正向测试和反例测试：

```text
正向测试：什么输入、什么作品状态下，这条规则应该触发，并让产物变好。
反例测试：什么情况下看起来相似，但不应该触发；否则会误伤哪类作品。
```

canonical 规则源原则：

```text
同一条稳定规则只能有一个主源文件。
writer skill 存本阶段下限硬门和执行流程。
repair / review skill 存诊断、归因、修复和写回动作。
共享资产存上限增强、长案例、类型经验和词池。
流程文件存跨阶段交接、停止条件和协作协议。
如果一个反馈同时影响多个文件，必须先判断主源，再只在其他文件写短入口或路由，不复制整段规则。
```

如果发现旧规则互相冲突，必须先做冲突消解：哪条更底层、更普适、更能保证作品成立；哪条只是特定风格或场景增强。不能把冲突规则全部保留在 skill 本体里让模型自行猜。

复盘输出必须说明：哪些经验升级为硬门，哪些只是增强资产，哪些只进备忘录，哪些旧规则被降级或淘汰。不得把所有经验都塞进共享资产，也不得把单次偏好写进 writer 硬门。

共享资产调用边界：

```text
经验归因、写回位置、下限 / 上限判断 → 本 skill 本体直接执行。
rubric、盲预测、T+N 复盘、质量分数 → 读取质量评估与预测系统。
各阶段专项审查细则 → 命中阶段后读取对应音乐语言资产。
```

## 必须检查

- 题眼是否兑现。
- 副歌核心句是否仍保持原意。
- 曲式是否服务情绪。
- 风格是否匹配人物、题材和传播场景。
- 歌词是否可唱、可记、有真人痕迹。
- 演唱控制是否突出传播资产。
- style prompt 是否具体，不 generic。
- 老胡反馈是否已经沉淀到执行规则。
- 是否存在生成前或发布前预测；如果存在，复盘必须逐条清算哪些预测被验证、哪些被推翻。
- 是否触发质量 rubric 的边际细化、待验证假设或正式 bump。

## 外部创作者视角复盘

复盘时按问题命中选择 0 到 4 个视角做反向检查。没有命中具体问题时，不为凑格式调用视角；材料已经能直接定位责任环节时，先完成链路归因和写回动作。

- Rick Rubin 视角：哪些句子、编曲、标签或情绪堆叠其实可以删掉。
- Max Martin 视角：副歌 hook、重复、旋律入口和短视频切片是否真的可复唱。
- 李宗盛视角：作品是否有人味、年龄感和真实关系代价。
- 罗大佑视角：作品是否触到更大人群或时代情绪，还是只停在个人小感动。
- 陈奕迅 / Billie Eilish / 张惠妹 / Adele 视角：生成结果的人声是否兑现了叙事、贴耳或爆发任务。

复盘结论要写清：本次哪些人物视角被验证有效，哪些视角误导了作品，哪些反馈通过了五项测试，哪些应该写回 skill、共享资产、当前作品复盘或规则进化备忘录。

外部创作者视角只做反向审查工具，不单独强制输出完整视角调用卡。确实影响了诊断结论或写回动作时，只折叠进“主要问题”和“写回动作”：

```text
调用视角：哪个视角发现了哪个链路问题，这条经验通过五项测试后的状态是什么，应该写回哪里。
```

如果复盘无法说明人物视角带来的具体变化，必须标记为“本次视角调用无效”，并写入待验证假设，而不是假装有用。

## 复盘结果优先输出硬门

本 skill 的主产物不是漂亮总结，而是定位问题、决定写回位置、完成规则回流。用户可见输出必须先给结论，再给证据。

默认输出顺序：

```text
1. 一句话总判断：本次失败 / 成功主要卡在哪个环节。
2. 链路归因：选题、曲式、歌词、演唱控制、生成平台、发布包装分别是否负责。
3. 最影响结果的 3 个问题：每个问题必须有证据、影响和修复方向。
4. 经验写回动作：写回哪个 skill、共享资产、作品复盘或规则进化备忘录。
5. 不写回的现象：哪些只是单次偏好、单次平台偏差或证据不足。
6. 下一次生成前必须改什么：最多 3 条。
7. 需要老胡补充的材料：只问会改变归因的缺失信息。
```

禁止的复盘形态：

```text
先写大量视角调用、rubric 术语和流程说明，最后才说问题在哪。
只说“歌词不够好 / prompt 太泛 / 情绪不够”而不判断具体责任环节。
把所有经验都塞进共享资产，绕过对应 skill 本体。
把单次主观偏好直接升级成通用硬门。
只复盘成功经验，不处理失败样本。
```

## 审查维度

- 表层需求是否被正确识别。
- 真实表达目标是否在题眼、副歌和曲式中保持一致。
- 根本目的是否服务生成可用性、发布价值和后续迭代效率。
- 选题题眼是否像情绪发动机，而不是营销标题。
- 副歌核心句是否有记忆点、唱感和情绪代价。
- 单句评判是否先说明乐段位置和功能。没有说明是主歌、副歌、Bridge 还是尾句，不得直接判“具体更好”或“抽象更差”。
- 抽象情绪词是否被感官、修辞、韵脚或前文证据托住；具体物件是否真的带出情绪、关系压力和声音回环，而不是只陈述事实。
- 都市信息类低情绪物件是否完成映射替换。手机界面、平台动作、办公通勤、短剧都市空间、家居边界物、消费工具和高频 AI 都市素材，如果没有时间磨损感、自然情绪、年代感、生活痕迹、身体感受或关系压力，必须判断是否该用更有情绪附加值的系统替代。时间磨损感不是必须写老东西，而是要有反复使用、等待、错过、季节经过、关系变化、身体反应或记忆残留。五感、光影、季节、天气、旧物磨损、声音残留或身体反应只是常用入口，也可以来自自然景物、年代物件、地域痕迹、旧习俗、公共记忆、家庭物件、职业痕迹和交通声响；替换后不能丢掉原动作的关系功能。
- 核心情绪词是否有必要的人称归属。该写“你的温柔、我的悲伤、他的称呼、她的祝福”时不能省成泛情绪；归属词必须让关系更痛，而不是只补字数。
- 词性骨架是否成立。核心句优先由代词、动词和具象名词承担情绪：代词锁关系，名词铺底色，动词见情绪。若高潮主要靠形容词、副词和抽象名词堆出来，或人称漂移、名词无情绪底色、动词太弱，必须判为语言骨架风险。
- 修辞是否匹配曲风、乐段和题眼。大众流行情歌优先比喻、拟人、反复；古风 / 国风可用对偶、借代；民谣 / 走心治愈应轻修辞；励志 / 热血可用反复、排比、夸张；通感、双关、反语只做点睛。每个核心修辞必须服务画面、情绪、人物、推进、hook、声音记忆、韵脚或唱感，且一句歌词主用一种修辞，避免修辞过载和伪诗意。
- 曲式是否让副歌变得必然。
- 曲式模板是否明确，是否服务题眼和传播目标。必须检查本歌采用 V+C、标准流行、无 Pre 简约流行、循环短句、抒情慢歌 / 民谣加长铺陈，还是自定义结构。
- 歌曲是否同时完成重复和对比：Chorus / Hook 是否形成记忆重复，Verse 2 / Bridge / Final Chorus 是否提供变化、翻面或加重。
- 各乐段功能是否兑现：V1 建立人物和场景，Pre 收紧情绪，Chorus 释放核心句，V2 推进而不复述，Bridge 翻面而不装饰，Outro 回收而不作文总结。
- 歌词是否有真人痕迹和可唱句尾。
- 风格是否有细分判断，不是通用抒情模板。必须检查文本风格三要素：题材、意象体系、语言语感；曲式不能单独证明风格成立。国风看语体和古典意象，说唱看短句、押韵、flow，民谣看生活叙事，R&B 看贴耳私密和重复变体，摇滚看态度和强动词，电子看循环短语，励志看阻力和行动，复古看年代语感，独立看个人化逻辑。
- 演唱控制是否突出传播资产，而不是堆标签。
- 失败样本暴露的是词、曲、唱、平台提示词还是审美方向问题。
- rubric 维度是否高估或低估了当前作品。
- 当前观察属于单次观察、待验证假设、跨作品观察还是可沉淀规律。

## 经验回流

经验不能凭一次感觉直接回流。必须先完成五项测试并标注规则状态，再判断是否可跨作品复用。

如果经验可跨作品复用，按写入层级测试决定写入：

- `02_共享资产库/02_音乐语言资产/`
- `02_共享资产库/03_质量评估与预测系统/`
- `02_共享资产库/04_案例经验库/`
- `02_共享资产库/05_工具流程/`
- 对应 `skills/laohu_*`

如果只属于当前作品，写入当前作品 `09_归档复盘.md`。

## 规则升级门槛

```text
单次偏好：
只来自老胡一次审美选择、单条评论、单个平台生成结果。
写入当前作品复盘或规则进化备忘录，不写入通用 skill 硬门。

待验证假设：
同一问题有明确证据，但还没有跨作品重复出现。
写入规则进化备忘录，标记下一次验证方式。

跨作品规律：
至少两首作品或两次独立生成暴露同类问题，且原因一致。
写入共享资产或类型化评审经验库。

正式规则：
问题会稳定破坏题眼、唱感、生成可用性、发布价值或评审隔离。
写入对应 laohu_* skill 或核心共享规则，并说明替代做法。
```

实时规则：

- 阶段中发现执行错误，先判断它属于硬门缺失、执行流程错误还是单次操作失误；硬门或流程缺失才立即改对应 skill 或流程文件。
- 阶段中发现创作质量门缺失，先判断它是基础下限还是上限增强；基础下限改对应 skill，上限增强改共享资产。
- 阶段中发现当前作品状态变化，立即改 `00_阶段确认记录.md`。
- 阶段评审找出初稿缺陷后，必须追问“为什么上游初稿 skill 没有提前避免”。
- 选题评审问题默认先归因到选题初稿链路；歌词评审问题默认先归因到歌词初稿链路；演唱控制评审问题默认先归因到声音控制初稿链路。归因后再通过五项测试决定是否写回对应 writer skill。
- 类型化经验写入 `02_共享资产库/04_案例经验库/类型化评审经验库.md`，不要硬塞进主 skill。
- 如果只是当前作品的单次偏好，写入当前作品复盘或规则进化备忘录；如果五项测试确认是硬门缺失，不能只写备忘录，必须即时改正式规则。
- 不把所有经验都留到最终复盘再总结。

## 失败模式表

```text
触发条件：没有完整链路材料
一线处理：只复盘已给出的阶段，列出缺失材料。
兜底：不得写成完整作品复盘。

触发条件：只有单次反馈或单条评论
一线处理：标记为单次观察或待验证假设。
兜底：不得直接写成通用硬门。

触发条件：生成失败原因不明
一线处理：按词、曲、唱、平台提示词、审美方向拆分可能归因。
兜底：写入待验证假设，不强行归因。

触发条件：发现硬门缺失
一线处理：补做五项测试，确认是基础下限硬门还是上限增强；再写回对应 skill、共享资产或流程文件。
兜底：不能只写“下次注意”。
```

### 🔴 CHECKPOINT / 🛑 STOP

```text
STOP 1：材料不足时，只能做阶段审查或问题卡，不写完整复盘名义。
STOP 2：单次现象没有跨作品证据时，只能进待验证假设，不直接污染通用规则。
STOP 3：发现疑似长期有效硬门时，必须完成五项测试、规则状态和写回位置判断，不能只留在复盘里。
```

## 反例黑名单

- 不要只写“本次效果不错”。
- 不要只评价歌词，不看曲式、风格和演唱控制。
- 不要把失败样本丢掉；失败样本是下一次少犯错的资产。
- 不要把只属于某一次作品的偶发现象写成通用规则。
- 不要把平台生成失败全部归咎于歌词或全部归咎于 prompt。
