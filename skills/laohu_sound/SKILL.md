# 老胡声音提示词

## 核心职责

把人声歌曲的锁定歌词，或纯音乐的用途与形式命题，发展成可供外部音乐平台生成的声音方向和提示词包，并根据真实外部音频做定向修订。本Skill处理提示词假设，不生成音频，不把预期听感写成已经听见的事实。

## 必须读取

```text
AGENTS.md
当前 state.yaml
当前 work.md；人声歌曲读取锁定歌词、核心句和用户声音要求，纯音乐读取用途、身体/情绪弧、主题动机和形式要求
knowledge/creative-core.md 的听众原则；人声歌曲同时读取人物原则
knowledge/sound-prompt.md
少量相关个人声音偏好记录
```

## 模式

```text
music_fragment
sound_direction
sound_package
external_audio_revision
```

一次只激活一个模式。默认不创建声音Writer池、Selector或文本A&R。

先按 `state.work_type` 进入 `vocal_song` 或 `instrumental` 分支。旧状态缺少字段时只为兼容视为 `vocal_song`。纯音乐不是删除主唱的人声歌曲，不执行歌词锁、人物称呼、主唱、咬字和Controlled Lyrics逐字符规则。

## 模式零：`music_fragment`

### 适用输入

用户已经拥有旋律、节奏细胞、groove、riff、和声、主题动机、演唱动作或局部编曲，并希望只炼片段，或把片段发展成完整提示词包。输入按 `schemas/music-fragment.schema.json` 记录种类、表达、上下文作用、权威、锁定维度和开放维度。

### 权威与分支

- `user_locked` 片段只读；发现硬冲突时请求扩大权限，不暗改。
- `user_editable` 只修改 `open_dimensions`，锁定维度不得被候选顺手改变。
- `locked_dimensions` 与 `open_dimensions` 不得重叠；重叠时先请求用户明确，不自行解释优先级。
- 人声歌曲发展完整包时读取锁定歌词，保护承重字、重音和气口；只炼片段不强迫补完整歌词。
- 纯音乐不得使用 `vocal_action`，也不得把 `lyrics` 或 `vocal_action` 列为开放维度。
- 自然语言 `description` 可以作为原始灵感进入；若目标是正式炼制片段，最终要转成与种类相符且人能复核的级数、音程轮廓、节奏格、和声功能、罗马数字或段落图。没有音频时仍是结构假设，不声称试听。

### 两种目标

```text
只炼片段：确认片段作用与保护项 → 只发展开放维度 → 回测必要歌词/形式上下文 → 交付结构化片段并停止
发展完整包：确认片段权威 → 将其写入work.md保护资产 → 进入sound_direction → 完整回装与外部生成验证
```

只炼片段时最多给三个实质候选；候选必须改变真实音乐关系，不用形容词换皮。用户选择后追加 `music_fragment_refined` 事件，保持 `sound_choice` 阶段，并把下一动作设为继续炼另一片段、进入完整声音方向或停止。局部成立不能冒充完整提示词包成立。

## 模式一：`sound_direction`

### 目标

把歌词与听众用途，或纯音乐的用途与身体/情绪弧，转成2-3个可选择的完整声音主张，而不是先生成多套长提示词。

### 每个方向包含

- 目标听众和主要使用场景。
- 主唱年龄感、音区、音色、距离和唱法。
- 3-7秒最高记忆单元及主要组件。
- 核心句的旋律或节奏轮廓。
- groove和身体脉冲。
- 主要和声色彩。
- 核心配器职责和让位。
- Verse、Pre、Chorus、Bridge/替代段和Final的主要差异。
- 为什么男女人物和关系边界仍成立。
- 最大外部生成风险。

方向差异必须来自人物身体、记忆机制、形式或声音空间。只换流派、BPM或乐器不构成新方向。

`instrumental` 方向用以下内容替换人声与歌词专属项：主要使用场景、听众注意与身体动作、一个最高主题动机家族、形式段落及时间变化、groove/和声、核心配器与音色职责、转场、高潮/非高潮策略、结尾和最大生成风险。主题动机可以是旋律、节奏细胞、groove、和声转折或音色签名，但仍只能有一个最高中心。

### 用户选择

AI推荐一个完整方向并说明证据。用户可选一个方向，或要求调整一个从属维度。只有AI证明调整不制造第二中心和字段冲突时才能组合；不得让用户任意拼装各方向的局部亮点。

选择后写入 `state.locked.sound_direction_id`，进入 `sound_package`。

## 模式二：`sound_package`

### 前置

- 声音方向已锁定。
- `vocal_song`：歌词已由用户锁定。
- `instrumental`：用途、主题动机方向和实际形式已确认，不要求歌词。
- 外部平台已知则使用其稳定语法；未知时采用保守标准标签。

### 生成顺序

1. 人声歌曲冻结歌词正文并建立逐字符基准；纯音乐冻结用途、主题动机和形式承诺。
2. 明确一个最高声音记忆中心和所有从属声部。
3. 人声歌曲确定主唱身份、旋律轮廓、groove、和声、配器和乐段动态；纯音乐确定主题动机、形式、groove、和声、配器、音色和动态。
4. 生成正向、集中、可执行的Style Prompt。
5. 人声歌曲生成控制稀疏的Controlled Lyrics；纯音乐生成可执行的Instrumental Form。
6. 人声歌曲剥离标签后逐字符比对歌词；纯音乐复核形式、动机和提示词一致。
7. 写平台假设、最小标签降级和外部验证项目。

### Style Prompt

两条分支都只写平台可执行的流派/融合、速度拍号、groove、最高记忆、核心乐器职责、形式动态、声场和结尾；人声歌曲再写主唱，纯音乐写主题动机与器乐形式。删除创作解释、营销口号、禁止清单、互相冲突标签和无法执行的散文。

### Controlled Lyrics

- 标准乐段标签。
- 行控只用于核心Hook、角色变化、必要停顿、动态或结尾。
- 不增加歌词、解释台词和第二人物。
- 不逐行控制。
- 剥离控制后与锁定歌词逐字符一致。

本节仅适用于 `vocal_song`。

### Instrumental Form

本节仅适用于 `instrumental`。按实际形式描述每段的主题动机状态、主要变化曲线、groove/和声职责、配器进入退出、转场和结尾；不用Verse/Chorus标签机械代替形式变化，不增加人声、歌词或空的Controlled Lyrics。

### 平台降级

人声歌曲若平台误唱行控，先删除独立行控；仍不稳定时缩为标准乐段标签。不得为平台解析修改歌词。纯音乐只保留平台能够执行的形式控制；平台不支持细分结构时压缩形式，不虚构歌词控制。

### 交付

输出一套完整包，不提供三套长包再评审。明确哪些属于生成假设，哪些只有外部音频能验证；人声歌曲另标真人试唱风险。为该包创建初始 `prompt_revision_id`，在修订纪录中保存正文 hash、初始来源和需要外部验证的可观察变化，然后等待用户外部生成。

## 模式三：`external_audio_revision`

### 输入

用户可以提供一个或多个 `audio_run_id`、音频路径、整体感受或具体时间点反馈。同一 `prompt_revision_id` 可以拥有多个外部生成结果，用来区分稳定问题和平台随机性。

用户不必知道或报出这些 ID。当用户只说“这次生成”、提供音频文件或用文字复述听感时，系统应为外部结果登记 ID，并关联当前提示词版本。只有关联真的无法判断时才问用户，不把内部编号变成使用负担。

用户文字感受始终是有效主输入。当前环境确实具备音频工具时可以补充技术分析，并明确能力模式；不能读取或理解音频时使用 `user_text_only`，不得补写没有听见的事实。

### 诊断顺序

```text
实际听见/用户明确描述什么
→ 原提示词要求什么
→ 差异落在哪个词、乐段、声音或结构
→ 归因属于平台未遵从、提示词冲突、声音方向、作品输入或个人偏好；人声歌曲再区分歌词和歌手音区
→ 最早能够改变结果的字段
```

### 修改权限

- 字段或解析问题：修改具体字段与标签。
- 同一声音方向内的主唱、旋律、groove、和声、编曲问题：定向修改对应职责。
- 声音命题或最高记忆错误：返回 `sound_direction`，不靠加标签掩盖。
- 人声歌曲的歌词问题：请求用户解锁并返回歌词阶段；禁止暗改。纯音乐没有这一返回项。
- 平台能力限制：记录外部证据，不把模型限制升级成通用音乐规则。

每个反馈周期先把观察标成 `keep`、`change` 或 `uncertain`。修订前明确三件事：

1. **保留资产**：本轮已成立且不应被连带破坏的听感或提示词决定。
2. **单一修改组**：可以同时改多个字段，但它们必须服务同一个根因，并在 `modification_group` 里记录 `target_fields`、`changes` 和 `reason`。
3. **可反驳预期**：用 `expected_observable_changes` 说清新音频中应该听见什么变化，下轮用真实结果验证，不用“更好”自证。

然后创建新的 `prompt_revision_id`，关联父版本、本轮反馈事件和来源 `audio_run_id`，并等待新音频。用户可以进行多轮循环；没有新证据不继续凭文字想象修复。同一根因跨多轮复发时返回声音方向、平台能力或歌词权限层。

用户明确认可当前外部结果和提示词包时，执行 `accept_sound_package`，把当前版本标为 `accepted`并结束循环。用户只是暂时不再生成时记为暂停，不伪造接受。系统不能因为轮数多、已经投入很多或没有时间而自动通过。

## 写回

1. 更新 `work.md` 的声音方向或当前正式提示词包。
2. 追加选择、生成、提示词修订、外部结果或接受事件。修订事件的 payload 遵守 `schemas/prompt-revision.schema.json`。
3. 更新 `state.yaml` 阶段、锁定项、`sound_iteration` 和下一动作。
4. 外部结果可提交 `laohu_learning`，但不能自动变成长期规则。
5. 运行项目校验；人声歌曲追加歌词逐字检查，纯音乐追加形式一致检查。

## 红线

- 没有音频时不等待、不声称试听。
- 不假设所有智能体都能听懂音频；必须声明实际分析能力。
- 不生成多套完整包进行AI互评。
- 不任意拼接方向。
- 不用更高、更响、更宽替代人物和Hook因果。
- 不增加男声、和声角色或关系事实越过歌词授权。
- 不为平台方便改歌词。
- 不把纯音乐当作删除主唱的人声歌，不生成空Controlled Lyrics。
- 不把一次生成失败写成永久禁令。

## 完成

人声歌曲要求歌词逐字一致、人物和声音方向一致、Controlled Lyrics控制稀疏；纯音乐要求用途、主题动机、实际形式和Instrumental Form一致。两条分支都要求一个最高记忆中心、Style Prompt正向集中、平台风险与降级明确。此状态只表示可进入外部生成，不代表音频或发行已经成立。
