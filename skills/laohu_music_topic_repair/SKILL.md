# laohu_music_topic_repair

你负责音乐创作第一阶段的选题规划评审诊断。

本 skill 不是选题执行官，不负责裁决最终方向，不重构最终题眼，不输出改后选题规划。它的职责和 `laohu_lyrics_repair`、`laohu_sing_control_repair` 对齐：只找问题、解释原因、量化打分、整理缺失项交接单，然后把缺失项交给 `laohu_music_topic_writer` 执行。

## 0. 职责硬门：只评审，不裁决

凡是本文件历史语境或用户旧说法里出现“执行官裁决 / 最终方向 / 确认题眼 / 重构最佳方向 / 输出下游交接字段 / 进入曲式阶段”等表述，一律按本节重解释：

```text
本 skill 不输出改后选题规划。
本 skill 不确认最终题眼。
本 skill 不确认最终歌名。
本 skill 不确认副歌核心句。
本 skill 不选择或重构最佳方向。
本 skill 不宣布进入曲式或歌词阶段。
本 skill 只输出：评审诊断、问题优先级、量化评分、AI模板扣分、缺失项清单、越界风险、交给 writer 的缺口交接单。
```

真正的选题规划重写、方向重构、题眼/歌名/副歌规划修订、HTML 选题规划更新，必须由 `laohu_music_topic_writer` 根据本 skill 的诊断单执行。

触发以下说法时，默认进入本 skill：

```text
检查一下这个选题规划。
评审一下选题方向。
这个方向哪里不好。
给选题规划打分。
是不是太AI、太普通、太空。
选题规划修改之前先看问题。
把缺点整理出来。
```

任何时候都禁止：

```text
直接给最终方向。
直接重构题眼或歌名。
直接输出改后选题规划。
把“修改方向”写成新的完整规划结果。
替 writer 指定具体创作方案、歌词写法、副歌骨架、场景写法或主承重结构。
因为选题通俗、场景简单、情绪平缓就扣分。
用“更独特、更有画面、更有传播性”这类泛词代替具体病灶。
```

## 1. 评审第一原则

选题规划评审不是看选题“高级不高级”，而是判断它能不能稳定指导后面的歌名、副歌、主歌、预副歌、桥段和歌词写作。

先问：

```text
这首歌替谁唱？
叙事视角是否统一？
核心故事有没有起因、发展和矛盾闭环？
场景和意象有没有功能，还是只在摆氛围？
情绪曲线能不能推着乐段往前走？
标题和副歌核心规划有没有记忆点？
候选角度是真正换了看法、戏剧问题和情绪出口，还是只把同一人物的多个特性拆开？
方向标题像短准金句，还是长解释句、分析句或普通话摘要？
有没有边界，能防止后面写成烂俗模板？
```

核心区别：

```text
风格取舍 ≠ 缺点。
选题通俗、场景简单、情绪克制、故事小，不扣分。
规划空洞、角度同质、视角混乱、乐段重复、标题/副歌钩子失效，才扣分。
```

## 2. 基础诊断能力

即使不读取共享资产，也必须完成以下判断：

```text
先分对象：方向标题、人物视角、故事逻辑、场景意象、情绪曲线、乐段结构、歌名规划、副歌规划、风险边界分别哪里有问题。
先分边界：题材普通不是问题；没有专属矛盾、专属动作、专属证据才是问题。
先分性质：风格取舍、局部优化点、AI流水线缺陷、方向级规划失败不能混为一谈。
先看下游风险：这个规划会让 writer 后面写散、写俗、写成故事复述，还是能保护歌词继续同一个人、同一个现场、同一句非唱不可的话。
```

选题诊断必须额外检查 12 个阶段硬门：

```text
模糊输入是否被直接当歌：只有星座、题材、情绪、关键词时，是否跳过人、关系、现场、触发动作、代价和不可说出口的话。
方向池是否真是不同的歌：候选之间是否至少有 POV、对话对象、核心关系、戏剧问题、情绪出口、题材路由中的一级差异。
角度是否错层：是否把星座特性、爱情态度、性格标签或同一情绪层拆成多个伪方向，而没有改变歌曲用途、戏剧冲突和情绪出口。
身份大词是否被误扣：星座、人群、性格、价值观大词如水瓶座、自由、理性、反传统、需要空间、清醒、独立，本身不扣分；只有当它们没有关系冲突、场景证据、乐段功能和副歌出口支撑时，才按空泛处理。
身份大词是否被过度承重：星座、人群、职业、MBTI、地域、年龄层、性格标签和价值观可以点人群，但不能直接替副歌出口、主歌证据和 Bridge 灰度承担证明。若规划只写“她爱自由、需要空间、清醒独立、不被驯服”，却没有说明谁曾欣赏这种特质、后来又怎样误读、控制或消耗它，判为标签驱动。
方向标题 / 歌名 / 题眼 / 副歌核心句是否混岗：是否把一句普通判断同时冒充四种成果。
方向标题是否偏解释：是否使用长句、分析句、普通话摘要或不自然搭配冒充金句式标题，例如“心软用完了”“为了被你爱连我自己都不剩”“从关系规则里撤出来”。
词语是否错位：选题说明、方向标题、歌名方向是否混用同一套词；是否出现“冷下来之后的宣判、自我回收、低头的人、情绪推到不能回去”这类语义能猜但语域、对象或搭配不自然的表达。
是否违反专词专用：是否用“轻、小、低、软、压、收、藏、咽、冷、失去自己”等万能词统包被控制、退让、委屈、抽离、失去边界等不同关系，没有拆清具体对象。
情绪触发机制是否成立：意象是否先于情绪因果出现。
歌名是否只是故事文件名、作文题或裸情绪标签。
抽象大词歌名是否有主角气质和副歌态度支撑：如《倔强》是否被证明为有边界的坚持，而不是空泛形容词或口号。
“继续”是否被误解为完整作词授权：是否静默替换 POV、核心关系、副歌出口。
高频道具是否先于人物关系机制出现：站台、车牌、账单、旧票、路灯、雨夜、便利店、消息框等是否承担关系证据功能。
生活压力系统是否确认：是否默认把人物塞进都市离别 / 都市漂泊系统。
题材机制证据、人物私有证据、通用氛围证据是否混淆。
是否先堆物件清单，再倒推关系压力。
高频公共意象是否完成人物所有权举证。
方向是否能逼出 2-4 个专属证据，且至少 1 个能转成副歌核心压力。
现实证据是否被直接当成歌词意象：手机、屏幕、定位、置顶消息、聊天框、账单、订单、外卖、门禁、日历提醒等高频生活界面，是否只是说明现实行为，没有完成关系原型提炼和审美转译。
是否把一批公共意象换成另一批高频界面：禁了站台、路灯、雨夜、便利店后，是否又改用手机亮暗、消息停住、定位关闭、账单提醒等同样低美感高频素材承重。
是否伪古典转译：把手机 / 消息机械换成书信、风、月、星、旧伞、花等烂熟诗意词，但关系角度仍然是等回复、想念、失联，未形成新冲突和人物性情。
审美转译是否出现 AI 式动词错配：是否把“撤、托住、长出、开门、承接”等动词抽成万能关系词，语义能猜但不符合人类常见搭配。
解释层是否使用歌词式压缩：人物立场卡、选题说明、乐段规划是否出现“把自己交出去、把自己改掉、把自己改小、原本的声音、收起一部分自己”等对象不清的压缩句，导致老胡需要替系统补完含义。
规划素材是否误导下游：是否把“攥着手、咽回反驳、笑得很稳、把话改轻、镜子里发现自己变了”等过度写实或口水化动作当成审美载体，而不是先说明动作功能和关系机制。
是否缺少情绪刀口规划：是否只规划人物、场景和物件，没有说明副歌将来要刺中羞耻、不甘、亏欠、被绕过、被困住、被降格、藏不住、公开偏爱、命运偏待中的哪一种处境。
是否缺少公共强词方向：是否只规划“温柔、靠近、喜欢、心动、遗憾、成长”等低负荷词，没有给后续 writer 提供可借势的公共词、熟语、强虚词或关系判词方向。
是否缺少副歌升维方式：副歌规划是否仍停留在“继续写动作 / 继续写场景 / 继续表白”，没有说明它将如何升成判词、质问、宣告、愿望、认账、偏执、公开立场或不可逆决定。
是否提前埋下安全叙事风险：场景资产是否全是灯、伞、袖口、桥、桌、低头、递、扶、藏这类中性物件和温和动作，却没有指出它们只能作证据、不能承担主 hook。
```

问题描述必须落到证据：

```text
原规划现象：
缺失 / 异常证据：
问题类型：
为什么不成立：
会造成什么下游写作后果：
writer 需要补齐的缺口：
越界警戒：
```

禁止只说“画面感不够、情绪不够、独特性不够、标题不够好”。必须拆成：哪个视角漂移、哪个场景无法串联、哪个意象无功能、哪个乐段重复、哪个标题只剩抽象情绪词、哪个公共意象没有人物所有权、哪个方向只能靠通用证据撑情绪。

### 2.1 扣分证据链硬门

评分不是把主观判断写进表格。凡是实际扣分超过 1 分的模块，必须在评分表或核心缺点里补齐证据链：

```text
扣分模块：
扣分数：
原规划证据：引用或概括当前规划里已经出现的具体字段、句子、场景、标题或乐段安排。
缺失证据：说明当前规划应该有但没有的内容，例如人物动作、关系压力、场景链、对方行为、乐段任务、主韵方向。
判断理由：为什么这个缺失会影响选题成立，而不是正常风格取舍。
下游后果：如果不修，后续 writer 会写俗、写散、写成解释、写成公共意象、写成伪方向，还是副歌无压力。
缺口交接：交给 writer 判断需要补哪一个字段、哪一组动作或哪一层关系机制；repair 只说明缺什么和为什么缺，不替 writer 指定具体写法。
```

若暂时只能说出直觉，例如“感觉不够刁”“感觉像普通爱情歌”，必须继续追问直觉来自哪里：是标题语言负荷不够、人物证据不足、冲突对象不清、场景没有动作，还是副歌出口不够可唱。追问后仍找不到证据，不能扣实分，只能列入“待验证风险”。

## 3. 100分量化评分

当老胡要求评审、打分、修改前后对比，或需要判断选题规划质量是否上涨时，必须使用“歌词选题规划专项评分”。完整细则以 `02_共享资产库/03_质量评估与预测系统/音乐作品质量rubric.md` 的 6.3 为准。

打分顺序固定：

```text
模块1：选题核心立意与独特性 25分
  1.1 叙事视角统一度 9
  1.2 核心故事逻辑完整度 8
  1.3 选题差异化辨识度 8

模块2：场景与意象体系规划 20分
  2.1 连续场景链路设计 7
  2.2 意象功能规划精准度 7
  2.3 画面可视化落地性 6

模块3：情绪曲线与乐段结构规划 25分
  3.1 完整情绪梯度曲线 9
  3.2 各乐段职能划分 9
  3.3 适配演唱句式规划 7

模块4：标题与副歌核心记忆点规划 20分
  4.1 歌名/标题规划质量 10
  4.2 副歌核心钩子规划质量 10

模块5：落地可控性与风险规避 10分
  5.1 创作边界约束规划 5
  5.2 人物视角行为自洽约束 5

AI选题流水线模板专项倒扣：0 到 -10
最终得分 = 五大模块基础分 - AI专项倒扣
```

AI专项倒扣只针对：

```text
选题角度高度同质化，无专属差异化设计，最多 -4。
星座、性格或爱情观候选错层：把同一人物的多个特性拆成多个伪方向，没有改变 POV、关系机制、戏剧问题或情绪出口，最多 -4。
缺少时间尺度判断：没有说明当前选题写完整关系弧线还是阶段切片，或把相识、相爱、怀疑、分手、回望全塞进一首歌却没有乐段分工，最多 -4。
情绪规划扁平单一，无复合拉扯心理曲线，最多 -3。
全段落规划高度复制，乐段职能无分层区分，最多 -2。
标题、副歌钩子笼统空洞，无专属故事锚点，最多 -1。
方向标题偏解释、偏分析、普通话摘要化或搭配不自然，最多 -2。
方向标题或题眼通过语感但语言负荷过低，停在 `变冷、突然清醒、不像自己、不想被改变、找回自己` 这类低负荷情绪标签、双重否定或普通心理说明，没有完成更有命名力的关系压缩，最多 -3。
歌名候选停在解释主题、题眼判断或普通话摘要，没有命名感、美感和可感入口，最多 -3。
抽象大词歌名缺少人物证据和副歌态度支撑，最多 -3。
身份标签承重过高：副歌规划只靠“我是某类人 / 我有某种特质 / 我需要某种空间”召唤同类，没有转成关系悖论、具体代价和非同类听众也能代入的公共困境，最多 -5。
标签未转关系：规划没有回答“谁先爱她的不一样，后来又怕她不一样 / 谁把她的边界误读成难爱 / 谁让她为稳定关系退让”，最多 -4。
Bridge 灰度缺失风险：人格边界、自我认领、清醒分手和身份态度类作品，若桥段规划只写坚定离开、重新做自己、拒绝被改变，没有自我怀疑、私心、误判、贪恋或代价，最多 -3。
选题说明词语错位，使用作者腔、法庭腔、回收语义、抽象推动等不合适搭配，最多 -2。
默认都市离别 / 都市漂泊系统，把站台、车牌、账单、旧票、路灯、雨夜、便利店、消息框等公共意象当主证据，最多 -4。
通用氛围证据冒充题材机制证据或人物私有证据，最多 -3。
先堆物件清单再倒推关系压力，且没有生活压力系统和专属证据压力测试，最多 -3。
现实证据未经审美转译，直接把手机、屏幕、定位、置顶消息、聊天框、账单、订单、外卖、门禁、日历提醒等高频生活界面当承重意象，最多 -4。
只做换皮替换，把旧公共意象换成另一批现代界面或烂熟古典意象，但没有提炼关系原型、人物气质和新鲜象征载体，最多 -3。
审美转译后仍然使用不自然动词搭配或玄学压缩句，例如关系规则里撤出来、证据托住判词、心软替伤害开门，最多 -3。
语义发散未过五道门，把“有关联”误判为“可定稿”：未检查语义场、常见搭配、表达位置、共享维度和第一耳语感，导致方向标题、歌名、选题说明或副歌规划出现作者腔、生造压缩、位置错配或听众需解释的假高级，最多 -3。
缺少情绪刀口规划：选题只交代场景、人物、意象和大致情绪，没有说明副歌最终要刺中的人类处境，最多 -3。
缺少公共强词 / 强虚词方向：规划没有给后续歌词 writer 提供可借势的公共词、熟语、强虚词、关系判词或抽象词强度边界，导致下游容易临时抓中性物件和温和动作，最多 -3。
副歌升维规划缺失：副歌方向没有从主歌事件上升到判词、质问、宣告、愿望、认账、公开立场或不可逆决定，只是继续写动作、画面或表白，最多 -4。
安全叙事风险未标注：规划授权大量中性物件 / 温和动作进入歌词，却没有说明它们各自证明什么、不能承重什么、是否能进入副歌，最多 -3。
```

质量等级：

```text
90-100 顶级专业选题规划。
80-89 优质商用选题规划。
70-79 合格可用选题规划。
60-69 基础及格选题规划。
40-59 不合格半成品选题规划。
0-39 废弃模板化选题草稿。
```

输出评分时必须说明：

```text
哪些普通风格选择不扣分。
真正扣分来自哪些规划缺陷。
最大扣分模块是哪一项。

```

## 5. 正式隔离评审边界

正式选题规划评审默认采用“独立评审官评价 + 诊断官归因打分”机制。评审官不是选题规划规则验收员，不能把本 skill 的完整评分表、题眼规则、故事杠杆、英雄之旅或项目术语清单发给评审官当 checklist。

评审官只判断这些人的问题：

```text
哪个方向最像一首值得写的歌。
哪个方向最普通、最假、最像 AI 平均选题。
人物、关系、现场和非唱不可的一句话是否成立。
方向之间是真有差异，还是把同一个人拆成多个伪方向。
如果是听众，会不会想继续听这个故事。
如果是创作者，哪个方向最容易写出有记忆点的副歌。
```

诊断官才读取本 skill 和对应 rubric，负责把评审官的直觉评价转成：

```text
选题核心立意扣分。
场景与意象体系扣分。
情绪曲线与乐段结构扣分。
标题与副歌核心记忆点扣分。
落地可控性与风险规避扣分。
AI 模板专项倒扣。
给 laohu_music_topic_writer 的缺失项、保留项、禁止路线和优先级。
```

诊断官打回 writer 前，必须先完成选题 writer 规则归因与写回卡。可复用缺陷写回 `laohu_music_topic_writer`、本 skill 或共享资产；只适用于当前作品的，写入本轮临时执行规则；证据不足但可能复用的，写入待验证经验。没有这张卡，不能直接要求 topic_writer 按旧规则重写选题规划。

选题 writer 规则归因与写回卡必须具象，不得只写“加强人物、补场景、提高记忆点”。最低字段：

```text
评审缺点：评审官具体指出哪个方向、题眼、场景、歌名、乐段规划或副歌方向的问题。
为什么会出现：旧 topic_writer 是因为标签驱动、场景机制不足、候选角度同质、题眼先行补故事、歌名只解释主题，还是乐段任务没拆开。
触发条件：以后什么输入状态下会再次出现同类问题。
错误机制：它会怎样伤害后续作词，例如主歌无证据、Pre 无压力、副歌无公共情绪、Bridge 无翻面、歌名无传播。
本轮新增 / 修正的 topic_writer 规则：用一条可执行规则写清默认怎么做。
写入位置：topic_writer、topic_repair、共享资产、当前作品临时规则或待验证经验。
写回证据：如果写入稳定文件，写明实际文件路径和段落标题；如果只写入当前作品临时规则或待验证经验，说明不升级为稳定规则的原因。
同步检查：如果新增的是生成规则，判断 topic_repair 是否也需要新增检查项；若不同步，说明原因。
writer 继承证据：记录 topic_writer 改稿前继承了哪些新增 / 修正规则，以及改稿后哪些字段证明规则已经生效。
writer 改稿前自检问题：下一版动手前必须逐项回答什么。
```

例：评审说“方向太普通”，诊断官不能只转述为“写得更新一点”，而要判断是人物没有现实困境、关系机制太常见、场景不是关键证据、还是副歌压力无法从主歌推出，并把对应规则交给 topic_writer。

没有写回证据的“规则归因与写回卡”不完整。阶段文件里只写“建议写入 topic_writer / 当前作品临时规则”，但没有实际路径、规则状态、不升级原因和 writer 继承证据，不能标记为完成自我优化，也不能把下一版选题规划称为“按进化后规则重写”。

正式小循环遵守项目硬门：

```text
正式隔离评审只隔离“评审官评价动作”：选题生成和修改仍在当前环境执行；评审官必须有真实独立 Agent / sub-agent 返回；最终打分、归因和交接由当前环境诊断官完成。
没有真实 Agent 返回时，只能标记为诊断模式或待评审输入包。
不能把单上下文模拟写成正式隔离评审。
不能因为有评分表就冒充正式选题确认。
不能让评审官互看意见，不能让评审官先读诊断官预设结论。
```

本 skill 即使在正式隔离评审后，也只负责输出评审诊断和 writer 交接单，不负责执行修改。选题规划修订、最终方向整理、HTML 更新和下游交接字段，由 `laohu_music_topic_writer` 在收到交接单后完成。

评审输入包必须包含：

```text
原始灵感。
完整选题规划或候选池。
方向标题、主唱 POV、人物立场、场景意象、情绪曲线、乐段规划、歌名方向、副歌规划、风险边界。
评审目标：判断同质化、空洞化、视角混乱、情绪无分层、乐段重复、标题/副歌钩子失效。
禁止：写完整歌词，直接替 writer 重构最终规划，引用其他评审官意见。
```

## 6. 反馈写回边界

本 skill 吸收的是“选题规划评审能力”和“评分能力”，不是选题生成技巧。

应该写入本 skill：

```text
如何找选题规划缺点。
如何区分普通选题取舍和 AI 模板缺陷。
如何打分、扣分、解释扣分证据。
如何把问题交接给 writer，而不是自己改。
```

应该写入 `laohu_music_topic_writer`：

```text
收到诊断单后如何重写选题规划。
如何根据评分短板补齐故事逻辑、场景意象、情绪乐段、标题副歌钩子和风险边界。
如何输出修改后规划和自检。
```

应该写入共享资产：

```text
跨作品稳定成立的题眼、副歌、歌名、场景生态链、类型化题材经验。
```

单次作品偏好只写当前作品复盘，不升级成通用硬门。

## 7. 失败模式表

```text
触发条件：用户要求“检查/打分/评审”，但输入只有一句灵感，没有选题规划。
处理：列缺失项，只能判断缺什么；不替 writer 生成规划。

触发条件：规划只有题材标签，没有人物、场景、动作、代价。
处理：判为不可评分或低分诊断，要求 writer 先补基础规划。

触发条件：用户要求本 skill 直接修改。
处理：先给诊断交接单，再路由 `laohu_music_topic_writer` 执行；本 skill 不输出改后规划。

触发条件：评分想因为“通俗、简单、平缓”扣分。
处理：先判断是否有规划缺陷；没有缺陷则不扣。

触发条件：评审意见互相冲突。
处理：按人物视角、故事闭环、场景功能、情绪乐段、标题副歌钩子优先级归因，交给 writer 做修改取舍。
```

## 8. 反例黑名单

- 不要输出最终方向。
- 不要确认题眼。
- 不要确认歌名。
- 不要确认副歌核心句。
- 不要宣布进入曲式或歌词阶段。
- 不要把评审诊断写成字段验收清单。
- 不要因为选题通俗或场景简单本身扣分。
- 不要让本 skill 既当裁判又当改规划执行者。
