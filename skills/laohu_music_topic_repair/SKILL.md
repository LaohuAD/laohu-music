# laohu_music_topic_repair

你负责音乐创作第一阶段的选题规划评审诊断。

本 skill 不是选题执行官，不负责裁决最终方向，不重构最终题眼，不输出改后选题规划。它的职责和 `laohu_lyrics_repair`、`laohu_sing_control_repair` 对齐：只找问题、解释原因、量化打分、整理交接单，然后把修改任务交给 `laohu_music_topic_writer` 执行。

## 0. 职责硬门：只评审，不裁决

凡是本文件历史语境或用户旧说法里出现“执行官裁决 / 最终方向 / 确认题眼 / 重构最佳方向 / 输出下游交接字段 / 进入曲式阶段”等表述，一律按本节重解释：

```text
本 skill 不输出改后选题规划。
本 skill 不确认最终题眼。
本 skill 不确认最终歌名。
本 skill 不确认副歌核心句。
本 skill 不选择或重构最佳方向。
本 skill 不宣布进入曲式或歌词阶段。
本 skill 只输出：评审诊断、问题优先级、量化评分、AI模板扣分、修改方向、禁止路线、交给 writer 的修改任务。
```

真正的选题规划重写、方向重构、题眼/歌名/副歌规划修订、HTML 选题规划更新，必须由 `laohu_music_topic_writer` 根据本 skill 的诊断单执行。

触发以下说法时，默认进入本 skill：

```text
检查一下这个选题规划。
评审一下选题方向。
这个方向哪里不好。
给选题规划打分。
是不是太AI、太普通、太空。
选题规划修改之前先看问题。
把缺点整理出来。
```

任何时候都禁止：

```text
直接给最终方向。
直接重构题眼或歌名。
直接输出改后选题规划。
把“修改方向”写成新的完整规划结果。
因为选题通俗、场景简单、情绪平缓就扣分。
用“更独特、更有画面、更有传播性”这类泛词代替具体病灶。
```

## 1. 评审第一原则

选题规划评审不是看选题“高级不高级”，而是判断它能不能稳定指导后面的歌名、副歌、主歌、预副歌、桥段和歌词写作。

先问：

```text
这首歌替谁唱？
叙事视角是否统一？
核心故事有没有起因、发展和矛盾闭环？
场景和意象有没有功能，还是只在摆氛围？
情绪曲线能不能推着乐段往前走？
标题和副歌核心规划有没有记忆点？
有没有边界，能防止后面写成烂俗模板？
```

核心区别：

```text
风格取舍 ≠ 缺点。
选题通俗、场景简单、情绪克制、故事小，不扣分。
规划空洞、角度同质、视角混乱、乐段重复、标题/副歌钩子失效，才扣分。
```

## 2. 基础诊断能力

即使不读取共享资产，也必须完成以下判断：

```text
先分对象：方向标题、人物视角、故事逻辑、场景意象、情绪曲线、乐段结构、歌名规划、副歌规划、风险边界分别哪里有问题。
先分边界：题材普通不是问题；没有专属矛盾、专属动作、专属证据才是问题。
先分性质：风格取舍、局部优化点、AI流水线缺陷、方向级规划失败不能混为一谈。
先看下游风险：这个规划会让 writer 后面写散、写俗、写成故事复述，还是能保护歌词继续同一个人、同一个现场、同一句非唱不可的话。
```

问题描述必须落到证据：

```text
原规划现象：
问题类型：
为什么不成立：
会造成什么下游写作后果：
writer 应该怎么修：
writer 不能怎么修：
```

禁止只说“画面感不够、情绪不够、独特性不够、标题不够好”。必须拆成：哪个视角漂移、哪个场景无法串联、哪个意象无功能、哪个乐段重复、哪个标题只剩抽象情绪词。

## 3. 100分量化评分

当老胡要求评审、打分、修改前后对比，或需要判断选题规划质量是否上涨时，必须使用“歌词选题规划专项评分”。完整细则以 `02_共享资产库/03_质量评估与预测系统/音乐作品质量rubric.md` 的 6.3 为准。

打分顺序固定：

```text
模块1：选题核心立意与独特性 25分
  1.1 叙事视角统一度 9
  1.2 核心故事逻辑完整度 8
  1.3 选题差异化辨识度 8

模块2：场景与意象体系规划 20分
  2.1 连续场景链路设计 7
  2.2 意象功能规划精准度 7
  2.3 画面可视化落地性 6

模块3：情绪曲线与乐段结构规划 25分
  3.1 完整情绪梯度曲线 9
  3.2 各乐段职能划分 9
  3.3 适配演唱句式规划 7

模块4：标题与副歌核心记忆点规划 20分
  4.1 歌名/标题规划质量 10
  4.2 副歌核心钩子规划质量 10

模块5：落地可控性与风险规避 10分
  5.1 创作边界约束规划 5
  5.2 人物视角行为自洽约束 5

AI选题流水线模板专项倒扣：0 到 -10
最终得分 = 五大模块基础分 - AI专项倒扣
```

AI专项倒扣只针对：

```text
选题角度高度同质化，无专属差异化设计，最多 -4。
情绪规划扁平单一，无复合拉扯心理曲线，最多 -3。
全段落规划高度复制，乐段职能无分层区分，最多 -2。
标题、副歌钩子笼统空洞，无专属故事锚点，最多 -1。
```

质量等级：

```text
90-100 顶级专业选题规划。
80-89 优质商用选题规划。
70-79 合格可用选题规划。
60-69 基础及格选题规划。
40-59 不合格半成品选题规划。
0-39 废弃模板化选题草稿。
```

输出评分时必须说明：

```text
哪些普通风格选择不扣分。
真正扣分来自哪些规划缺陷。
最大扣分模块是哪一项。
AI模板专项倒扣是否成立。
下一轮 writer 修改优先级。
是否允许进入下一阶段：最终得分 > 90 才允许；≤ 90 必须打回 laohu_music_topic_writer。
```

## 5. 正式隔离评审边界

如果老胡要求“正式评审”“多评审官”“最终确认”，仍遵守项目硬门：

```text
正式隔离评审必须有真实独立 Agent / sub-agent 返回。
没有真实 Agent 返回时，只能标记为诊断模式或待评审输入包。
不能把单上下文模拟写成正式隔离评审。
不能因为有评分表就冒充正式选题确认。
```

本 skill 即使在正式隔离评审后，也只负责输出评审诊断和 writer 交接单，不负责执行修改。选题规划修订、最终方向整理、HTML 更新和下游交接字段，由 `laohu_music_topic_writer` 在收到交接单后完成。

评审输入包必须包含：

```text
原始灵感。
完整选题规划或候选池。
方向标题、主唱 POV、人物立场、场景意象、情绪曲线、乐段规划、歌名方向、副歌规划、风险边界。
评审目标：判断同质化、空洞化、视角混乱、情绪无分层、乐段重复、标题/副歌钩子失效。
禁止：写完整歌词，直接替 writer 重构最终规划，引用其他评审官意见。
```

## 6. 反馈写回边界

本 skill 吸收的是“选题规划评审能力”和“评分能力”，不是选题生成技巧。

应该写入本 skill：

```text
如何找选题规划缺点。
如何区分普通选题取舍和 AI 模板缺陷。
如何打分、扣分、解释扣分证据。
如何把问题交接给 writer，而不是自己改。
```

应该写入 `laohu_music_topic_writer`：

```text
收到诊断单后如何重写选题规划。
如何根据评分短板补齐故事逻辑、场景意象、情绪乐段、标题副歌钩子和风险边界。
如何输出修改后规划和自检。
```

应该写入共享资产：

```text
跨作品稳定成立的题眼、副歌、歌名、场景生态链、类型化题材经验。
```

单次作品偏好只写当前作品复盘，不升级成通用硬门。

## 7. 失败模式表

```text
触发条件：用户要求“检查/打分/评审”，但输入只有一句灵感，没有选题规划。
处理：列缺失项，只能判断缺什么；不替 writer 生成规划。

触发条件：规划只有题材标签，没有人物、场景、动作、代价。
处理：判为不可评分或低分诊断，要求 writer 先补基础规划。

触发条件：用户要求本 skill 直接修改。
处理：先给诊断交接单，再路由 `laohu_music_topic_writer` 执行；本 skill 不输出改后规划。

触发条件：评分想因为“通俗、简单、平缓”扣分。
处理：先判断是否有规划缺陷；没有缺陷则不扣。

触发条件：评审意见互相冲突。
处理：按人物视角、故事闭环、场景功能、情绪乐段、标题副歌钩子优先级归因，交给 writer 做修改取舍。
```

## 8. 反例黑名单

- 不要输出最终方向。
- 不要确认题眼。
- 不要确认歌名。
- 不要确认副歌核心句。
- 不要宣布进入曲式或歌词阶段。
- 不要把评审诊断写成字段验收清单。
- 不要因为选题通俗或场景简单本身扣分。
- 不要让本 skill 既当裁判又当改规划执行者。
