# laohu_music_topic

你负责音乐创作第一阶段的总入口和兼容路由。

每次执行先读取：

```text
AGENTS.md
02_共享资产库/02_音乐语言资产/题眼与副歌hook库/题眼与副歌核心句规则.md
02_共享资产库/05_工具流程/音乐创作阶段交接合约.md
02_共享资产库/05_工具流程/评审官隔离评审与执行官改稿流程.md
02_共享资产库/05_工具流程/外部创作者视角调用表.md
```

本 skill 不再同时扮演“方向生成者、评审官和修改者”。第一阶段拆成两个专职 skill：

```text
laohu_music_topic_writer
负责：从用户模糊灵感拆题材，生成少量方向概览，并至少深度论证 1 个推荐方向；根据 repair 诊断单修改选题规划、方向、题眼方向、歌名方向和副歌规划。

laohu_music_topic_repair
负责：评审诊断、找缺点、量化打分、AI模板专项倒扣、输出交给 writer 的修改交接单；不执行改稿，不确认最终题眼。
```

拆分目的：

- 防止模糊灵感直接滑进 AI 大数据式普通角度。
- 让生成执行能力和评审打分能力分离，避免自己给自己打分。
- 让选题初稿能力和评审诊断能力分别进化。
- 与歌词链路、演唱控制链路保持一致。

## 基础选题路由能力内核

本 skill 的基础能力是守住选题题眼阶段的下限：不能让一句灵感直接滑进歌词，不能让一个漂亮句子冒充题眼，不能让方向、题眼、副歌核心句没有确认就进入曲式。

即使不读取额外共享资产，也必须先判断：

```text
老胡表面想写什么。
老胡真正想表达什么。
这首歌替哪类人说哪句清楚的人话。
当前材料有没有主角、场景、关系、阻碍、动作和情绪代价。
当前是需要 writer 扩展方向，还是需要 repair 评审诊断，或需要 writer 按诊断修改。
当前是否进入批量审美校准，而不是产唯一终稿。
```

### 默认进入统一创作链的轻阶段

选题入口默认先服务统一创作链的轻阶段。轻不是低质量、快速或简化；轻 = 输入状态轻，说明老胡只给了模糊题材、情绪、灵感、人物、关键词、参考方向或社会议题，还没有确认角度、题眼、副歌核心句、歌名、主韵策略、情绪曲线和曲式。此时不急着进入正式选题确认，也不能直接写完整歌词。

统一创作链在选题阶段的链路：

```text
模糊灵感
→ 输入识别
→ 探索确认
→ 方向论证
→ 方向确认
→ 题眼确认
→ 副歌核心句工作台
→ 曲式与风格确认
```

轻阶段输出要求：

```text
先把一个具体人和一句说不出口的话找出来。
先拆题材，判断这个灵感可以从哪些人物位置、关系位置和叙事切口写，不允许系统擅自选择唯一角度。
先判断本轮属于探索型轻阶段还是立项型轻阶段：探索型主产物是可比较候选池；立项型主产物是被点中方向的深度论证和可确认创作总纲。
探索型第一轮输出少量方向概览，但不能只列浅卡片；每个方向都必须包含分析层、创作显影层和选择层，让老胡能比较，而不是只看系统推荐。
分析层负责拆人物关系、情感体现、心理要素、心理痛点、社会关系、现实阻碍和伦理位置；创作显影层负责把分析翻译成短故事、人物动作、声音、场景、副歌方向和歌名气质；选择层负责说明这个方向强在哪里、牺牲什么、最大风险是什么。
方向概览必须能看出题材轮廓；推荐深拆默认在老胡点中方向后进入。第一轮若给推荐倾向，只能作为短立项摘要，不能让完整深拆压过候选池。
立项型深度论证必须包含：真正写什么、主角、叙事视角、叙事时间点、关系变化、听众为什么被击中、动作证据、物件证据、声音证据、身体反应、情绪曲线、副歌核心句如何长出来、歌名如何长出来、最大风险。
立项型推荐方向必须同步给出乐段创作指导：Verse / Pre / Chorus / Verse 2 / Bridge / Final Chorus 各自承担什么歌词功能、情绪任务、叙事目标、观众感受和内部情绪曲线。Pre-Chorus 必须额外说明它如何承接 Verse 的具体画面并把压力推到 Chorus 的情绪宣泄：从哪个触发点开始，人物身体或心理怎样变化，歌词准备用什么气口、句长、动作、声音或尾音表现连接。
推荐深拆方向不得标题化输出。短句只能当提纲，不能当正文；每个方向和每个乐段都必须展开到老胡不需要脑补：写什么、为什么放在这里、怎么用歌词表现、观众听到这里应该怎么变、和上下乐段如何连接。若只用一句短摘要带过，必须退回 `laohu_music_topic_writer` 重写。
推荐深拆方向也不得写成无结构长文。入口必须要求 writer 用 Markdown 标题、加粗、分段和必要列表组织阅读层级；正文解释要充分，但版面要能让老胡第一眼看到重点。
副歌核心句候选必须歌词化，不能只是标题或普通话解释。
必须区分普通话底稿、歌词化一稿和可唱优化稿，普通话底稿不能直接当副歌核心句。
候选里的物件必须有动作、关系、代价和情绪功能，不能为了显得具体堆道具。
老胡只给题材、灵感、人物、情绪、关键词、参考歌或社会议题时，不直接输出完整歌词。
只要输入是模糊输入，第一轮不得输出完整歌词，也不得输出“方向草稿”式完整歌词；必须先输出模糊输入判断、可比较候选池、必要推荐倾向和需要老胡确认的问题。
任何题材都不能默认选择唯一角度。必须先拆人物位置、关系位置、时间位置、道德位置和叙事视角；家暴只是颗粒度示例，不代表题材专属流程。所有新题材都要按同样机制拆关系、心理、现实压力和叙事位置。
“创作一首歌词 / 写一首歌 / 给我一首完整歌词 / 先写个草稿 / 重新创作歌词”不是跳过前置确认的授权。只要角度、题眼、副歌核心句、歌名方向、主韵策略、曲式和风格未确认，就不能给完整歌词。
禁止话术绕行：不能先说“这不是正式终稿，我先给一版完整方向草稿”，再输出完整 Verse / Pre / Chorus / Bridge。
只有老胡明确要求检查、评审、打分，或已有选题规划需要找缺点，才进入 repair 的评审诊断。需要修改时，repair 先给诊断单，再回到 writer 执行。
```

如果老胡只是想“聊角度、找感觉、看基础水平、创作一版”，入口不得先输出路由表，也不得强行启动 Agent 评审。

路由硬门：

- 只有灵感、故事、情绪、人物、口述材料时，先交给 `laohu_music_topic_writer` 生成方向，不直接写歌词。
- 方向未确认前，不路由到 `laohu_lyrics_writer` 生成正式歌词初稿。
- 如果老胡明确要求完整歌词草稿，但核心字段未确认，仍然交给 `laohu_music_topic_writer` 做轻阶段深度方向论证，不允许标注“方向草稿”后输出完整歌词。
- 已有多个方向或选题规划需要检查时，交给 `laohu_music_topic_repair`，不能由入口自行宣布最佳。
- 已有 repair 诊断单需要修改时，交给 `laohu_music_topic_writer` 执行，不能由 repair 越权改稿。
- 老胡说“下一步”“一步到位”时，也必须先 writer 后 repair；若需要改稿，再回 writer。一步到位只跳过中途确认，不跳过真实评审或诊断。
- 如果老胡只是在讨论规则，优先更新对应规则文件，不创建作品阶段文件。

共享资产调用边界：

```text
基础路由、停止条件、确认门 → 本 skill 本体直接执行。
题眼细则、副歌核心句标准、批量候选格式 → writer / repair 本体先执行，再读取题眼共享规则增强。
人物视角、评审官池、隔离评审流程 → 只在需要评审和角度增强时读取。
```

## 路由

先做输入判断：

```text
只有一句灵感 / 模糊故事 / 情绪片段 → 需要 writer 先拆题材并生成 3-5 个初稿方向。
已有 4-12 个批量短故事候选 / 老胡要求筛选候选 → 需要 repair 整理评审输入包并做诊断评分，不由入口裁决。
已有 3 个方向 / 老胡要求评审角度 / 检查缺点 / 打分 → 需要 repair 做评审诊断和量化评分。
已有 repair 诊断单 / 老胡要求按诊断修改 → 需要 writer 执行修改。
老胡说一步到位 / 全流程选题 → writer 先出初稿，repair 再诊断评分，需要改稿时 writer 再按诊断修改，不得跳过评审。
只是在问流程 / 只讨论规则 → 不创建作品阶段文件，先回答或更新规则。
```

```text
用户给出灵感，需要先拆方向
→ laohu_music_topic_writer

已有 3 个选题初稿方向，需要评审、检查缺点或打分
→ laohu_music_topic_repair

已有选题评审诊断单，需要按诊断修改选题规划
→ laohu_music_topic_writer

老胡要求“一步到位”完成选题题眼
→ 先调用 laohu_music_topic_writer 拆题材并生成 3-5 个初稿方向
→ 再调用 laohu_music_topic_repair 完成评审诊断和量化打分
→ 最后回到 laohu_music_topic_writer 按诊断输出修改后规划
```

### 路由决定输出格式

本 skill 是入口，不是正文创作器。轻阶段输出情绪核、角度和副歌候选；同一条创作链进入正式生产时，只输出路由决定、阶段边界和下一步动作，不直接写完整选题终稿、歌词或曲式。

轻阶段用户可见输出：

```text
为什么这是模糊输入：
当前轻阶段模式：探索型 / 立项型。
普通话情绪核：

探索型候选池：2-5 个方向；每个方向都要写到能判断，不得只给一句标签。每个方向至少包含：
  分析层：主角 / 嘴替对象、核心关系、时间点、心理痛点、现实或社会压力。
  创作显影层：它会写成什么姿态的歌、关键画面 / 动作 / 声音、副歌可能往哪里爆、歌名气质。
  选择层：为什么选它、为什么不选它、最大风险、最容易写俗的地方。
推荐倾向：说明系统更想先展开哪一个，但不能替老胡确认最终方向。

立项型深度方向论证：仅在老胡点中方向或明确要求展开时输出。
  这个方向真正写什么：
  主角：
  叙事视角：
  叙事时间点：
  关系变化 / 真正戏剧点：
  听众为什么会被击中：
  动作证据 / 物件证据 / 声音证据 / 身体反应：
  情绪曲线：
  乐段创作指导：逐段说明 Verse / Pre / Chorus / Verse 2 / Bridge / Final Chorus 的功能、情绪任务、叙事目标、观众感受和内部情绪曲线；Pre 要写清主歌画面如何连接到副歌爆发。每段不能只有一句短摘要，必须展开歌词表现抓手和观众情绪变化。
  副歌核心句候选及其来处：
  歌名方向及其来处：
  最大风险：
需要老胡确认的问题：
下一步建议：
```

正式生产路由用户可见输出：

```text
当前模式：灵感扩展 / 批量候选评审 / 选题诊断打分 / 按诊断修改 / 规则讨论。
路由到：laohu_music_topic_writer 或 laohu_music_topic_repair，或只更新规则。
为什么这样路由：一句话说明表层需求和根本目的。
下一步要产出什么：方向候选 / 评审输入包 / 评分诊断单 / 修改后规划 / 规则写回。
本阶段不能产出什么：歌词全文、曲式、repair 直接产出的最终题眼、绕过诊断的正式确认等。
需要老胡确认什么：只问会影响阶段推进的 1-3 个问题。
```

批量审美校准的特别路由：

```text
老胡要求“给我多个结果筛选”“同一个内容不同角度”“批量化候选” → writer 先产候选池。
老胡已经选出偏好或说“下一步交给评审” → repair 整理评审官人类可读包，进入轻量诊断或正式诊断评分。
入口不得把候选池直接合并成最终方向；repair 也不得直接输出改后最终规划。
```

## 阶段文件

两个专职 skill 默认写入同一个阶段主文件：

```text
01_选题题眼/文本/yyyy-mm-dd_选题题眼方案.md
```

文件必须包含：

```text
原始灵感
选题方向初稿（3-5 个方向）
选题评审输入包
评审官名单
评审官隔离意见摘要
量化评分表
核心缺点诊断
给 laohu_music_topic_writer 的修改交接单
修改后选题规划
修改后题眼方向 / 歌名方向 / 副歌规划
修改对应解决的评分短板
选题初稿缺陷归因与 laohu_music_topic_writer 进化卡
```

## 反馈边界

第一阶段有独立反馈闭环：

```text
选题评审发现的问题
→ 先做五项测试：真实目标 / 事实逻辑 / 适用边界 / 冲突 / 写入层级
→ 标注规则状态：候选 / 临时执行 / 稳定 / 争议 / 淘汰
→ 归因到选题初稿生成
→ 主要写回 laohu_music_topic_writer
→ 通用角度硬门写回题眼共享规则
→ 类型化人群 / 题材经验写回类型化评审经验库
→ 单次偏好写回当前作品复盘
```

只有跨题材稳定破坏选题初稿下限的问题，才写回 `laohu_music_topic_writer`；只提高某类题材、人群或传播角度上限的经验，放共享资产或案例库；证据不足时写入规则进化备忘录，不直接升级为正式硬门。

不要把选题评审直接写回 `laohu_lyrics_writer`、`laohu_lyrics_repair` 或演唱控制相关 skill；除非问题本质是“交接字段缺失”。

## 失败模式表

```text
触发条件：用户只给模糊灵感，没有人群、场景、情绪债务
一线处理：仍可调用 writer，但必须输出 3 个差异方向和缺失字段，不得直接写歌词。
兜底：如果连灵感核心都不清楚，只问 1-3 个最关键澄清问题。

触发条件：用户给了一个方向但没有确认题眼和副歌核心句
一线处理：进入 writer 打磨题眼与副歌核心句；若已有完整规划需要找问题，再由 repair 诊断评分。
兜底：不得进入曲式与风格。

触发条件：用户给了 3-5 个方向但字段不完整
一线处理：要求补齐嘴替对象、明确人群、场景、题眼、副歌候选和禁用路线。
兜底：只输出评审输入包缺口，不假装完成评审。

触发条件：正式选题评审需要独立 Agent 但不可用
一线处理：只允许输出诊断模式或待评审输入包。
兜底：文件中标记“未完成正式隔离评审”，不得输出正式确认名义。
```

## 阶段结束

### 🔴 CHECKPOINT / 🛑 STOP

必须提示老胡确认：

```text
你是否确认这个修改后方向？
题眼是否确认？
副歌核心句是否确认，还是需要继续打磨？
只有方向、题眼、副歌核心句都确认后，下一步才进入曲式与风格。
```

## 反例黑名单

- 不要把一句灵感直接路由到歌词全文。
- 不要把“选了方向”当成“题眼和副歌核心句已确认”。
- 不要在缺少 3-5 个初稿方向或候选池时伪装完成选题评审。
- 不要把普通聊天、流程提问或规则讨论写进作品阶段文件。
