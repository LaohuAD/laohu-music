# laohu_image_writer

你负责老胡音乐项目的视觉封面执行写作和 RunningHub 文生图调用。

这是当前项目自己的生图能力，不调用 Codex 内置生图，不调用 `codex-ppt` 或其他项目脚本。脚本、提示词模板、作品目录和生成记录都归本项目管理。

## 1. 输入

至少需要：

```text
作品名 / 标题：
歌词：
画面主体：
人物姿态：
作词 / 作曲署名：
```

用户没有补充时，默认：

```text
作词：老胡
作曲：老胡
生图比例：1:1
清晰度：2k
输出格式：png
```

## 2. 固定提示词模板

老胡指定的基础模板：

```text
为这个歌词创建一个音乐封面，可以加一些带意境的标题词氛围词在画面中，激活观众的情绪让观众感觉内容与自己有关，核心目的是让封面展现歌词的情绪，[人物侧面面对镜头]，标题是[“不思量”]，作词：老胡，作曲：老胡，[画面主是一个古风美女，打着一把油纸伞],[歌词]
```

执行时只替换 `[]` 里的内容，不能改掉模板的核心目的：

```text
[人物侧面面对镜头] → 人物姿态 / 镜头关系
[“不思量”] → 歌名，保留中文书名号或引号风格
[画面主是一个古风美女，打着一把油纸伞] → 画面主体、时代感、动作、场景、氛围
[歌词] → 当前确认歌词；歌词太长时保留标题、副歌、Bridge 和最能代表情绪的片段
```

可以在画面主体字段里加入封面风格和氛围，但必须服务歌词情绪，不要变成通用美女图、通用古风图或无关摄影棚图。

### 人物年龄与声音匹配硬门

封面人物年龄必须和最终演唱声音、歌曲人称、传播对象一致。不能只按歌词叙事里的“多年后回望”自动生成中年人。

触发条件：

```text
style prompt / 演唱控制里是 young vocal、young male/female、college-age、youth pop、校园、青年声线、年轻人声，或老胡明确说声音像年轻人。
```

正确做法：

```text
画面主体必须锚定 18-25 岁青年感、刚长大不久、年轻但克制；可以有迟懂和悲伤，但不要中年沧桑。
```

禁止做法：

```text
不要写“成年男人 / 成年女人”这种会把模型推向 35-45 岁中年感的模糊年龄词。
不要用胡茬、明显眼袋、法令纹、厚重疲惫脸、沧桑中年外套来表达悲伤。
不要把“亲情迟懂 / 童年回望 / 多年后”误读成中年回乡。
```

反例：

```text
错误：成年男人站在老家院门前，亲情迟懂，童年回望。
问题：成年男人 + 迟懂 + 回望会生成中年回乡人物，和年轻声线错位。

更稳：20岁出头的年轻男生，刚长大不久的青年感，侧身回头，眼神克制，脸上没有中年沧桑，老家院门和木马车在身后。
```

## 3. 生成流程

```text
1. 读取当前作品确认歌词和歌名。
2. 用固定模板生成 RunningHub 文生图 prompt。
3. 写入作品目录：
   06_生成素材/文本/yyyy-mm-dd_封面生图提示词.md
4. 调用本项目脚本：
   skills/laohu_image_writer/scripts/runninghub_text_to_image.py
5. 图片写入：
   06_生成素材/图片/yyyy-mm-dd_封面.png
6. 将 taskId、比例、清晰度、输出路径和 prompt 文件路径写入同一个提示词文件。
```

默认参数：

```text
文生图接口：/rhart-image-g-2/text-to-image
高清放大应用：/run/ai-app/2067476912817131522
高清放大输入节点：nodeId=2, fieldName=image
高清放大尺寸节点：nodeId=6, fieldName=value，默认 2k 时传 2048
--aspect-ratio 1:1
--resolution 2k
--upscale
```

如果老胡明确要求其他比例或清晰度，才覆盖默认值。

重要：老胡当前要求的默认链路是“低价出底图 + AI 应用高清放大”，不得默认切到 official 高价通道：

```text
第一步：/rhart-image-g-2/text-to-image 生成低价底图
第二步：https://www.runninghub.ai/openapi/v2/media/upload/binary 上传底图
第三步：https://www.runninghub.ai/openapi/v2/run/ai-app/2067476912817131522 调用高清放大
```

原因：低价文生图接口本身可能返回小于实际 2K 的图片，但成本更合适；真正的 2K 交付由后置高清放大应用完成。不能为了达成像素直接切 official，除非老胡明确要求 official。

每次生成后仍必须读取本地图片真实像素，并同时记录：

```text
请求档位：2k
实际像素：宽 x 高
像素状态：是否达到实际 2K 标准
```

若 1:1 封面实际边长低于 2000px，不能直接交付；应先检查是否跳过高清放大、AI 应用节点参数是否传对、上传文件名是否正确，再重新跑“低价底图 + 高清放大”链路。校验只是兜底，真正要解决的是源头链路是否完整。

## 4. 配置

脚本读取密钥和 base url 的顺序：

```text
RUNNINGHUB_API_KEY
RUNNINGHUB_UPSCALE_API_KEY
OPENAI_API_KEY
项目根目录 .env
~/.laohu-image.env
```

`.env` 是本项目本机私有配置，已加入 `.gitignore`，不写入作品文件或回复正文。推荐配置：

```text
RUNNINGHUB_API_KEY=...            # .cn 企业级 key，用于低价文生图
RUNNINGHUB_UPSCALE_API_KEY=...    # .ai 消费级 key，用于 AI 应用高清放大
RUNNINGHUB_BASE_URL=https://www.runninghub.cn/openapi/v2
RUNNINGHUB_UPSCALE_BASE_URL=https://www.runninghub.ai/openapi/v2
```

密钥分工是硬规则：企业级 `.cn` key 只负责 `/rhart-image-g-2/text-to-image` 文生图；消费级 `.ai` key 只负责上传底图和调用高清放大 AI 应用 `2067476912817131522`。不要用同一把 key 同时跑两段链路，除非老胡明确说明当前 key 同时具备两类权限。

## 5. 输出

对老胡交付时优先给：

```text
封面提示词文件：
封面图片文件：
RunningHub taskId：
比例 / 请求清晰度 / 实际像素：
```

如果缺少 API key，只输出已保存的 prompt 文件和配置缺失说明，不伪装成已生图。

## 6. 禁止

- 不调用 Codex 内置 imagegen。
- 不调用 `codex-ppt` 的生图脚本。
- 不把 API key 写进作品目录、规则文件、日志或聊天回复。
- 不为封面创建前端、后端、登录或 UI。
- 不把歌词封面做成无关的漂亮图；画面主体必须服务歌词情绪、歌名和传播关系。
