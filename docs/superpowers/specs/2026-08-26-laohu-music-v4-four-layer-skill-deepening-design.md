# 老胡音乐 V4：逐 Skill 四层能力深化设计

## 一、设计目的

本轮不重新发明“老胡音乐 V4”，也不把四层能力写成一份覆盖全项目的通用模板。目标是保住现有九个 Skill 已经形成的专业能力，再逐个检查它们是否真正完成了从方向、关系、材料到成品的完整传导。

本轮以这条已有总原则为共同语言：

> 灵魂以箴言定向，筋骨以章法成篇，血肉以技法生变，表皮以法度成形。

四层的基本作用单位是单个 Skill：

- 灵魂回答这个 Skill 究竟保护什么价值、怎样取舍、为何非由它负责不可。
- 筋骨回答它怎样组织自己的判断、步骤、状态、依赖、承接与回流。
- 血肉回答它使用什么领域材料、怎样选择、借助什么专业技法产生什么效果。
- 表皮回答它最终以什么语言、字段、格式、接口、参数和验收尺度交付。

项目层不再复制九份相同的四层说明。项目层只负责确定各 Skill 的职责、相互依赖、阶段状态、交接协议和失败回流，让每个 Skill 用自己的专业语言实现四层。

## 二、这次不做什么

1. 不因为四层重要，就给每个 Skill 机械增加“灵魂、筋骨、血肉、表皮”四个同名章节。
2. 不把已经成熟的选题、写词、歌名和封面能力推倒重写。
3. 不把每个 Skill 修成全能工具；一个 Skill 的短板若属于另一个 Skill，应通过交接解决，而不是越权补齐。
4. 不按行数、文件长度和目录整齐程度删减旧内容。
5. 不把 Reference 中的知识搬回顶层或 Skill，制造重复权威。
6. 不用文件存在、关键词出现和静态链接证明能力已经生效。
7. 不自动推送 GitHub；本地提交只记录本轮明确修改，不带入上层仓库的无关改动。

## 三、现状判断

### 3.1 已经形成领域四层的能力

以下 Skill 的四层已经明显进入其专业判断，不宜大改：

- `laohu-lyric-topic`：已经能从题材、人物、关系和材料中形成作品命题，并把总线交给下游。
- `laohu-lyric-writing`：已经把关系命题、段落运动、材料抒情、语言声音和反向审稿连成完整写词链。
- `laohu-lyric-title`：已经形成从作品总线到命名机制，再回到全歌复核的独立能力。
- `laohu-lyric-cover`：已经形成从音乐作品到第一视觉、信息差和发布包装的独立能力。

它们需要的是保护、补缝和交接校准，不是全面重写。

### 3.2 四层已经出现，但能力链尚未完全贯通

`laohu-lyric-composing` 已有正确的谱曲箴言、完整的六个声音部门、词曲接口和 AI 音乐生成规范。当前主要缺口不是知识不足，而是：

- 作品总线怎样压成一个主导全曲的“听觉问题”，仍可能停留在解释层。
- 六个声音部门容易被平行调用，缺少由同一主听觉判断向下分配职责的清晰传导。
- 风格提示词、演唱控制和曲式设计虽然各自完整，但需要更清楚地证明每一项参数来自哪一项作品判断。
- 第一版已经好听时，现有规则能够要求回查，却还可以更准确地区分“制作完整”“音乐成立”和“作品总线被听见”。

### 3.3 横切能力正在用通用表格稀释领域能力

`laohu-song-director` 的阶段、锁定、依赖和回流意识很强，但当前交接字段明显偏向歌词，容易让谱曲、歌名和封面被迫使用歌词化的共同语言。

`laohu-quality-supervisor` 能追查最早责任节点，但四层验收仍偏向选题和歌词。如果同一套“人物、段落、材料、语言”门槛直接检查谱曲、歌名和封面，会得到看似完整、实则越级的监督。

正确方向不是让横切 Skill 学会所有专业细节，而是让它们准确找到领域负责人，并验证领域 Skill 自己的能力链是否真的执行。

### 3.4 自进化已有强骨架，但缺少“长处优先”的改造边界

`laohu-project-evolution` 已经具备反馈分层、根因追查、权威归属、语义迁移、行为回归和回退能力。它当前需要补充的核心判断是：

- 优化成熟 Skill 时，先确认它不可替代的专业长处。
- 四层深化服务于这项长处，不以消灭所有短板为目标。
- 发现的缺口若属于相邻 Skill，应修交接或路由，不把目标 Skill 改造成全能 Skill。
- 四层最终必须被翻译成目标领域的语言，不能把母模型的名称直接复制到产物里。

### 3.5 自然沟通能力丰富，但不能成为第二套专业判断

`laohu-natural-dialogue` 已经具备很强的理解、解释、批评、教学和语言审查能力。本轮只需校准一条边界：它负责让老胡听懂、比较和继续，不负责重新裁决作品命题、歌词、曲式、声音、歌名和封面。沟通层发现领域结果说不清时，应退回领域 Skill 补判断或证据，不能自行生成一套更顺口的替代结论。

## 四、总设计

### 4.1 每个 Skill 先确定一条独门能力链

四层不能从抽象名词开始套。每个 Skill 先回答：

```text
它接到什么上游事实或作品判断
→ 它独自完成哪一次不可替代的专业转译
→ 它通过哪些领域关系和材料完成转译
→ 它把什么可执行结果交给谁
→ 什么证据说明这项转译真实发生
```

只有这条能力链成立，四层才能进入该 Skill。

### 4.2 项目只保护同一作品，不要求同一种表达

跨 Skill 交接必须保护同一条作品总线、锁定事实、用户决定和失败边界；下游收到以后，必须把它重新翻译成自己的领域语言。

例如：

```text
选题交给写词的是关系动作和材料边界
写词交给谱曲的是声音落点、段落职责、重音、气口和回归变化
声音锁定后交给歌名的是作品记忆、语言记忆和听觉记忆
歌名交给封面的是命名承诺、视觉可见项和不得泄露项
```

不能用一张固定字段表代替四次不同的专业翻译。

### 4.3 Skill 内部以主判断统领，不让好标准同时满功率运行

每个 Skill 每次任务只激活一个主胜负手：

- 选题可能争人物关系的不可替代性。
- 写词可能争副歌的关系动作和可唱记忆。
- 谱曲可能争一项贯穿全曲的听觉变化。
- 歌名可能争听前承诺与听后增义。
- 封面可能争一眼看懂的异常关系与未泄露答案。

其他正确标准作为辅助、硬门、降权或暂不激活项。这样既追求极致，也避免把所有优点堆成平均作品。

### 4.4 Reference 负责按条件加深，不能成为无人调用的知识仓库

每个 Skill 要写清：

- 遇到什么专业缺口才读取哪份 Reference。
- 从 Reference 取走什么判断或方法。
- 它改变了哪个候选、字段或执行动作。
- 哪些内容本轮不采用。

Reference 不因内容正确就默认生效；没有改变取舍或得到可审计确认，视为未激活。

## 五、逐 Skill 设计

### 5.1 `laohu-song-director`

独门能力：维持同一作品在不同专业阶段中的身份、状态、依赖和回流。

保护：

- 总导演不替领域 Skill 创作。
- 状态锁、用户确认、局部试验和正式阶段分离。
- 上游未成立时不让下游用完成度遮盖问题。

修改：

1. 明确“四层属于各领域 Skill，总导演只管理它们的连接”。
2. 把歌词化的通用四层交接卡改成两部分：
   - 所有阶段共用的不变量：作品总线、锁定事实、用户决定、保护项、当前状态、失败回流。
   - 各领域自己的交付：由选题、写词、谱曲、歌名和封面分别定义。
3. 修正总导演越权生成歌名、曲式和声音假设的表述：总导演可以要求局部试验，但结果必须由对应领域 Skill 产生并裁决。
4. 增加交接验收：下游必须说明自己如何把上游判断翻译成领域动作，不能只写“已读取”。

不做：不在总导演中复制五个领域 Skill 的全部规则。

### 5.2 `laohu-lyric-topic`

独门能力：把题材、人物、事实和关系压力变成一首歌不可替代的作品命题。

保护：现有八条选题箴言、命题硬骨、材料成熟度、公共连接、对标迁移和作品总线。

修改：

1. 把独门能力链明确为“种子与事实 → 关系冲突 → 人物选择与代价 → 认识运动 → 作品总线”。
2. 检查十六份 Reference 的调用是否都能落到这条链；只修无人承接、重复负责或缺少激活证据的位置。
3. 强化选题向四个下游的差异化交接，不让一份完整故事同时交给写词、谱曲、歌名和封面。

不做：不继续增加新的题材清单，不把选题变成写词或故事策划大全。

### 5.3 `laohu-lyric-writing`

独门能力：把关系命题变成一个具体人物能够唱出、听众能够记住并在回归中重新理解的语言。

保护：现有六条写词箴言、段落变义、材料抒情、留白、语义保护、声音卡和反向测试。

修改：

1. 让每项技法都明确作用对象、目标效果、使用条件和过量风险；不让“复沓、比喻、对偶、反差、留白”退化为修辞名录。
2. 强化材料候选的比较：同一用意下比较不同尺度、公共性、私人归属和声音潜力，防止默认选择钥匙、车票、旧照片等平均物件。
3. 明确写词交给谱曲的是声音问题和文字保护项，不是要求谱曲给歌词配气氛。
4. 保护有效旧句：改稿必须证明新增了关系、声音或文化尺度，不因整齐、古雅和押韵机械替换。

不做：不把写词 Skill 变成曲式、音乐制作或沟通 Skill。

### 5.4 `laohu-lyric-composing`

独门能力：把作品关系和歌词运动变成听众能够实际听见的秩序、破坏、等待、回归、选择和余波。

这是本轮加厚最多的领域 Skill。

修改：

1. 增加“主听觉命题”：每首歌先确定听众最后必须重新听见什么，以及哪一种音乐关系承担这次改变。
2. 把六个声音部门改为受主听觉命题统领的职责链，而不是六项并列配置：
   - 动机负责身份与回归。
   - 节奏负责人物的身体行动和语言步态。
   - 和声负责期待、拒绝解决和责任改变。
   - 曲式负责信息、记忆和高潮到达次序。
   - 配器负责人物世界、距离与物理质感。
   - 演唱负责此刻具体怎样开口。
3. 每项音乐决定必须留下：来源于哪项作品事实、听觉上具体改变什么、预期听众先后听见什么、用什么试听结果否决。
4. 把曲式、风格提示词和演唱控制编译为同一声音蓝图的不同接口；不得各自优化到漂亮，却互相讲不同的歌。
5. 强化候选比较：候选必须改变 hook 到达、能量分配、重复意义、演唱姿态或结尾听觉后果；只换乐器和标签不算候选。
6. 保留 Style Prompt 的 1000 Unicode 字符硬门、Controlled Lyrics 原文保护和现有校验工具；机械通过只裁决可用性，不裁决音乐质量。

需要同步检查三份现有 Reference：

- `曲式结构与音乐叙事.md`：强化结构候选与信息、声音条件之间的因果。
- `音乐风格路由与提示词生成.md`：让每个提示词字段能够回溯到声音蓝图，而不是风格词堆积。
- `vocal-control.md`：让控制标签只表达主唱动作和段落变化，不承担歌词解释或全局风格。

### 5.5 `laohu-lyric-title`

独门能力：把作品压成一个听前成立、听后增义、回到全歌仍然准确的名字。

保护：现有三种命名机制、五道门、母义去重、全歌回插和读音搜索检查。

修改：

1. 明确输入不只来自歌词字面，也来自声音记忆、人物动作和作品用途。
2. 强化命名候选必须由不同命名机制产生，不能只换近义词。
3. 明确歌名不替作品制造一个正文没有的冲突，也不退化为发布标题。

不做：不重写现有成熟命名系统。

### 5.6 `laohu-lyric-cover`

独门能力：把音乐作品中最值得先看见、又不能提前说尽的关系压成一个画面。

保护：现有第一视觉、主体动作、异常关系、信息差、平台适配和提示词交付。

修改：

1. 明确封面负责选择“看见什么、藏住什么”，不负责重新设计人物全部视觉资产。
2. 已有角色、服装和场景资产时，直接继承；确需完整视觉开发时交给专业视觉项目，封面 Skill 只保留音乐作品的构图、信息与包装裁决。
3. 强化标题与画面互补：二者共同偿还作品承诺，不能重复说同一句，也不能各自讲另一首歌。

### 5.7 `laohu-quality-supervisor`

独门能力：发现当前成品最早在哪个专业节点失去成立条件，并把它退回唯一负责人。

修改：

1. 先识别被审结果和领域负责人，再读取该 Skill 自己的四层门槛。
2. 监督层只验证“领域能力链是否真的发生”，不以一套歌词化四层标准裁决所有产物。
3. 追查顺序改为：领域身份错误 → 领域灵魂失准 → 领域关系或章法断裂 → 材料与技法无效 → 形式或接口失败。
4. 每次判退必须指出：失败证据、最早责任点、应回到哪一步、重做后会出现什么可观察变化。
5. 同一执行者既创作又监督时，行为结论最高为 `OBSERVE`，不能自证质量已经达到巅峰。

不做：不让监督 Skill 成为第二位选题人、作词人、作曲人或视觉导演。

### 5.8 `laohu-project-evolution`

独门能力：把真实失败和用户反馈编译成目标 Skill 能够长期执行、验证和回退的能力增量。

修改：

1. 增加“长处优先”的成熟 Skill 优化门：先写清独门能力、现有优势和保护场景，再分析缺口。
2. 明确四层深化发生在目标 Skill 内部；进化 Skill 负责识别和编译，不把统一模板复制给所有 Skill。
3. 区分三类缺口：
   - 目标 Skill 自己的层次缺口：补目标 Skill。
   - 相邻 Skill 已有能力但交接失效：修路由或交接。
   - 目标 Skill 根本不该负责：保留边界，不补短板。
4. 增加“优势回归”：除原始失败、同根变体和边界反例外，必须用一个旧强项场景证明修改没有削弱原本擅长的结果。
5. 新建一份按需读取的 Reference：`单一技能四层深化与保真迁移.md`，保存完整审计、编译、迁移和回归方法；主 Skill 只保存触发、路由和核心动作。
6. 新能力写回时，原则、章法、技法和法度必须使用目标领域语言，不显性复制母模型名称。

### 5.9 `laohu-natural-dialogue`

独门能力：把已经成立的专业判断变成老胡听得懂、能比较、能决定并能继续创作的交流。

保护：现有事实承接、具体证据、自然中文、锋芒边界、隐性教学和发送前审稿。

修改：

1. 明确沟通能力链：领域结论与证据 → 用户当前最关心的矛盾 → 通俗因果与具体例子 → 明确动作或决定入口 → 自然语言交付。
2. 领域结论说不清时，退回领域负责人补证据；沟通层不能为了顺口重写专业结论。
3. 发送前检查继续作为表皮法度，但不得反向压缩完整分析，或让所有回复长成同一种格式。
4. 仅补边界，不大规模删减当前已经细化的自然语言规则。

## 七、验证设计

### 7.1 结构验证

- 九个 Skill 的 frontmatter、名称和路径保持有效。
- 所有 Reference 链接可达，没有仓库外必需依赖。
- `AGENTS.md` 保持顶层职责，不复制领域细节，不超过项目文档预算。
- Style Prompt 和 Controlled Lyrics 现有脚本继续通过原有有效样本。

### 7.2 路由验证

- 总导演能够把同一作品分别交给选题、写词、谱曲、歌名和封面，不用歌词字段统治所有阶段。
- 质量监督能够识别产物领域并找到唯一负责人。
- 自进化能够区分目标 Skill 缺口、跨 Skill 交接失败和不应补齐的短板。

### 7.3 行为场景

至少保存以下场景，不预写唯一成品答案：

1. 只有“故乡、想家、电影感”三个宽词，选题不能编造一段完整人生，必须形成关系缺口和有依据的探索路线。
2. 同一关系命题存在“小物件、公共意象、人物动作”三类材料，写词必须比较承重、归属、声音和公共连接，不能默认私人物件最深刻。
3. 已有锁定歌词和作品总线，谱曲必须给出一个主听觉命题，并让六个声音部门共同实现它；不得只交风格、乐器和情绪标签。
4. 两个曲式候选必须改变信息次序、hook 到达或最后副歌责任，不能只增删一个段名。
5. 歌名候选必须来自不同命名机制，并通过听前、听后和全歌回插。
6. 封面必须说明看见什么、藏住什么，以及怎样与歌名互补；不能把完整剧情画成海报说明书。
7. 总导演交接同一作品时，下游输出必须使用各自领域语言，同时保护同一作品判断。
8. 质量监督面对错误 Style Prompt 时，应先判断是作品听觉命题、风格路由、提示词编译还是字符接口问题，不得统一归因为“情绪不够”。
9. 自进化面对“封面人物设计不够专业”的反馈，应先判断是否属于封面 Skill 的独门职责；若完整角色开发属于外部视觉项目，则修交接，不把封面 Skill 改造成角色设计系统。
10. 自然沟通面对复杂谱曲判断时，只翻译已经成立的音乐结论，不用更顺口的文学比喻替换节奏、和声、音域和停顿事实。

### 7.4 回归与保护

每项实质修改至少检查四类结果：

```text
当前失败场景：新规则是否拦住原问题
同根变体：换题材后是否仍能识别根因
边界反例：是否把相似但正确的做法误杀
旧强项场景：原来擅长的结果是否保持或增强
```

机械脚本只给结构和接口结论；同一执行者完成修改与验收时，行为最高标记为 `OBSERVE`，质量保持 `UNKNOWN`，等待真实创作或独立任务验证。

## 八、完成标准

本轮完成不以“九个文件都出现四层字样”为标准，而以以下结果为准：

1. 每个 Skill 能用自己的专业语言说明它独自完成哪一次转译。
2. 四层能够从该 Skill 的方向传到具体执行和验收，而不是停在开头说明。
3. 上游作品判断经过交接后没有丢失，下游也没有被迫使用上游的专业语言。
4. 已有长处得到保护，修改没有把 Skill 做宽、做平均或做成全能工具。
5. Reference 在真实条件下被调用并改变取舍，不只是存在于目录里。
6. 自进化以后能继续用同样方法深化任何一个 Skill，并能防止信息密度在重构中下降。
7. 结构、路由和行为场景分别给出真实验证结论，不把文档完整冒充能力完成。
