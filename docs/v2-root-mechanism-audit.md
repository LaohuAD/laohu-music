# V2 根本机制迁移审计

状态：2026-07-23 完成静态迁移审计；真实作品质量仍需生产验证。

## 1. 审计目的

本文件回答两个问题：V2 中哪些内容会直接改变作品的上游决定，必须进入 V3；哪些内容只是多智能体流程、重复职业说明、表面补丁或未被真实产出证明的复杂度，不应迁移。

它是架构证据，不是运行时规则。正式创作只读取 `AGENTS.md`、当前 Skill、相关 `knowledge/`、作品状态和少量个人记忆，不读取本审计。

## 2. 准入标准

一项内容只有同时满足以下条件才进入 V3 运行时：

1. 改变命题、人物知识、观察、语言发动机、核心句、曲式、乐段、承重句、声音方向、主记忆、形式或外部反馈归因中的真实决定。
2. 不执行时会跨作品重复造成高代价失败，而不是只影响一个字或一次平台随机结果。
3. 能回到人类怎样理解、感受、记忆、演唱或使用作品的上位原理。
4. 能说明模型为什么会产生对应坏结果，以及作品中能观察到什么表面症状。
5. 有适用边界和过度执行风险。
6. 不能被 Schema、语法检查或脚本更可靠地完成。
7. 只有一个运行时权威位置，不在顶层、Skill和知识文件复制全文。

未满足以上条件的内容只保留为迁移证据、压力场景、个人记忆候选或明确拒绝项。

## 3. V2 七项 Active 权威

V2 `rules/registry.yaml` 只有以下七项 active 规则。V3 的裁决如下：

| V2 active规则 | 裁决 | V3唯一运行时位置 | 迁移结果 |
|---|---|---|---|
| `core.anti-mode` | 迁移 | `knowledge/creative-core.md` 第8节 | 保留高价值位置识别公共默认、人物重新授权、第一耳自然和替换损失；拒绝每句强行陌生化 |
| `core.creative-causality` | 迁移根本因果 | `knowledge/creative-core.md` | 保留已有经验、关系刺激、人物知识、选择性知觉、三重统摄、语言发现、尺度、文化、整体回装；删除多Writer/Selector隔离链 |
| `core.market-ready` | 迁移投资原理 | `knowledge/creative-core.md` 第7与第13节 | 保留人的发现、作品身份、记忆资产、听众用途、缺陷可修复性；删除Selector/A&R岗位和内部评分 |
| `core.producer-voice` | 迁移压缩版 | `AGENTS.md` 9.5 | 保留证据、因果、主语动作对象、事实/推论/审美区分和音频诚实；删除固定报告模板 |

| `shared.lyric-qualification-gate` | 迁移创作边界 | `knowledge/lyrics-craft.md` | 保留自然中文、私性/诗性分离、抽象词双向测试、呼吸、节奏时间假设、声韵、回装；删除七门trace与独立评委链 |
| `shared.section-functions` | 迁移因果方法 | `knowledge/lyrics-craft.md` 第4至第6节 | 乐段按听众理解变化和人物动作组织；不按标签填背景/爆发/升华，不强迫标准曲式 |

## 5. AI失败模式逐项映射

| V2失败模式 | V3根因处理 |
|---|---|
| 具体动作脱离上位原理 | `creative-core.md` 全部规则采用原理→错误机制→方法→证据→边界 |
| 虚假具体、库存意象 | 选择性知觉、事实/私性/诗性具体和语言发动机 |
| 公共情绪直接承重 | 抽象词语境缩窄与听众借用/作品增义双向测试 |
| 情绪加强但尺度停滞 | 情绪强度与作品尺度分开 |
| 文化材料作文清单 | 文化材料由当前人物重新发声 |
| 开场与全歌断轴 | 开场认知缺口必须由后文兑现 |
| 听众没有位置、廉价互动 | 听众主要角色、真实使用动作及反煽动边界 |
| 文章骨架分行 | 乐段新增、语言机制跨段生长、残句/呼吸/节奏时间假设 |
| 语义近似替换 | 炼字词句从人物动作与责任开始，押韵不得倒推句意 |
| 修辞跨体系跳转 | 一个主要语言发动机、全歌回装与第一耳语义桥梁 |
| Writer自我证明、Repair无边界重写 | 一份主稿冷读、`keep/revise/escalate`、保护锁定项、没有失败证据不改 |
| 学习反馈扩张成规则 | `laohu_learning` 的证据等级、根因Schema、晋级权限与唯一权威 |
| 声音标签堆料 | 一个最高记忆中心、具体声部职责、四条曲线与正向窄提示词 |
| 沟通模板化 | `AGENTS.md` 9.5，不把内部速记和固定报告结构交给用户 |

## 6. 路线文件裁决

V2 的题材、情绪、语言和曲风路线不作为 V3 active 规则迁移。原因是路线名称容易在语言样本前锁死作品，并把“爱情=雨、克制=低动态、都市=R&B”等常见搭配重新写回系统。

其中真正跨题材的部分已经上收：情绪是两股同时成立的力量；语言路线由实际样本发现；曲风由用途、人物身体和主记忆推出；纯音乐拥有独立分支。具体路线只在用户输入或当前作品证据触发时作为候选，不建立永久预设表。

## 7. 生产Skills裁决

V2七类岗位的大部分篇幅是隔离、候选池、Selector、Repair、A&R、trace和职业头衔的重复实现。V3不迁移岗位数量，只迁移以下根本职责：

- Writer的发散、收敛、承重位置搜索和全歌回装，进入单一 `laohu_lyrics` 与 `laohu_sound`。
- Selector的资格与投资分离，转成初稿/终稿节点的“下限是否通过、资产是否值得继续投入、根因应返回哪层”，不建立委员会。
- Repair的保护资产、最早根因、修改范围和无净改善则保留，进入section/line/audio revision模式。
- A&R的生成准备诚实边界，进入声音包完成条件；它只授予外部生成资格，不声称发行。
- Learning的本与标、偏好/缺陷/一次性要求分离，进入 `laohu_learning` 与Schema。

被拒绝的内容：多Writer池、资格/投资/验收三个独立Selector、固定候选预算矩阵、超长trace、内部评分、实名角色表演、流程投入证明质量。这些结构在V2的验证记录中多数只达到 `structurally_validated`，没有证明真实产出上限提高，并已造成约2小时38分钟等待。

## 8. 历史反馈的根因覆盖

V2 `learning/feedback.jsonl` 的14条记录已逐条归并：

- 诗性、自然中文、第一耳、私性/诗性分离：已覆盖。
- 韵脚、呼吸、行/小节幻觉：迁移为韵脚优先级、呼吸组和高价值句节奏时间假设；拒绝全歌默认矩阵。
- 场景先于情绪、库存现代道具：迁移为选择性知觉和听众已有记忆，不建立物件黑名单。
- 语言出现前锁死主题、低频搭配冒充诗性：迁移为语言发现主题与自然中文非补偿边界。
- 深刻认识冒充歌曲语言、跨段文章化：迁移为可持续语言发动机、乐段新增和完整回装。
- 人物把推测升级成事实：迁移为四类知识来源。
- 资格与投资互相污染：保留原则，删除多Selector实现；V3由用户在高价值节点提供外部判断。
- 音频被错误写成内部过程：已改为提示词过程、外部音频结果和多轮反馈循环。
- 最新反馈覆盖全部旧规则：Skill明确新反馈只提高权重，不取消锁定项和不可补偿边界。

`accepted-rejected.jsonl` 为空，`market-feedback.jsonl` 没有形成可迁移市场规则，因此没有伪造对应经验。

## 9. 新增但非复制的V3基础

- `work_type` 支持人声歌曲和纯音乐，不让纯音乐经过歌词假流程。
- `music_fragment` 支持旋律、节奏、groove、riff、和声、动机、演唱动作和局部编曲从中间进入；只炼片段时按最短路径停止。
- `audio_run_id` 与 `prompt_revision_id` 支持同一提示词多结果、多轮外部反馈和平台随机性归因。
- `analysis_mode` 强制声明 `user_text_only`、`tool_assisted_audio` 或 `both`，不假装听音。
- `prompt-revision.schema.json` 补足了原契约只“引用版本 ID”却无法恢复修订因果的缺口：每轮保存父版本、音频/反馈来源、保留资产、同根因修改组和可观察预期。
- `state.yaml.sound_iteration` 保存当前生效版本、已接受版本、待反馈音频和循环次数；`accept_sound_package` 把“暂停”与“用户验收”分开。
- 目录、Schema和操作接口为未来网站保留稳定语义，但网站不是当前运行依赖。

## 10. 仍需真实验证的边界

本次审计证明的是：根本机制存在、权威单一、接口可恢复、V2冗余有明确拒绝理由。它不能证明任意模型会稳定写出顶尖歌词，也不能证明提示词会产生理想音频。

首次真实V3作品至少要验证：命题与核心句决策是否比V2更快；完整初稿是否已经出现不可替代资产；逐段/逐句交互是否只暴露真实问题；节奏时间假设是否帮助外部生成；同一提示词多音频是否能区分平台随机性；用户反馈能否被正确分类而不膨胀规则。未经过这些结果前，项目状态是“基础架构与根本规则成立，产出质量待实战验证”，不是“稳定达到顶尖或发行级”。
